> **已被 [[trajectory-workbench]] 取代(2026-09-04)。** 轨迹不再住在场景 JSON 里、不再在场景画布上拉线:
> 一条轨迹一个独立资产文件,作者面是独立的桌面工作台(画面/世界两种空间)。本卡只留作历史:
> 下面提到的 `trajectory_panel` / `tools_trajectory` / `trajectory_items` / `_validate_scene_trajectories` /
> `scene_trajectories` id 宇宙已全部删除;仍成立的条款(时间曲线首键钳位、sampleHz 上限 240、触地强制成帧、
> 抽稀用数值差、空表不许清盘、source 与帧同一次落地)已并入新卡。

## 是什么(一句话)

策划怎么做出一条实体轨迹:在**场景实景**上拉线定空间,在属性面板调节奏与通道定时间,
松手即烘成运行时唯一认的密关键帧。运行时那一半见 [[entity-trajectory]]。

## 权威源(读代码从哪进)

`trajectory_model.py` = 两头的**形状**(七通道填满 / 省缺省键 / 固定键序与取整);
`trajectory_bake.py` = 运动学(采样器的 Python 镜像、弧长参数化、时间曲线、物理积分、抽稀),
纯函数、零 Qt、零磁盘;`scene_v2/tools_trajectory.py` = 手势,`trajectory_items.py` = 图元
与几何派生;`shared/trajectory_panel.py` = 线之外的一切 UI。构建期兜底在 `validator.py`;
`playTrajectory.trajectoryId` 的补全宇宙(按 `sceneId` 收窄的 `scene_trajectories`)在
`tools/json_lang`。

## 硬契约(违反即 bug)

- **拉线只在新画布。** 老画布只有属性面板那一半(能编清单 / 分段 / 节奏 / 参数,不能拉线)。
  别往老画布补一把工具:它没有 Document/Command 层,面板走"直写 + 标脏"已经是那侧的例外。
- **轨迹是场景级 part,而且场景级 part 的数据形状不必是点列。** 轨迹喂给图元的是**整张轨迹表**,
  不是一条点列;而"当前编哪条 / 哪段 / 洗刷到哪一刻"是**视图状态**,由工具持有,
  同步时**绝不能顺手重设**——重设 = 别的实体一变更就把作者正在编的段踢掉。
  画布总规矩见 [[scene-canvas-v2-document-view-command]]。
- **手势期间不写数据,松手恰一条命令。** 因此 Esc 中途取消不需要反算回滚——数据压根没被改过。
- **`source` 与 `keyframes` 必须在同一条命令里。** 松手 = 先改 source、紧接着重烘,两者**一起**
  写进那一条命令。分两条的话撤销只退一半,磁盘上留下"路径是新的、帧是旧的";
  **运行时只认 `keyframes`,所以这种坏数据在游戏里根本看不出来。**
- **空分段返回的空表绝不许拿去清盘。** 烘焙机在 `segments` 为空(或整段被跳过)时返回空列表;
  此时**必须保留原有 `keyframes`**。手打的帧一次误触就没了,撤销之外没有第二条退路。
- **画布画的几何必须由烘焙机给,不许自己连线。** 手绘段的 `path.points` 只是个**形状**:
  `startFrom` 决定它整体平移多少,`smooth` 时真正走的是平滑曲线而不是折线。
  画布若直接连点,**位置差一个 delta、形状差一条曲线,两边都不报错**——作者照画布摆好,
  进游戏发现物件走的是另一条路。
- **落盘取整只有一套规则。** 拖动写出的数与重烘写出的数必须同口径;两套取整会让同一条轨迹
  在"拖一下"和"重烘一次"之后长出两种写法,黄金往返当场红。
- **物理定步长与 `sampleHz` 解耦**:先按固定步长积分出真实轨迹,再按采样率重采。
  不解耦的话策划一调采样率弹跳高度就变——那是"改显示精度改掉了设计"。
- **面板自己不判断写哪一份数据。** 它只产出**新的整张轨迹表**,交给宿主注入的窄协议:
  新画布 = 一条命令(整键写,撤销恰好退回一整份);老画布 = 直写 + 标脏。
  面板自己挑写哪份,正是老画布"写错副本"的根因。

## 空间与时间解耦(这条决定了 UI 长什么样)

线是线(路径控制点),快慢是另一条曲线(横轴时间、纵轴路径进度 0..1)。
**重调节奏不必重画线**——拖时间曲线的键,一个路径控制点都不会动。物理段没有这一半,
它的时间由积分本身决定。做任何面板改动前先认下这条:把节奏并回线上(比如"按点距定速度")
就是把这个解耦拆了。

## 已知坑

- **时间曲线首键必须钉在 t=0(只能上下拖)。** 采样器的边界是**钳位**:`t <= 首键` 一律返回首键。
  首键飘到 120ms,`0..120ms` 那段就是"保持首键的 progress",**不是"从头渐变"**,
  作者几乎必然误解。独立通道轨同理——所以面板加通道点是**成对加**(t=0 一个、段末一个),
  不是加一个孤点;`keys` 整个为空时才回落到上一段传下来的姿态(段间连续)。
- **`sampleHz` 上限 240 不是拍脑袋。** 采样器的段长有 `span = max(1, Δms)` 的**下限 1ms**
  (亚毫秒段会被拉长)。采样率逼近 1000Hz 时,落盘帧距开始被那条下限吃掉——**采得越密越不准**。
- **触地与静止瞬间必须强制成帧。** 抽稀按误差挑点,而弹跳的**尖角恰好是误差最大处**,
  只有采样点正好落在尖角上才留得住。不强制的话弹跳被磨成一条圆滑抛物线,
  **没有任何东西会报错**。
- **抽稀用"同一时刻的数值差",不是经典 RDP 的垂距。** 垂距在(时间, 数值)这种量纲不一致的
  空间里没有意义,而且**不给误差上界**;换成数值差,"抽稀后在任意原始采样点上偏差 ≤ 容差"
  才是可断言的。
- **物理触地判据刻意偏离 `types.ts` 的字面写法:碰撞响应要同时查弹起速度。** 只查撞击速度的话
  `restitution=0` 会得到"vy=0 却仍标记腾空",下一步又被重力拉成零深度触地,**原地死循环**。
  **别照 types.ts"修回去"。**
- **Y 向下:重力为正、往上抛的初速 y 是负、地面是较大的 y。** UI 文案、箭头方向、tooltip 都
  按这条写死了;按"Y 向上"的直觉取负号会全部画反,**而且不报错**,策划照着填出来的东西
  方向相反。
- **面板是懒建的**:折叠区没展开过就只"揣着"磁盘值,取编辑区会拿到 None。宿主的动画心跳
  必须接受这个 None——播放靠**宿主那根心跳**推,面板**不另起定时器**(两根心跳互相打架,
  且页不可见时照烧 CPU)。
- **往返保真靠"就地改深拷贝",不是"按控件重建 dict"。** 面板没有控件的 `source` 子键是
  **结构上**带回去的;改成按控件产出重建,不认识的键就静默没了(见 [[editor-roundtrip-contract]]
  的重建区)。通道轨表同样对不认识的通道原样透传。
- **鼠标事件里不改布局**(见 [[canvas-gesture-safety]]):提交与状态刷新一律排到下一拍,
  由带 context 的单发定时器驱动,鼠标事件里只重绘。
- **空表 = 删键。** `trajectories` 写成 `[]` 会让黄金往返红(本仓约定"缺省不落键")。
- **命中尺寸一律屏幕像素**,且地面线要比顶点略宽——它是一条无限长的细线,按顶点那点命中带
  很容易差一两像素而"怎么点都不动"。
- **被 `startFrom` 锚住的段起点拖不动**(锚在实体或上一段末点上)。这是设计,不是 bug;
  状态栏要按现场说明,否则作者会一直在那个点上拖。

## 怎么验证

`test_trajectory_bake.py` 是主门(含逐 case 读 `src/utils/keyframeSampler.golden.json` 的
**跨语言 parity**——TS 与 Python 两侧采样必须同数);`test_trajectory_panel.py`(节奏与线解耦、
往返保真)、`test_scene_v2_trajectory_tool.py`(手势 / 一条命令 / 活动态在重投影下存活)、

("什么都没发生"与"编排如此"长得一模一样),只能在构建期抓。
