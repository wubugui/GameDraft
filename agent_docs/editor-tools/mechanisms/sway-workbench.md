## 是什么(一句话)

分割认不出的东西,作者自己画:开 `sh scripts/py.sh -m tools.sway_workbench`(主编辑器
「工具 → 草木工作台…」、开发控制台「草木工作台」也有入口),选场景 → 原画上涂三个通道 →
**推给游戏**(立刻在跑着的游戏里看,资源不动)→ 满意了 **导出到游戏**(写进资源)。
运行时那一半见 [[scene-wind]]。

**游戏是预览器**(与声学 / 粒子两台同一条):工作台只管抠图与标注,动起来什么样去游戏里看。
不在页面里重跑一份摆动——那份数学只在 `backgroundSway.ts`,页面里再写一遍必然漂。

## 作者面有什么

| 做什么 | 怎么做 |
|---|---|
| 四层涂 | 补植被 / 加刚体 / 减刚体 / 锁死不动;`1`~`4` 切层,当前层画得实、其余压淡 |
| 擦 | `E` 开橡皮 **或** 右键拖;**只擦当前层** |
| 改错了 | `Ctrl+Z` 撤销(按笔)、`X` 清空本层(也可撤)、「历史…」挑一份恢复 |
| 看清楚 | 已抠出的植被 / 实例分区 / 自由度 / **已判定的刚体** 四个叠加层;`F` 视图复位 |
| **点一下问它** | **Alt+点** = 这一点属于哪株、什么脾气、alpha / 叶度 / 自由度 / 刚体度各是多少 |
| **指哪亮哪** | **Alt+悬停** = 那一株整片高亮 + 报编号 / 脾气 / 株高(松开 Alt 就灭,画画时不闪) |
| 推给游戏 | `P` 或按钮;页面上**此刻**的四层 + 锚点 / 整体摆(存没存都算)→ 烘进本机预览 → 游戏原地换上;**资源不动** |
| 导出到游戏 | `B` 或按钮;先存盘 → 烘进资源(各时段照明载荷目录)→ 游戏换回资源里这份 |

入口:`sh scripts/py.sh -m tools.sway_workbench`、主编辑器「工具 → 草木工作台…」、开发控制台「草木工作台」、
**场景页的「草木摆动 → 在草木工作台中打开…」**(直接装当前场景,与声学 / 粒子两台同一套 detached 起法)。
命令行:`--push <场景>`(盘上的涂层烘进预览并通知游戏)、`--export <场景>`(烘进资源)。

⚠ 推送 / 导出**不能同步做完再回**:冷的时候要解分割、补底板,十几秒到几十秒,浏览器那边看着就是个卡死的按钮
(作者会以为工具挂了,然后去点第二次)。线程里跑、`/api/job/status` 轮询;两个按钮在活跑完之前都按不动,
服务端也只许一个活(`_JOB`)。
⚠ 后台状态里的字段**不许叫 `ok`**:响应信封外层已经有一个,同名会盖掉它,前端一律当成"请求失败"
——症状是刚点按钮就报错(实测撞过,已有单测钉死)。

## 🔴 推给游戏 ≠ 导出到游戏(制作人 2026-09-14 定名)

原话:"推给游戏是指立即推送给运行时的游戏!资源写游戏应该叫做导出到游戏"。
**来历(别再犯)**:原先的「推给游戏」只往槽里写一行 rev,让游戏重装**盘上已经烘好的**拆层;而涂层要"重烘"
才进拆层——制作人涂刚体、保存、按了几百次「推给游戏」,游戏里一直是上一次烘的样子,零报错。

| 按钮 | 读什么 | 写到哪 | 告诉游戏 |
|---|---|---|---|
| 推给游戏 | 页面上此刻的四层 + 锚点 / 整体摆(`/api/push` 带 `channels` / `overrides`,**不先存盘**) | `local/sway_preview/<场景>/<烘焙目录名>/`(gitignore、不归 DVC、不在 public 下所以打包抽不到),PNG 快速压缩 | `{source: 'preview'}` |
| 导出到游戏 | 盘上的 `sway_paint.png` / `sway_overrides.json`(**先存盘**,没存上就不导) | 各时段 `lighting/<背景基名>/`(资源) | `{source: 'export'}` |

烘焙是同一个 `sway_field.bake_sway`:`inputs` + `out_root` 就是推送,缺省就是导出——**两条路没有第二份拆层逻辑**。

- **槽**:`/__gamedraft-api/runtime-sway` 一行 `{rev, sceneId, source, ts}`(`rev` 服务端自增;没写 `source` 按 export)。
- **预览口**:同一个插件在 `<槽>/preview/<场景>/<烘焙目录>/<文件>` 给本机预览目录里的文件(`src/dev/runtimeSwayApiPlugin.ts`)。
  ⚠ 这是往浏览器递本机文件的口子:只认三段、每段不许带分隔符 / `..`、文件名只许是拆层产物那几个(`SWAY_PREVIEW_FILES`),
  HEAD 要回 `application/json`(`loadOptionalJson` 先 HEAD 探、类型不对当没有)。Python 的 `PREVIEW_ROOT` / `DERIVED`
  与 TS 的 `RUNTIME_SWAY_PREVIEW_DIR` / `SWAY_PREVIEW_FILES` 两边各写一处,`PreviewContractTests` 对着断言。
- **游戏侧**(`runtimeSwaySync.ts`):**这一局里新来的**推送才算(`isFreshSwayPush`)——`preview` 记下"这个场景用预览(rev)",`export` 忘掉;
  玩家在不在那个场景都记,在就原地重装。`Game.buildSway` 进场景 / 换时段 / 重装时问 `previewFor(sceneId)`,有就从预览口装。
  ⚠ **第一眼看到的那行:只有 `ts` 晚于本局启动(`bootAt`)的才算**。槽文件跨重启留在盘上,刷新后第一眼那行可能是昨天推的、
  从没导出过的——当成预览就是"作者以为导出了、游戏里显示的却是一份没进资源的东西"(与 [[debug-ui-persistence]] 交换档的
  "新鲜期"是同一类坑);但**本局启动之后才推的**(工作台"推送 → 游戏没开 → 拉起游戏 → 补发")必须认——2026-09-14 之前一律不认,
  补发永远落空、日志还写着「✔ 已让它换上」。`resetSeen()`(换场景时调)**不再清 rev**:rev 是全局自增的,清掉之后配上
  启动时刻那条会让每次换场景都白白重装一遍;槽被删了重来(rev 变小)按第一次看到处理。
- **游戏页心跳**:游戏轮询槽时带 `?scene=&boot=&preview=&applied=`(此刻在哪个场景、这个场景用没用预览、真换上的最近那次 rev),插件记下最近一次,
  槽的 GET / POST 回包带 `game: {sceneId, bootId, preview, applied, loading, ageMs}`(工作台自己探槽不带参数、不算心跳)。
  ⚠ **dev server 收下了 ≠ 游戏页看到了**:原来槽一应答就报「✔ 游戏里已换上」、徽章写"游戏在",游戏页根本没开也这么说。
  **游戏只在场景装完(`scene:ready`)之后读槽里的推送**(`Game.swayReadySceneId`):`currentSceneData` 在装载一开始就换了,
  工作台看到"游戏进了这个场景"补发推送,正撞在 `buildSway` 还没装完时原地重装,草木层会坏。
  **但装场景 / 原地重装期间心跳照发**,带 `loading=1`(场景可以为空,插件要有 `boot` 才记),这段**不读槽**(`lastRev` / 预览表都不动),
  装好后第一轮照常认新推送;原地重装不占着取槽的锁,不会叠两次重装。⚠ 2026-09-14 前这段心跳是停的:
  游戏在装一个大场景时按 P,工作台看心跳超过 4 s 判"没有游戏页",去 `/api/link/open`——控制台开着就**再开一个游戏窗口**,
  没开就排一条切场景把玩家拽回入口。现在 `push_to_game` / `/api/link/status` 回 `pageBusy`(心跳新鲜且 `loading`),
  页面走 `waitBusyPage`:不开游戏、等它装好(最多 90 s),在这个场景就等 `applied` 打 ✔,在别的场景说一句。
  标题画面也是"没有场景",同样按 `loading` 报,等满 90 s 说"装好之后再按一次"。
  现在 `push_to_game` 回 `pageAlive` / `inScene`(心跳 4 s 内算开着),日志与徽章分三档说:在这个场景已换上 / 游戏在别的场景、
  进来就是这份 / dev server 在但没有游戏页。游戏刷新过(心跳里 `preview=0`)而预览比资源新时,徽章直说"推过的预览没进这一局,按 P 再推"。
- **游戏没开着**:推送照样烘好预览;前端让控制台把游戏切到 / 拉起到这个场景,**等心跳显示游戏页进了这个场景**再
  `POST /api/push/notify` 补发一次(游戏认它启动之后推的那行)。等待期间两个按钮不锁(游戏可能根本起不来)。
- **一个时段目录都没写就算失败**:`bake_sway` 每个时段都跳过(没有照明载荷 / 尺寸不对)时返回空表、不抛;原来照样报
  「✔ 已写进资源」。`_start_job` 见到空表抛错,原因在日志里那几行"跳过 …"。
- **工作台上的叠加层跟游戏看到的走**(`layers.derived_dir`):预览比资源新就读预览,状态行写"叠加层是推给游戏的预览(还没导出)";
  推完 / 导出完只刷新拆层产物那几层(`refreshDerived`),⚠ **不许走 `openScene`**——它从盘上重装四层,没存的笔画就没了。

### 推给游戏要快(跑马梁实测)

一次推送原先 21 s(Telea 补底板 3.5 s × 每个时段、分割实例两两去重整幅求交、每个时段整张解码原画)。现在:

| 情形 | 耗时 |
|---|---|
| 工作台进程里第一次(冷) | 约 16 s |
| 装场景后(后台已预热)/ 同样的输入再推 | 约 1 s |
| 只改刚体 / 锚点 | 约 1 s |
| 改了锁死(植被没变) | 约 2.6 s |
| 补了植被(植被归属变了,底板要重补) | 约 10 s |

- 做法全在 `sway_field`:**按输入内容哈希**记住各段(分割按位压缩 `_SEG_MEM`、场景常量 `_scene_base`、分割实例 `_base_instances`、
  每株形状 `_instance_shape`、只随植被归属变的距离变换 `_veg_fields`、伪世界几何 `_scene_geometry`、补带计划 / 补图 / 编好的 PNG);
  去重求交先比包围盒;按时段的场景对象不再整张解码原画(`_SceneRef`)。
- 🔴 **缓存键只许是内容哈希**,不许是文件名 / 时间戳 / 场景 id;缓存里的数组一律 `setflags(write=False)`。
  换缓存时对着不缓存的旧产物**逐位**比过;`PreviewBakeIntegrationTests` 两条(只改刚体 / 补了植被)各跑一次"走缓存 vs 清空缓存",
  逐位相同才算过(变异验过:把 `_veg_fields` 的键去掉植被归属,补植被那条当场红)。
- **装场景时后台预热**(`/api/warm` → `bake_sway(dry=True)`:按推送的口径算一遍、一个字节都不写);推送 / 导出 / 预热共用
  `_BAKE_LOCK` 一个一个来(共用同一批进程内缓存)。

- **推的是"变了",不是内容**:草木的载荷是那几张 PNG,不是 JSON。
- **🔴 重装的 URL 必须带缓存戳 `?v=<rev>`**:`AssetManager` 按 URL 缓存纹理,不换 URL 永远拿到旧图
  ——症状是"推了没反应"且零报错。
- **新 root 要插回旧 root 原来的位置**(`parent.getChildIndex`),否则草木会跑到实体层前面或后面。
- **第一次看到槽只记 rev 不重装**(除非那行是本局启动之后推的,见上):否则每次刷新页面都把上一次的推送重放一遍(声学那条踩过)。
- **别只信 `discover_game_url`**:它读 devstate、缺省回 5173,而作者常跑在别的端口(本仓 launch.json
  里并列着 5173/5174/5178/5180/5188)。`layers.find_game()` 按槽是否应答**实探**一遍并记住赢家;
  推错端口的症状同样是"推了没反应"。

## 三个通道(工作台与烘焙之间的契约)

`lighting/<背景基名>/sway_paint.png`,RGBA 一张图,**是烘焙的输入不是产物**(烘焙器只读不写;
留在开发树、不进发行包,与 `skyvis.png` 同一类):

| 通道 | 画上去的意思 | 烘焙怎么用 |
|---|---|---|
| R | 补植被 | 分割漏掉的草木补进来:贴着已有实例(≤ 10 px)的并进去,离得远的自成一株 |
| G | 锁死不动 | 与石头同一待遇:从植被里扣掉、也不补底板,原画那块原样留在底板上 |
| B | **加刚体** | 逐像素刚体度:这些像素只跟着整株转,不跟着弯 |
| A | **减刚体** | 把自动判成刚体的那部分去掉(分割把不该刚的认成了木质时用) |

**刚体是自动打底的**:分割认出来的木质(`WOODY_PROMPTS`:树干 / 枝条 / 茎)默认就是刚体
——枝干本来就只能跟着整株摇、不该像草叶一样弯(制作人 2026-09-13:"那个树的枝干不是刚体了?")。
作者的涂层在这个底上加减:`rigid = clamp(木质 + 加 − 减)`。

通道次序两边各写一处(`layers.CHANNELS` 与 `sway_field.read_paint`),测试逐条钉死——
错一位就是"涂了没反应"且不报错。

## 三层各画各的(作者面的硬要求)

**页面里三个通道各有自己的一张画布**,存盘时才合成 RGBA。一张画布加色画三层会同时坏两件事,
制作人 2026-09-13 直接报"只能画不能擦":

- **橡皮只能整体擦**:改一层会把另外两层一起抹掉(涂了刚体再想修植被 = 刚体白涂);
- **通道之间互相冲淡**:canvas 是预乘的,在同一张上叠画另一个通道,先前通道的值会被读回时除小
  (实测刚体 20828 → 叠涂植被后变 20446,没人动过它)。

作者面按画图软件的通用手势:**橡皮是开关、擦的永远是当前层**,**右键拖**随时擦当前层,
`Ctrl+Z` 撤销,`X` 清空本层,`1/2/3` 切层。撤销按**一笔一张 128×128 瓦片表**存(每块瓦片一笔里只取一次原样),
另有**总字节上限**(`S.undoByteCap` 320 MB,超了从最旧的丢,最新一条总留着)与 40 条上限 ——
⚠ 别只存一笔里第一段的范围(第一版就是这么写的:拖一长条,撤销只回来一个圆点),
也别整张快照(2048×1152 一笔 9 MB,四十笔 360 MB);**也别每个鼠标移动存一块矩形**(2026-09-14 前是这样:
大笔刷刷几秒一笔就上百 MB,只按条数限就能涨到 GB 级把渲染进程撑崩)。

## 植株工具:锚点 / 整体摆(2026-09-13)

- **锚点**:左键放、右键删最近的一个(屏幕 30 px 内)。刚体部分绕离它最近的锚点转——点在竿底 / 树干底;
  **整体摆**:点一株切换(同一株再点是取消,按株判不是按点堆)。两样都在捕获期截住点击,涂层一个像素不动。
- 存进 `sway_overrides.json`,**只存原画像素位置**:实例 id 每次烘焙都会变,存 id 的话烘一次作者的设置就指到别的株上。
  与涂层**同一次** `Ctrl+S` 保存(`save_paint(..., overrides=)`)、同一套撤销(`S.undo` 里 `kind:'ov'` 的条目)、
  同一份本地草稿(`d.ov`);覆盖前把上一份挪进 `sway_paint_history/overrides-*.json`(保留 20 份)。
- ⚠ 老页面(不带 `overrides` 字段)存一次**不许**清掉已有的逐株设置——`save_paint` 只在收到 dict 时才写
  (`OverridesSaveTests` 钉着)。
- 改完「推给游戏」就能看(推送带着页面上此刻的锚点 / 整体摆,不用先存);要进资源得「导出到游戏」。

## 数据安全(作者的涂层是**手工劳动**,一次误存可能是半小时的活)

三道闸,都在 `layers.save_paint`,**改这个工具时谁也别把它们绕过去**:

1. **乐观并发**:页面装载时记下盘上那份的 mtime,保存时带回来。盘上的比它新 ⇒ 拒绝并让作者刷新
   —— 否则两个窗口互相覆盖,谁也不知道丢了什么;
2. **大面积删除要点头**:这次保存抹掉的已有内容超过 35% ⇒ 拒绝并报出每层的前后数,`force` 才写。
   "页面没装好就点了保存"正是这么把人家的活清空的;
3. **每次保存留一份历史**(涂层旁边的 `sway_paint_history/`,**必须同时在 `.dvcignore` 里排掉**
   —— 每场景 20 份,不排就进 DVC 推送体积;联动槽 `runtime_sway.json` 同理。
   保留 20 份,**文件名是那份内容自己的存盘时刻**(被替换那份的 mtime,带毫秒、重名再加序号;原来用"现在",
   标着 15:30 的那行其实是 15:00 存的——恢复时整整差一版),同一时刻同样字节的不重复进历史;
   **恢复先把历史读进内存再留当前这份**(原来先留、20 份满了顺手把正要恢复的最旧那份剪掉,恢复失败且那一版永久没了)
   —— 只精确到秒的话同一秒两次保存会互相覆盖,中间那版就没了)。页面上「历史…」能挑一份恢复,
   恢复前当前这份也进历史,所以恢复本身也可撤。

另外:页面每 8 秒往服务端存一次草稿(`/api/draft` → `local/sway_drafts/<场景>.json`,只在有改动时),装场景时**先把场景画出来**
再问一句要不要恢复(拒绝过的同一份这一局不再问)—— 浏览器崩了只丢这 8 秒。存盘成功即清掉草稿。
⚠ **草稿不许放 `localStorage`**(2026-09-14 之前就放在那):桌面壳是纯内存 profile、端口每次随机,关窗 / 崩了草稿跟着没,
"只丢 8 秒"在主入口里从来不成立;全仓 localStorage 已清退,见 [[debug-ui-persistence]]。自检把 `layers.DRAFT_ROOT` 指到临时目录、
页面上把 `draftStore` 换成桩,绝不碰作者的真草稿。草稿是**相对盘上那份的增量**:
只编码 `S.chDirty` 里那几层(一层 PNG 编码 ≈ 45 ms,四层 ≈ 180 ms —— 正画着卡这一下就是"一顿"),
恢复时先装盘上的、再盖这几层;草稿里带着写它时的 `baseMtime`,和现在盘上的对不上就在确认框里明说
(盘上那份在中间被另一个窗口改过,叠上去会把两边混在一起)。**笔按着的时候一律不编码**,
排 `requestIdleCallback` 也要在真跑之前再判一次 —— 排队期间人又下笔了就让掉这一轮。

## 画笔只重画这一笔经过的矩形

整张重画要把四层涂层逐像素合一遍(2048×1152 × 4),实测 45–80 ms;原来每个鼠标移动都整张重画,笔刷十几帧、拖快了跟不上手。
`draw(rect)` 只合这一块的涂层(CPU 那部分),各叠加层照旧**整幅 `drawImage` 靠裁剪限制范围**,一次移动 ≈ 2 ms。
- ⚠ **别用九参数的子矩形 `drawImage`**:「已抠出的植被」+「自由度」同开时,那条合成路径与整幅贴出来的像素差到 127(真 GPU 与 SwiftShader 都中)。
- ⚠ **着色缓存要缓存"拷过一次"的画布**:刚 `putImageData` 的那张第一次被贴出去时,低 alpha 处的预乘取整与之后再贴不同(同样差到 127),
  整张画一遍、再局部重画一块,笔画周围就是一道方框接缝。`tintFromChannel` 在共用的 `tint-build` 里算、拷进缓存画布再用。
- 判据:15 种叠加组合下 `draw(rect)` 与 `draw()` 逐像素相同;一整笔画完与整张重画逐像素相同(自检 S12)。

## 硬契约(违反即 bug)

- **🔴 刚体度不许塞进 `sway_matte.png` 的 alpha**,单独一张 `sway_rigid.png`。
  浏览器把 PNG 画进 canvas 时按 alpha 预乘,**alpha = 0 的像素 RGB 会被清成 0**;运行时的 CPU 副本
  (`readCpu`)正是这么取的,塞进 alpha 等于把自由度整张清零 —— 症状是草木一动不动、零报错。
  2026-09-13 踩过一次,当场回滚成单图。
- **🔴 `sway_paint.png` 只许有一个写入者**。"同一份内容两个来源"就是把制作人的活吃回来的那个 bug:
  工作台里擦掉 → 保存成功 → 刷新一下,盘上另一张 `sway_lock.png` 又把擦掉的全读了回来。
  收敛成:**涂层是唯一来源**,`sway_lock.png` 只剩**读取 + 一次性迁移**(保存时并进 G 通道并删除),
  谁也不许再产出它 —— `--lock-ids` 那条命令行(`sway_field.seed_lock`)2026-09-13 改成写涂层的
  G 通道、并走 `layers.keep_history` 留同一套历史;`SeedLockTests` 用正则钉死"没有任何
  `_atomic_bytes(... LOCK_FILE ...)`"。旧文件还在的场景,装场景时并进「锁死」层让它**看得见**
  ——看不见 = 明明锁着却以为没锁(制作人 2026-09-13 第一眼就问"锁死区域怎么看不到了")。
- **🔴 作者涂的刚体不参与"整株刚转"的判定**。`kind = plant` 那条规则是"木质像素 > 2% ⇒ 整株刚体",
  要是把涂层并进 `woody`,涂三根竹竿整丛就变成刚体、叶子也不弯了——**正好毁掉作者要的"竿刚叶弯"**
  (2026-09-13 实测:涂完 plant 从 1 变 2)。涂层只管两件事:逐像素刚体度、这些像素不颤叶。
- **🔴 导出前必须先落盘,推送不许落盘**。导出读的是盘上那张 `sway_paint.png`:页面上涂了没存就导出,导出的是上一版,
  而画面上看着已经涂了 —— 「导出到游戏」自己先 `save()`,没存上(冲突 / 取消)就不导。
  「推给游戏」带的是页面上此刻的四层,**不写资源、也不替作者存盘**(存不存是作者的事,推送只管让他立刻看到)。
  `test_页面上两个按钮打的是对的口子` 钉着两边。
- **🔴 推给游戏的预览不许写资源**:只许落 `local/sway_preview/`。`PreviewBakeIntegrationTests` 推前推后对资源目录做指纹比对。
- **涂在没有实例的地方会被丢掉**(石头、锁死区、空地):那些像素不属于任何一株,刚体度落不下去。
  烘焙会报"刚体涂层落在植被上的 xx%",低于一半直接出声。对着「已抠出的植被」那层涂。
- **场景清单不许逐个 `Scene(sid)`**:那会打开每张原画读尺寸,36 个场景 ≈ 十秒白屏。
  烘焙目录只由「场景 id + 第一张背景名」决定,直接拼路径。
- **`.js` 的 MIME 自己钉死**(`H.extensions_map`)。Windows 注册表常把 `.js` 映射成 `text/plain`,
  浏览器按 HTML 规范**拒绝**这种 MIME 的模块脚本:页面白着、控制台只有一行 Strict MIME type checking。
- **写盘走 `retry_transient`**(见 [[atomic-write-windows]])。
- **🔴 `restore` 的历史名必须是纯文件名**。它的动作是"拿这个文件的内容盖掉作者的涂层",
  名字是从请求里来的:拼得出路径 = 拿一个无关文件覆盖掉半小时的手工活,而且不声不响。
- **🔴 通知游戏与烘焙各一个 `try`**。合在一起的话,游戏那边一出岔子就会把一次**已经烘好、
  产物都落盘了**的活报成失败,作者会再烘一遍(冷的时候十几秒)并开始怀疑工具。
  送不到只是"没送到游戏:…"一行日志,烘焙的成败与它无关。
- **🔴 单键快捷键遇到会吃字母键的控件要让开**(`SELECT` / `TEXTAREA` / 文本类 `INPUT`)。
  切完场景焦点就停在场景下拉框上,那时按 `X` 会**清掉整整一层**、按 `B` 会直接导出进资源,
  而人只是想用首字母跳选项。滑块不在此列(它不认字母键,拦了反而让 `[` `]` 失灵);
  `Ctrl+S` / `Ctrl+Z` 也不在此列。
- **视图着色缓存必须在装场景时清掉**。键里带着 `img.src`,而每次装场景都换一个 `?t=`,
  所以跨装载**永远命中不了**,只会把上一轮那几张 2048×1152 的画布(一张 ≈ 9 MB)钉死在内存里
  (实测连开 4 次堆涨 81 MB)。
- **🔴 切场景:全部读到才算切过去**(`openScene`)。制作人 2026-09-13 报"切了场景没反应,画面都不变"。
  原来一进来就把 `S.scene` 改成新场景再去请求;请求一失败(`dev_room` 根本没有背景图,`/api/layers` 500)
  异常没人接 —— 日志一个字没有、下拉框显示新名字、画面停在旧场景,**页面却以为已经在新场景上**:
  这时 `Ctrl+S` 会把旧场景的涂层存进新场景名下,推送 / 导出也打到错的场景。
  现在:先请求,拉到拆层描述 + 全部图片才换 `S.scene`、换画面、释放旧图;失败留在原场景、
  下拉框退回、日志写 `⛔ 装不上 xx:原因(还停在 yy)`;确认框点取消下拉框也退回。
  清单(`layers.scenes()`)带 `hasBackground`,没有背景图的场景在下拉框里标"装不了"且不能选。
  自检 S11 钉住(把 `S.scene = sid` 挪回请求前,S11 当场 FAIL)。
- **🔴 复用的画布每次拿出来都要清空**(`scratch(name, w, h)` 每次重新赋宽高 = 清像素 + 复位
  画笔状态,哪怕尺寸没变)。四层涂层画布、叠加层、读通道用的中转画布跨场景复用,不复用的话每切一次
  新建一批 2048×1152 画布、旧大图不断开(`releaseImg`),内嵌浏览器面板里连切 5 次后图片全部
  加载不出来(桌面壳里没复现,但内存只进不出是真的)。复用而不清 = 上一个场景的涂层透到新场景里、
  再存进去。并发两次装载往同一组画布写,只认最后一次(`S.openToken`)。自检 S10 钉数量不涨。
- **🔴 热重载要把上一份纹理丢掉**(`AssetManager.dropTexture`)。每推一次换一个 `?v=`,同一张图在
  缓存里各占一份;不丢的话推几十次就把别人的东西从 LRU 里挤出去(底板一张 4 MB)。
- **游戏在不在,按推送用的那条槽实探**(`layers.find_game`),别拿控制台状态判:控制台是另一个服务,
  游戏跑着它也可能没应答,徽章会长期显示"没开着"(实测过)。
- **dev 槽的插件单独一个模块**(`src/dev/runtimeSwayApiPlugin.ts`),不写在 `vite.config.ts` 里:
  从配置里测它会把整份配置拖进 TS 程序,配置自己的历史类型问题会全冒出来(实测 tsc 直接红)。
  路径常量只有一份(`RUNTIME_SWAY_API`),游戏侧与插件共用。
- **新增拆层产物要同步四处载荷镜像**(TS / mjs / Python / 契约测试),少一处 = 整批静默不进包
  (见 [[scene-lighting]] 的"四连发")。`sway_rigid.png` 已登记。

## 推了 ≠ 进了资源,存了 ≠ 进了资源(状态条要说出来)

作者面有几个"以为生效了其实没有"的档,页面必须分得清、说得出,否则人只会得出"这工具没用"这一个结论:

| 状态 | 徽章 | 实情 |
|---|---|---|
| 涂了没存 | ● 有未保存的改动 | 盘上还是上一版;推给游戏照样看得到,导出会先存 |
| 推了没导出 | ● 游戏里是推送的预览(资源还没导出) | 预览 `sway.json` 比资源的新(`layers()` 给 `previewMtime` 与 `bakedMtime`);发行包里不是这份 |
| 存了没导出 | ● 待导出(资源里还是上一版) | `layers()` 给 `needsExport`:资源 `sway.json` 里记着导出时读到的输入指纹(`inputs.paintSha1 / overridesSha1`,读输入之前取),与现在的涂层 / 逐株设置比;老 meta 退回 `paintMtime > bakedMtime`。⚠ 光比 mtime 的话,导出途中又存一次会被后写的 `sway.json` 盖过去,"待导出"永远不亮 |
| 游戏没收到 | 游戏:没开着 / 在 xx 场景 | 产物已烘好,游戏没开着或没应答;游戏在别的场景时,进到这个场景就是这份 |
