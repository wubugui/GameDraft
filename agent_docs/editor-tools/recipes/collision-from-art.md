## 实测环境与日期

2026-09-23~24,Windows,项目 venv(`sh scripts/py.sh`,要 cv2 / scipy)。跑马梁、雾津街头两场由主代理首用定型;其余 32 场由
只读本卡 + 技能 `scene-collision-from-art` 的子代理修、另一批子代理按复查协议独立复查;3D 遮挡口径下 34 场又整体过了一遍(见文末"验证记录")。

## 什么时候用

- 制作人说"碰撞乱画 / 人站到屋顶上 / 这儿明明能走却走不过去 / 看看所有场景的碰撞"。
- 新场景第一次导出深度之后:自动碰撞 `collision_auto.png` 在大多数画上**不能用**(山梁把天空和谷底判成可走、
  街镇是一堆随机色块、崖墓天井把水面和崖壁判成可走)。
- 人手改碰撞仍去桌面地形工作台([terrain-workbench](../mechanisms/terrain-workbench.md));本卡是**命令行作者面**,
  写的是同一种作者层多边形,人随时能在工作台里接着拖顶点(工具靠 `screen.of` 指纹认出被拖过的块,反投回画面继续用)。

## 口径(先想清楚再动手)

1. **碰撞 = 玩家脚底那个画面点能不能站。** 玩家只查一个脚点(场景坐标),运行时把它走一条反投影链
   (场景坐标 → 行走面深度 → M-world → 碰撞格)落到网格上;热点 / NPC 自带的 `collisionPolygon` 另外再挡一层。
   判对错**只看画、在 3D 里判**:脚点下面是路、院坝、台阶面、地板 = 能站;是水面、崖外 / 天空 = 不能站;
   是物体(屋顶、墙面、桌子、桶、摊子)的画面 = 先分清是它的**占地**(不能站)还是它**后面被挡住的地**(按第 5 条估)。
2. **世界是 3D 的,画是它的投影;被挡住的地方画上没有信息,要估**(制作人 2026-09-23)。
   脚点在画面上的意思是"那个画面点**正下方**的地"。落在屋顶 / 桌面 / 人上半身的画面点,在 3D 里要么是那个物体的
   **占地**(站不了),要么是**物体后面被它挡住的地**——后者能不能站,画上看不到,按连续性估(见第 5 条)。
   **不依赖深度**:有的图深度整张是错的(崖墓系列标定塌成平面等)。深度着色(`crop --depth`)、深度图、
   自动碰撞一律不作依据,和画对不上就信画;工具里那条反投影链只是"画面点 ↔ 网格格子"的坐标换算,作者落盘与运行时
   走同一条,画面上的结果自洽,不需要它是对的(它把几个画面点压进同一格时实现度会报出来;薄块报不出来,
   立着的物体画面区尤其容易折叠——见已知坑,逐块 `crop --overlay` 核)。
3. **圈能站的地方,不圈障碍物的外轮廓。** 全部 `walk` 多边形的并 = 可走集;可走集以外由工具**自动生成**一块阻挡
   (`art_可走以外`,被可走集围住的空洞另成 `art_可走以外_岛N`),每次落盘都重算。漏圈的后果是"该走的走不了"
   (摆人图上一眼看出空着),而不是"人站到屋顶上"——前者安全,后者是事故。可走集**里面**的障碍再圈 `block`,阻挡压过可走。
4. **三种构图三种圈法**:野外 / 山梁 / 崖路(可走的是一条带)直接圈那条带;院落 / 室内 / 疏朗的街镇(地面连成一片、
   房子是岛)walk 圈整片地,每栋房子 / 每堆杂物圈 block;**房挨房的密集街镇**(街是房子之间的窄条)按街带一条条圈 walk——
   整片 walk + 逐屋 block 在这种图上会漏出一堆屋檐夹缝与死院(test_scene 补了 7 块才清干净,test_room_a 改圈街带就干净)。几条定下来的判法:门楼 / 过街楼底下是路(walk 穿过屋顶画面);
   树只挡根部(脚点落在树冠画面里是站在树后面的地上);菜地 / 田垄没有篱笆就能走;比一个人窄的零散路沿石、柱子不圈,
   连成一道挡路的(矮墙、栏杆)要圈;抬高的台子(说书台)没画台阶就当家具。
5. **物体圈多大 = 它在地上的占地,不是它在画面上的轮廓。**
   - **前沿**是看得见的那条接地线:墙脚线、桌脚 / 凳脚落地的那条线、台子侧面的底边。
   - **后沿**看不见,靠**顶面往下平移物体高**估出来:屋顶的檐口 / 桌面 / 台面这一圈往下挪"檐口到墙脚 / 桌面到桌脚"
     那么高,就是占地的后沿。草稿里给 block 写 `h`(物体高,场景单位),`crop --draft` 与叠图会把"占地往上抬 h"画成
     黄虚线——它应该和画上的屋顶 / 桌面对上,对不上就是占地或 h 估错了。
   - **占地往上、物体轮廓以内那一片是物体后面被挡住的地。**按连续性估能不能走:物体两边看得见的地(街、地板、院坝)
     明显从它后面连过去 → 能走(雾津街头去破屋的暗巷、茶馆里女客身后那条过道、说书台后面那圈地);物体后面靠着墙、
     另一栋房、崖、画边 → 不能走。拿不准时按"不能走"处理并在回报里点名。
   - 四面被围死、进不去的小块地(屋脊后、两屋之间的暗缝)封成 block,别留成孤岛。
   - **栏杆 / 矮墙是一条线的占地**:walk 前沿收到栏杆柱脚 / 墙脚,横木画面线到柱脚之间是栏杆后面的地(连着就能走)。
     **薄墙**(院墙约 20 厚)在网格里只占两三格:墙后面紧贴墙的那条地可能放不出来(和墙外脚落进同一格,实现度会低),
     更要紧的是**墙会不会漏**——每道院墙都用 `connected` 堵上院门问一次"墙外走不走得进院里",必须"不连通"。
     **上下两层**(桥面 / 桥下栈道、楼上 / 楼下)的地方,行走面会把两层的画面点压到一起:栏杆边往柱脚一收,上下层就可能
     经桥侧漏通,`check` 查不出来(两层本来就在同一个走得到的连通块里)。改过这种边后,堵上正常的上下口,用 `connected`
     问一次上层一点与下层一点——必须"不连通";漏了就把边退回扶手线(bridge_underpass 桥面就是这么退回的)。
     例外:桩插在**崖沿下方的崖壁上**时柱脚不是地面的边——以崖沿为准,别照柱脚把崖壁开成可走(崖墓后段护栏)。
   - **灌木丛 / 蕨丛**:实心成团、人钻不过去的按根部轮廓圈占地 + h(树冠上沿往下移一个 h 当根部后沿);稀疏的(看得见后面的地)
     只挡根部或不挡。树照旧只挡树干根部。
   - **坡屋顶的 h 量到檐口**(墙脚到檐口那一截,不是到屋脊):占地是墙围的那一圈,抬 h 后的黄虚线应对上檐口线;
     屋脊比檐口高出的那截只会多挡人,不影响占地。一排高矮不一的房子按高矮拆块。
   - **门楼 / 过街楼 / 门洞底下的路**:路本身圈 walk,再给这块 walk 写 `h0`(门楣底离地多高)+ `h`(门楼顶多高)——
     照样能走,摆人图把站在里面的人 h0 以上抠掉、脚边不抠。两侧的墙墩照常 block + h。
   - **围住可走区的墙 / 隔墙 / 栏杆也要挡人**:它们多半是自动生成的外围块(没有 h),站在墙根后面的人会被画在墙前面。
     要让摆人图看出遮挡,在墙线上补一条带 h 的细 block(梦_里屋隔墙上的门扇板)。
   - **看不见脚的栏杆 / 楼梯扶手**(透过栏杆看到的是下一层):找不到接地线就按扶手顶线收,栏杆后面不放开,回报里点名。
   - **前沿矮墙的墙帽内沿就是地面沿**时(家具脚、桶底正落在上面),walk 边贴墙帽内沿,不往里收。
   - **桌子后面只露出一头的凳子**:按与桌边平行估出整条凳的占地(看得见的那头定长度与凳脚位置)。
   - **占地伸出画底的前景物**(画面最下沿的墙、箩筐):占地照实画到画外,工具在扩出来的画布上算遮挡再裁回画面。
   - **斜靠的东西**(靠崖壁的碑、斜搭的木板)"占地 + 竖直 h"表示不出来(顶端往后错开,黄虚线必然对不上):
     它背后是崖 / 墙、挡不住任何人时不写 h;挡得住人时 h 取竖直方向的高,黄虚线对不上在 note 里写明是斜的。
   - **在 walk 外面、但会挡住站在它前后的人的物体**(路边的棚、大石、碑)也补一块带 `h` 的 block——不补,摆人图不会把
     站在它后面的人抠掉,也画不出黄虚线,复查看不出占地估得对不对(阎王岭山口的歇脚棚)。
   - 人从脚点往上立着,**站在物体后面的人会被物体挡住一截**——`crowd` 按各 block 的 `h` 把挡住的那部分身子抠掉,
     看的是"被挡的人站的那块地该不该有",而不是"人画在屋顶上了"。没写 `h` 的 block 当扁的(不挡人)。
   - ⚠ 游戏里人走到物体后面会不会被画到物体后面,靠的是运行时的深度遮挡——深度错的图,人会被画在屋顶 / 桌面上面。
     那是深度的问题不是碰撞的问题,但**开放了"物体后面的地"的场景要在回报里点名**,让制作人进游戏看一眼。
   - **例外(2026-09-25):深度已按原画标定、`art_review depthsheet` 过了之后**(流程见技能 `scene-depth-collision-from-art`),
     碰撞第二轮可以用 `crowd --occlusion both`:人按**游戏真实深度**被挡,与作者估的 h 遮挡对不上的画品红圈、脚被深度挡住的画红圈,
     逐个回画判是碰撞估错还是深度错。深度没过体检之前,本条"不依赖深度"照旧。
6. **标记点跟着画走**:出生点 / 跨点站位 / 场内跳跃的落点落在阻挡里是硬错;要按 E 交互的 NPC / 热点,交互半径里必须有
   **从出生点走得到**的地;触发区(`zones`)里必须有走得到的地,否则它永远不触发。这些东西很多是**按旧背景摆的**
   (雾津街头有 4 个 NPC、1 个热点、3 个触发区落在屋顶上;旧碰撞乱画时人能走上屋顶,所以一直没暴露)。
   处置是**改内容**:先在画上(和对白里)找到它指的那个东西,把坐标挪到那东西脚下的地上;触发区整块平移到紧挨着的街面、
   大小不变。**不要**为了够着它把屋顶开成可走。纯装饰、不交互的 NPC 站阻挡里是允许的。
   "要按 E"与运行时同一判据(`hotspotOffersPlayerInteraction`):空的 inspect(没图对话 / 正文 / 动作——
   过场冒泡锚点、占位)玩家按不了 E,不查;只在某段剧情里出现的实体碰撞(人群、临时箱堆,带 `conditions`)
   平时不挡,连通性不算它(图上只描边)。
   **一大片画上明明是街 / 地、却和主路不连通**(被房子围死):先找被屋顶挡住一半的巷口、灯杆边、门洞——
   雾津街头野地真正的路在街口灯杆旁,之前靠"一条暗缝"和"一堆塌棚木料"这两处错误的路连着,复查把错路一封就整片成了孤岛。
   真找不到口子才封,并在回报里点名。**封之前先想:这片是不是另一个出口 / NPC 的所在**(`check` 的 `islands` 会报)。
7. **玩法要求连通、画上却没有明摆着的通路**(河边:两岸都有出口,画上只有一河芦苇):挑画上**最像能过**的地方
   (浅滩、芦苇、倒木、踏石)圈成 walk,**不要凭空开一条直线**,并在回报里点名请制作人确认或补画。
8. **跳完就切场景的跳跃点**(`act_spot` 的动作里有 `switchScene`):落点只是跳的弧线终点,不需要能站;
   场内跳跃的落点要能站(跳过去就在那儿接着走)。`audit_walkable` 与本工具同口径。
9. **只做局部补丁**:哪块错改哪块,同 id 重写就是替换;**不重烘深度、不整张重画、不动 `collision_auto`**。
   整场照原画重圈过的场景,旧碰撞笔刷层(09-14 以前为补连通刷的)只剩坏处——它的阻挡格压过 walk、在可走区里留卡脚的碎格,
   它的可走格早被外围块盖掉——用 `brush --clear` 清掉,旧层留在 `terrain/history/`。

## 工具(`sh scripts/py.sh -m tools.terrain_workbench.art_review …`,产物在 `local/collision_review/<场景>/`)

| 命令 | 用途 |
|---|---|
| `render <场景> [--variant 夜] [--width 1600] [--out 路径]` | 全图:原画 + 此刻碰撞红块 + 多边形轮廓 + 标记点;输出世界宽高与时段变体名 |
| `crop <场景> x0 y0 x1 y1 [--scale 1] [--overlay] [--draft 草稿.json] [--variant 夜] [--out 路径] [--no-grid]` | 局部放大看画(自动拉对比度),坐标格直接读场景坐标;带 `h` 的块画出黄虚线估的顶面(`--depth` 叠深度着色,不作依据) |
| `apply <场景> 草稿.json` | 草稿一次落盘(同 id 替换)+ 导出一次 + 逐块报实现度;**第一次落盘前自动存 `before.png`** |
| `check <场景>` | 退出码 0 才算过:`problems / reach / marksOnBlock / interactUnreachable / zoneUnreachable / islands / underRealized` 全空;`smallIslands / finerThanGrid / variantDiff / offGridPct / brushLayer / blocksWithoutH` 只作参考(`blocksWithoutH` = 没写物体高的阻挡块,逐个过一眼是不是立着的东西忘了写) |
| `crowd <场景> [--x0 --y0 --x1 --y1] [--spacing N] [--width --seed] [--out 路径]` | 在所有"游戏判可走"的点上摆玩家(按透视缩放);脚底点绿 = 走得到、橙 = 走不到;站在带 `h` 的物体后面的人被物体抠掉一截 |
| `probe <场景> x,y …` | 这几个点挡不挡 |
| `connected <场景> x,y x,y [--seal x0,y0,x1,y1 …]` | 两点走不走得通(点落在墙上就近落到 40 以内的地);`--seal` 临时堵一个矩形——堵上院门 / 门洞再问墙外进不进得了墙里 = **薄墙漏缝检查** |
| `brush <场景> --clear` | 清旧碰撞笔刷层(整层,自动备份到 history) |
| `grid <场景> --fit` | 碰撞网格扩到盖满整张画(所有时段外观),不重烘 |
| `footprint <场景> --id <块> --h N [--out 草稿.json]` | 把按画面轮廓圈的阻挡块算成"占地 + h"草稿(占地 = 轮廓 ∩ 轮廓下移 h),并给出后面被挡住那片的范围;不落盘,`crop --draft` 对过再 `apply`。密集街镇批量改占地用它 |
| `move <场景> <npc\|hotspot\|spawn\|align\|landing\|zone>:<id> x,y` | 挪标记坐标(只动那两个数;触发区给新中心、整体平移;先核往返幂等) |
| `regions` / `region [--h 物体高]` / `remove` | 列 / 单块写 / 删 |

草稿 JSON:`{"id": {"kind": "walk"|"block", "pts": "x,y x,y …", "h": 物体高?, "h0": 下面空着多高?, "flat": true?, "note": "…"}}`
(`flat` = 故意不写 h 的平块——死角地、墙后封口——`check` 的 `blocksWithoutH` 不再列它),坐标 = 场景坐标(与 NPC 同尺);
block 的 `pts` 是**占地**,`h` 只给复查图估遮挡(运行时与合成器都不读)。
图例:出生点绿、出口青圈、NPC 橙方块、其它交互热点淡蓝圈、跨点站位紫 / 落点黄(切场景的落点灰黄)、
触发区青色虚框、实体自带碰撞品红块、作者多边形绿(walk)/ 红(block)线。

## 已知坑

- **摆人图看脚底的圆点,不看身子。** 人从脚点往上画 150 wu 高;没写 `h` 的物体不会挡人,所以站在屋脊线下方地上的人
  身子会盖在屋顶上——那是对的。写了 `h` 的物体会把站在它后面的人抠掉一截:被抠的人脚下是"物体后面的地",
  要问的是那块地按连续性该不该有。深度标定塌成平面的场景(崖墓系列)人物远近一样大,别拿人物大小判断透视。
- **`crowd` 摆的是"可走"不是"走得到"**——孤岛上照样站满人,所以才有橙点和 `check` 的 `islands`。
- **物体后面的窄条缺省撒点看不到人**(锅盆后约 12 宽的一条):看这种地方要 `crowd --spacing 12` 左右框小块看。
- **缩成占地后薄的块常掉进 `finerThanGrid`**(不再按实现度查),这是网格分辨率所限,看叠图红边对不对即可。
- **立着的物体画面区里,反投影链会折叠**:行走面在物体画面上是估出来的,几个画面点可能压进同一格——洋车车篷、
  岸边箱子画面里出现过"walk 边以外却显示能走"的错位,`check` 不报(块薄进了 `finerThanGrid`)。物体画面区要逐块
  `crop --overlay` 放大核,错位就把占地块往外多压进 10 来单位。
- **把"按轮廓封"改成"占地 + 后面封口"会夹出碎缝**:占地块、`_后` 封块、旧块三者之间常留一两格宽走不到的缝
  (test_scene 夹出 20 处),`smallIslands` 会列出来,封掉(写 `flat`)或让相邻块互相压进 10 单位。
- **占地若是"轮廓逐列往下减 h"算出来的,黄虚线的顶线按构造一定贴着屋顶上沿**——那时 h 估错只能从前沿看出来:
  前沿(接地线)对不上墙脚就是 h 错了。
- **一堆高矮不一的东西一块只能写一个 `h`**:为了黄虚线对得上,按高度拆成几块(箱堆 + 高箱)。
- **小块摆人太密看不清**:框的块小时缺省撒点也密,手动 `--spacing 40~60`;窄条反过来要 12。
- **实现度及格线随块大小走**:栅格化误差集中在边上一圈。< 5 格宽的(柱子、单个桶)只进 `finerThanGrid` 作参考;
  5–10 格及格线 0.8;更大 0.9。大块不及格多半是那一带行走面把好几个画面点压进了同一格,`crop --overlay` 对红块边。
- **`apply` 的 `blockedPct` 是按网格格数算的,`render` 的 `blockedScreenPct` 是按画面像素算的**,两者不同是正常的。
- **时段变体各有行走面**:同一张网格投到夜图会偏(`variantDiff`),夜图也要 `crop --overlay --variant 夜` 扫一遍边;
  偏得离谱(>10%)说明两套行走面不一致,报给制作人,别在一张网格上两头凑。
- **深度不作依据**:有的图深度整张是错的;就算对,着色也是按行归一化的,一整行都是墙 / 水 / 天时分不出立起来和平地
  (崖墓正式龛墙前整片同色)。读图只看原画;物体高、占地后沿都按画上的顶面 / 接地线估。
- **"最近走得到的点"只是几何提示**:阎王岭山口的歇脚棚热点离画上的棚约 450 单位,照提示挪会落在空路中间;先找画上那个东西。
  挪完看一眼有没有压到别的交互圈上(两个 E 提示叠在一起玩家按不准)。
- **坐标在画外、交互半径大得离谱的热点**(test_room_a 四个,x/y 放大倍数还不一致)是历史数据问题:`check` 报"在画外",
  **别**去挪——没法反推原意,挪进来半张图都冒 E。在回报里列出来交给策划定位。
- **删一块用 `remove --id`**:草稿 `apply` 只会新增或同 id 替换。
- **`apply` 有块实现不足时退出码 1,但已经存上了**——看逐块输出决定改哪块,别当成"没存"再存一遍。
- **两块 walk 边刚好对上**时栅格化会留细缝;小于约 30×30 的洞工具不当岛(不生成阻挡),但让相邻 walk 多重叠一点更稳。
- **碰撞网格可能没盖满整张画**(temple_exterior 纵向只盖到 y≈1315 / 1438):烘焙时网格只按行走面有效区取范围,
  运行时对网格外一律当"不挡",那一截画多边形也挡不住——`check` 报孤岛 / 外围块实现不足,并给 `offGridPct` 与提示。
  处置 `grid --fit`:格子大小与对齐不变,只在四周补格(不是重烘),补出来的格自动结果当"没数据"、作者多边形照常栅格化进去。
- **`smallIslands` 是走不到的碎片**(桌缝、画底单格、没到孤岛门槛),只作参考;摆人图上零星橙点能在这里对上号。
  多半是相邻两块共用了一条边——互相压进 10 单位就没了。
- **NPC 要不要交互看两处**:场景里的 `dialogueGraphId`,没写就继承角色注册表(`character_registry.json`)里那个角色的。
- **生成块别手改**:`art_可走以外*` 每次落盘按可走集重算,人在工作台里拖它会被冲掉;要改就改 walk 多边形。
- **资源走 DVC**:`public/resources/runtime/**` 被 git 忽略,`git status` 看不到碰撞改动;每次保存往 `terrain/history/`
  留一份,`terrain.json` 因多边形加密从几百字节涨到几十 KB,正常。
- **深度标定塌成平面的场景**(见 [scene-bake-downstream](../../asset-pipeline/mechanisms/scene-bake-downstream.md))
  反投影照样能用(画面点 → 网格仍是单射),照原画圈就行;**别**为了碰撞去重烘或调标定——标定归制作人手动做。

## 验收(三件自检 + 一次独立复查)

1. `check` 退出码 0。
2. 按 ~1100×750 场景单位分块 `crop --overlay`,每块红边贴着墙脚 / 崖边 / 路沿;每个时段变体再扫一遍。
3. 按同样分块 `crowd`,没有圆点落在屋顶 / 墙 / 水 / 崖外 / 家具上,没有明明是路却空着的一片,橙点都有交代。
4. 交给**另一个子代理**按技能里的复查协议独立看,它报的每一条按"局部补丁"修,修完再请它看,直到它报"无问题"。
5. 收尾:`sh scripts/py.sh -m tools.terrain_workbench --check`(全场景)+ `validate-data`。
