## 适用时机

给角色产新动画、补 state、或对已上线角色重扣/重生成。本卡管形状与判断,不重复步骤。

## 阶段骨架(每阶段:目的 + 完成判据)

1. **源确认**——锁定输入源。完成判据:源 = 游戏当前实际源,以 shipped `atlas.meta.json` 的
   packMode/source 逐角色查证,不凭目录名猜;新生成时设定图已修成**严格正侧面**(头、胸、骨盆、腿脚同一侧向,
   道具与握点完整、留足安全边距),并记为本批次唯一身份源——没过这一关不许进生成。
2. **批次准备**——本批全部动作的提示词写齐并统一检查(原地、可循环、镜头锁死、全身在框内、身份一致、
   允许动/必须固定的部位)。完成判据:**人批准本批次**。
3. **批量生成**——批准后连续生成整批(或到既定费用上限)。完成判据:整批关闭、原视频全部归档。
   生成期间只核对任务与费用(提交成功没有、重复没有、扣费没有、能否下载),**不做质量验收**。
4. **统一验收**——批次关闭后对整批一次看完。完成判据:每条视频要么可用、要么进「下一轮重生候选」清单。
5. **程序产出**——对可用视频跑确定性产线(拆帧、抠图、稳定、循环、图集、法线)。完成判据:硬闸门全过
   (程序退出码为准);agent 对程序报出的每条软 flag 都有 accept/reject。
6. **验收**——预览工具目验 + 素材审计。完成判据:动作/锚点/循环在游戏一致渲染下目视无缺陷。

## 判断点(拿什么证据判)

- **QA flag 定性**:调该 clip 的密排帧图目视,分"真缺陷"(如枪头凭空漂浮 + 空手)与"良性"
  (如躺姿时搁在身边的长枪被连通域 flag → accept)。
- **指标判读**见 [抠图判读铁律](../mechanisms/matting-toolbox.md),本卡不重复。
- **视频要不要重生,只认三个理由**(2026-09-14 制作人定,09-23 批为通则):A 运动中有部位被画框裁掉;
  B 不是正侧面;C 身份/画风整体漂移、局部后处理救不回来。**除此之外一律留在后处理解决**——抠图脏、
  节奏幅度不理想、脚滑、循环接缝、局部画质差、"后处理太难",都不是重生理由。
- **重生不自动发生**:命中 A/B/C 的只进「下一轮重生候选」清单(角色、动作、原任务、证据、命中哪条、预计费用、
  拟改的设定图或提示词),**人批准后**作为下一轮独立批次统一提交。
- **人说"这条可以用"就是强制可用源**:此后任何 QA 缺陷、旧拒绝记录都不许再把它打回生成,必须把下游做完。

## 分工契约

程序驱动确定性流水并判死硬失败;agent 只做 QA 语义裁决、异常排查、改配方**数据**(不改逻辑);
人拍生成模型选型与最终风格,**批准每个生成批次、批准重生候选、判定"可以用"**——凡花钱的生成都要人点头。
