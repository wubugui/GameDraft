## 背景

故事仓(`../FindingDogStory/`,GameDraft 的兄弟目录)新旧稿混放,曾有 agent 误把新设计回写进 3 份死档,
被 git 回退;2026-06-27 定过一版"主线唯一权威 = Demo完整流程"。**07-15 起故事仓有了统一总入口
《游戏总纲》,08-16 / 09-18 制作人又以「设定对账」文档逐次改设定**(开场改成骗定金→赌坊输光→
空山长明灯、帕子包改为背尸逃命途中捡、基调定为俗的怪静的怕),旧口径已经对不上:
按旧口径去读《关卡脚本_背庄家尸》会拿到作废的接活段与捡包位置(偏差记录 2026-09-06)。

## 决定

冲突时的权威顺序**以 `Demo制作资料/游戏总纲_设定剧情玩法.md` 一·1「正典优先级」为准**,本卡不复述清单,
只记读法:

- **最高 = 制作人当次审批的结论**,落在 `Demo制作资料/设定对账_<日期>.md` 系列(按日期越新越优先;
  各份顶部写明它取代了哪些旧稿)。**旧关卡脚本与对账冲突处,旧脚本是历史稿**——多数关卡脚本顶部
  已挂对账横幅,**先读横幅再用正文**。
- 其次 = 游戏总纲(一·2「已锁定的裁决」是各次对账的摘要);再次 = 其余 `Demo制作资料/`;
  阿秀支线方案、`故事设计/`、`系统设计/` 只在不与前面冲突时算数。
- `Demo完整流程_2026.06.05.md` **降为主线拍号 ↔ 实现 s-id 的映射表**(外加逐拍的基调标注),
  不再是剧情唯一权威。**显示编号 ≠ 实现 s-id**(如送货=显示⑧但 `s09_songhuo`),别按显示号猜 id。
  注意游戏主图已在 `s02_beishi` 之前长出一段序章状态,映射表未必覆盖——以 `flow_xungou_main` 为准。
- **已落地主线的梗概** = `故事设计/主线故事进度.md`(按主图状态顺序、以游戏落地为准):策划模式进场必读;
  **写只凭制作人明确命令**,流程见 skill `mainline-story-progress`。
- 故事仓位置:本机是 GameDraft 的兄弟目录;换机器时可能不在这里(曾在 `H:/FDStory/FindingDogStory`)。
  找不到就问制作人,**别当它不存在、也别凭记忆补设定**。
