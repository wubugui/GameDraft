## ⚠ 现状（2026-08-23）：本卡与下面那张对比表**都**已过期

统一光影本身在 2026-08-23 又换过一次内核：`E` 不再是"除掉画里的白天光"这种
比值口径，而是在伪世界里 **final gather 积出来**的辐照度，原画被拆成
`base·E + emissive`（恒等式）。现行口径一律以
[pseudo-world-final-gather](2026-08-23-pseudo-world-final-gather.md) 为准。

下面这一节记录的是 2026-08-21 那次取代，保留是为了说明**为什么**离线绝对辐射
还原那条路被放弃 —— 那个理由至今成立。

## ⚠ 2026-08-21：离线辐射还原被统一光影取代

**本卡记录的是"曾经怎么做"，不是"现在怎么做"。** 新场景一律走
[character-lighting](../mechanisms/character-lighting.md) 里的统一光影，
离线端在 `tools/scene_relight/`（不是本卡说的分割 + 绝对辐射还原）。

被取代的原因不是实现没做完，而是**目标变了**：

| | 本卡的路线（2026-07） | 统一光影（2026-08） |
|---|---|---|
| 离线烘什么 | 绝对辐射场（100 nit 尺度）+ 发光 mask | **只烘几何项**：法线 / 天穹可见性 / 3D 可见性网格。与光无关，**光怎么变都不用重烘** |
| 场景怎么变暗 | 用还原出的辐射场重新积分 | `原画 × clamp(S_new / S_day)`——先除掉画里的白天光，再乘上新光 |
| 角色怎么被照亮 | 从辐射场 probe 积分 irradiance | 与场景吃**同一个 S**（`albedo × S × radianceScale`） |
| 谁是真相源 | 烘出来的 probe（静态） | 场景 JSON 的 `lighting` 块（实时可改） |

**仍然成立、且被新系统继承的几条**（不要因为本卡"过期"就一起丢掉）：

- **实体受光必须在伪世界空间积分**，禁止屏幕空间直接模糊/积分。这条在新系统里升级成了
  铁律 S12：*一切光照都发生在伪世界空间*。
- **离线只烘、运行时只消费**，分割/烘焙模型不进运行时。
- **已烘场景是用户自己烘的，不要全量重烘**；迁移由用户按场景推进。

新系统另外补了两条本卡没有的：

**① 去霾的减法必须逐通道设下限，不能硬钳到 0。** 霾是**有颜色**的
（实测雾津街头 hazeColor = (0.835, 1.021, 1.144)），`max(painting − hazeAmt, 0)`
在暗部会把通道非对称清零——蓝绿先死、红活下来，画面上一片红色噪点
（实测 7.23% 像素部分钳零、孤立零点 5.02%）。改成"每通道至少留 10%"后降到 0.002%，
且钳住时按比例缩 ⇒ 色度守恒。

**② 显示变换绝不能烤进辐射场**
（本卡时期的工具把 ev 与 clamp 烤进导出 PNG，实测导出图动态范围只剩 17×，
角色 gather 到的光等于没有）。

## 背景（以下为 2026-07 的原始记录，保留作沿革）

二维绘制场景只有 LDR 颜色,实体素材又一概作为 albedo 进 Lambert 管线;不先恢复场景辐射度,
场景图上画出的灯、窗与明暗关系就无法成为实体的入射光。纯亮度规则会把白石、路面、水面误判成
发光体;纯语义模型认得出"灯笼"却判不准它是否点亮。首版(07-21)据此设计了"语义出候选 +
辐射证据四重裁决"的混合管线,**07-23 实测后被制作人推翻**:裁决层复杂、不可复现,且真正需要的
只是"哪块像素属于发光体"这一个语义问题。

## 决定

场景辐射度还原固定为**离线**管线,分两步:

1. **整图恢复**:`rad(x) = 100 × EOTF_sRGB(C_ldr(x)) × 2^sceneExposureEV`
   ——**100 nit 绝对尺度**、EV 以 `2^` 乘进线性辐射、每张图必须有独立 `sceneExposureEV`。
   (⚠ 实现缺口:`sceneExposureEV` 至今只在默认参数表里,计算路径无人读取。)
2. **语义一刀两断**:开放词汇分割给出发光体 mask(**mask 是语义的,不是亮度的**),
   `emit = rad × mask`、`base = rad × (1 − mask)`,两张图分别进后续积分。不再有"候选 → 证据裁决"层。

实体受光必须在深度还原的**伪世界空间**内从该辐射场积分 irradiance;
禁止让屏幕空间重叠、伪世界深度相离的像素互相照明。分割模型只在开发期烘焙时运行,
运行时只消费烘焙产物。

## 被否方案(防翻案)

- **语义只出候选 + 像素对比/内部亮度/近环溢光/环境能量四重证据裁决 `gainEV`**
  (07-21 首版,**07-23 否**):裁决层调不收敛,`gainEV` 已降级为可视化场,不再参与还原式。
- **tint 归一模型**:已推翻。
- **把 mask 当亮度阈值用**:mask 是语义判断,拿亮度反推会退回被否的纯统计路线。
- 由通用 agent 逐图目测标发光增益:不可复现,难以批量回归。
- 纯统计亮度或固定 LDR→HDR 肩线:会把日景白石、亮路、水面抬成发光体。
- 逐场景堆专用手写规则:维护成本随场景数线性增长。
- 在屏幕空间直接模糊或积分:无法排除屏幕重合、伪世界深度相离的错误传光。
- 运行时携带分割模型:体量与内存无必要,离线烘焙即可。

## 验收口径

- 正样本保留灯、烛火、发光窗口;负样本必须覆盖未点亮灯具、白石、亮路、水面、雾中高亮。
- 不能只报"检出过光源",须同时看漏检、误检与逐图曝光。
- 进实体着色验证前,典型场景先出带 nit/EV 标尺的 HDR 辐射度图与数值统计。
- ⚠ 已烘场景是用户自己烘的,**不要全量重烘**;迁移由用户按场景推进。
