## 现行决定(2026-08-30,制作人定调)

> **原画就是最终的光照结果。**

运行时不重新照亮场景,只把作者摆的**实体灯**加上去(先从原画反解 albedo 再乘);
**「夜」靠换一张夜原画** + 该时段的 probe + 该时段的灯,不靠调暗天光。
机制正文在 [scene-lighting](../mechanisms/scene-lighting.md) 与
[character-lighting](../mechanisms/character-lighting.md),本卡只记"为什么是这样"。

三代路线的差别:

| | ① 离线辐射还原(2026-07) | ② 统一光影(2026-08-20) | ③ 原画 + 加性灯(2026-08-30,**现行**) |
|---|---|---|---|
| 场景怎么变暗 | 用还原出的绝对辐射场重新积分 | `原画 × S_new / S_day`(除旧光乘新光) | **不变暗**——换一张夜原画 |
| 离线烘什么 | 绝对辐射场 + 发光 mask | 只烘几何项(法线/天穹可见性/3D 网格/GI 命中图) | 同②,但只有法线与天穹可见性有消费者 |
| 角色怎么被照亮 | 从辐射场 probe 积分 | 与场景吃**同一个 S**(实时) | probe 底光(烘死)+ 与场景**同一次打包**的加性灯 |
| `S_day` 的语义 | — | 参考光,当除数也当基准 | **只剩 albedo 除数**一个用途 |
| 天光/太阳的运行时项 | 有 | 有 | **已删**(原画自带,再算一遍是重复计光) |

## 为什么否掉②(统一光影的整体重打光)

不是实现没做完——P0–P6 全部落地并验收过。是**目标变了**:一张手绘原画的明暗关系
是美术画出来的成品,把它除以一个近似的 `S_day` 再乘一个近似的 `S_new`,等于用两次
近似去换一个"能实时变暗"的能力,而这个能力的真正需求(夜景)有更便宜也更好看的解:
**直接画一张夜原画**。代价是每张时段原画都要各烘一套载荷,收益是画面质量由美术直接掌控。

连带的结论:统一**角色**路径也一起停用(`Game.UNIFIED_CHAR_PATH_ENABLED = false`,
留码不删)。它的环境项是"合成天光 × 天穹可见性",原画不再被重打光之后它不对应任何东西。

## 仍然成立、被逐代继承的几条(别因为前代"过期"就一起丢掉)

- **一切光照发生在伪世界/世界空间**,禁止屏幕空间直接模糊或积分。现已升格为铁律 0
  (见 [coordinate-spaces](../mechanisms/coordinate-spaces.md))。
- **离线只烘几何项、运行时只消费**;分割/烘焙模型不进运行时。
- **摆灯、调参、推进时刻都不用重烘**(烘的全是与光无关的几何项);
  但**换原画就必须重烘那一张**。
- **已烘场景是用户自己烘的,不要全量重烘**;迁移由用户按场景推进。
- **显示变换绝不能烤进辐射场**(②时期实测:烤进 8bit 后导出图动态范围只剩 17×,
  角色 gather 到的光等于没有)。
- **去霾的减法必须逐通道设下限**,不能硬钳到 0(霾有颜色,硬钳会让暗部通道非对称清零)。

## 被否方案(防翻案)

- **③之前的整体运行时重打光**(②,2026-08-20 → **08-30 否**):理由见上。
  `SceneLightingDef` 里为它准备的 `radianceScale` / `characterShape` / `giGain`
  与 GI 反弹网格、3D 天穹可见性网格随之**无消费者**(料还在,别当它们在生效)。
- **「运行时重打光取代换背景图」**(②的推论,**08-30 反转**):`timeVariants` 曾在
  2026-08-21 被判为死契约,现在它是夜景的正路(`src/utils/sceneAppearance.ts`)。
- **语义只出候选 + 四重证据裁决 `gainEV`**(①首版,07-23 否):裁决层调不收敛。
- **tint 归一模型**:已推翻。
- **把 mask 当亮度阈值用**:mask 是语义判断,拿亮度反推会退回被否的纯统计路线。
- **发光体 mask 进着色/遮罩通道**(2026-08-25 制作人重申的永久废案,"早就说过"级):
  任何"标出哪些像素在发光、再拿这张图去参与着色或做遮罩"的方案不再提。
  **边界**:采样器为降方差在内部建的发光体表(按展开后的辐亮度阈值挑像素,只用来挑采样方向)
  **不算越界**——它不产出 mask、不进着色通道。判一个方案踩没踩线,就问
  "这张发光体的图会不会被别的东西读走"。
- 由通用 agent 逐图目测标发光增益:不可复现,难以批量回归。
- 纯统计亮度或固定 LDR→HDR 肩线:会把日景白石、亮路、水面抬成发光体。
- 逐场景堆专用手写规则:维护成本随场景数线性增长。
- 在屏幕空间直接模糊或积分:无法排除屏幕重合、伪世界深度相离的错误传光。
- 运行时携带分割模型:体量与内存无必要,离线烘焙即可。

## 背景（以下为 2026-07 的原始记录，保留作沿革）

二维绘制场景只有 LDR 颜色,实体素材又一概作为 albedo 进 Lambert 管线;不先恢复场景辐射度,
场景图上画出的灯、窗与明暗关系就无法成为实体的入射光。纯亮度规则会把白石、路面、水面误判成
发光体;纯语义模型认得出"灯笼"却判不准它是否点亮。首版(07-21)据此设计了"语义出候选 +
辐射证据四重裁决"的混合管线,**07-23 实测后被制作人推翻**:裁决层复杂、不可复现,且真正需要的
只是"哪块像素属于发光体"这一个语义问题。

### 2026-07 的决定

场景辐射度还原固定为**离线**管线,分两步:

1. **整图恢复**:`rad(x) = 100 × EOTF_sRGB(C_ldr(x)) × 2^sceneExposureEV`
   ——**100 nit 绝对尺度**、EV 以 `2^` 乘进线性辐射、每张图必须有独立 `sceneExposureEV`。
   (⚠ 实现缺口:`sceneExposureEV` 至今只在默认参数表里,计算路径无人读取。)
2. **语义一刀两断**:开放词汇分割给出发光体 mask(**mask 是语义的,不是亮度的**),
   `emit = rad × mask`、`base = rad × (1 − mask)`,两张图分别进后续积分。不再有"候选 → 证据裁决"层。

实体受光必须在深度还原的**伪世界空间**内从该辐射场积分 irradiance;
禁止让屏幕空间重叠、伪世界深度相离的像素互相照明。分割模型只在开发期烘焙时运行,
运行时只消费烘焙产物。

### 2026-07 当时的被否列表

- **语义只出候选 + 像素对比/内部亮度/近环溢光/环境能量四重证据裁决 `gainEV`**
  (07-21 首版,**07-23 否**):裁决层调不收敛,`gainEV` 已降级为可视化场,不再参与还原式。
- **tint 归一模型**:已推翻。
- **把 mask 当亮度阈值用**:mask 是语义判断,拿亮度反推会退回被否的纯统计路线。
- 由通用 agent 逐图目测标发光增益:不可复现,难以批量回归。
- 纯统计亮度或固定 LDR→HDR 肩线:会把日景白石、亮路、水面抬成发光体。
- 逐场景堆专用手写规则:维护成本随场景数线性增长。
- 在屏幕空间直接模糊或积分:无法排除屏幕重合、伪世界深度相离的错误传光。
- 运行时携带分割模型:体量与内存无必要,离线烘焙即可。

### 2026-07 的验收口径

- 正样本保留灯、烛火、发光窗口;负样本必须覆盖未点亮灯具、白石、亮路、水面、雾中高亮。
- 不能只报"检出过光源",须同时看漏检、误检与逐图曝光。
- 进实体着色验证前,典型场景先出带 nit/EV 标尺的 HDR 辐射度图与数值统计。
- ⚠ 已烘场景是用户自己烘的,**不要全量重烘**;迁移由用户按场景推进。
