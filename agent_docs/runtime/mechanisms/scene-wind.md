## 是什么(一句话)

场景 JSON 的 `wind` 描述**空气的速度** u(x, t)(M-world、wu/s),组装层持有**一份**参数 + **一个钟**
(`SceneWindState`),粒子系统与背景草木摆动从同一处读——所以一阵风过来纸钱掀起与枝叶一甩是同一拍。
两路各有增益(`gain.vfx` / `gain.sway`),分开调。

## 权威源(读代码从哪进)

- 数学:`utils/sceneWind.ts` —— 唯一实现,全在 CPU(没有 GLSL 版);成千上万个固定点的批量阵风走
  `windGustBasis / windGustClock / windGustFromBasis`(和角拆分,与 `windGustMul` 同一个公式)。
- 消费者:普通粒子在 `vfxSim.stepGeneric`(阻力相对空气:dv = −drag·(v − u));薄片(纸钱)在
  `vfxPlate.ts`;背景摆动在 `backgroundSway.ts`(没点亮的背景换成"底板 Sprite + 植被网格",点亮的背景尚未接)。
- 拆层:`tools/character_lighting_lab/sway_field.py` → `lighting/<背景基名>/sway.json` +
  `sway_plate.png`(底板)/ `sway_matte.png`(R alpha · G 叶度 · B 自由度)/ `sway_ids.png`(R/G 实例 id)/
  `sway_rigid.png`(逐像素刚体度)。
- 作者面:**草木工作台**([[sway-workbench]])——自动分割打底 + 手涂三个通道,落 `sway_paint.png`
  (烘焙的输入:R 补植被 / G 锁死不动 / B 刚体)。旧的单文件 `sway_lock.png` 仍然认(与 G 通道取并集)。

## 硬契约(违反即 bug)

- **风是速度,不是加速度**。受力方按自己的气动参数去"感受"它;把风写成一个直接加到粒子上的
  加速度,重的轻的一样被推——那是 `motion.wind`(发射器私有的旧字段,与场景风无关)。
- **一个钟**。钟在组装层与粒子同处推进(同暂停语义);摆动 mesh 与粒子各自再起一个钟 = 两边不同拍。
- **近地对数廓线是"大部分纸不动"的来源**:平躺的纸只吃到翘起边缘高度处的风(z0 = `roughness`)。
  别拿一个"吹动阈值"去凑这个现象。
- **阵风顺流推进**(τ = t − 顺风距离 / 平均风速):一阵风是扫过场景的,不是全场同时起落。
- **🔴 湍流是一片共享的涡,不是逐粒的抖动**(制作人 2026-09-12:"吹粒子感觉很死,就一个方向;
  真实的风至少会在原地打圈")。`sampleSceneWind` 返回的就是平均 + 阵风 + 涡:若干**无散度**的随机波
  叠加(每个模式的振幅 ⟂ 波矢 ⇒ ∇·u′ = 0,所以只会打旋、不会凭空涌出),随平均风推进、按各自的
  翻转率衰变重生,脉动量级 = `turbulence.intensity` × 该高度的平均风速。
  ⚠ 发射器自己的 `motion.turbulence`(作者面的老模块,萤火 / 尘埃在用)是**另一回事**:那是作者摆的局部抖动,
  与场景风的涡并存、会叠加。纸钱没配它(薄片只读 `turbulence`,paper_money 里为空),所以不存在重复计。
  ⚠ **消费方不许再叠一份自己的噪声**,尤其不许把噪声的时间 / 空间轴按**粒子种子**错开——
  那样每粒有一套私有乱流,挨着的两粒永远不会被同一个涡卷走(纸钱曾经就是这么写的,画面上的症状
  正是"全场只朝一个方向、看着很死")。同理:**竖直分量不许丢**(`out[1]`),上升下沉气流是纸被卷起来的来源;
  通用粒子那条 drag 路径曾经只加 x / z。
- **🔴 草木有惯性:风给的是目标角度,不是姿态**(制作人 2026-09-12:"物体对风的响应不真实")。
  每株(场是每个顶点)解一个受迫二阶振子 θ'' + 2ζω₀θ' + ω₀²θ = ω₀²·θ_target,ω₀ ∝ 1/√株高、
  ζ = 结构阻尼 + 随风长的气动阻尼。**不许退回"按当前风速直接摆到位"**(准静态):那样阵风一来立刻到位、
  风一停立刻回中,不会过冲、不会余振、不会与阵风共振——这是看着假的主要来源。
  实测(跑马梁,风速阶跃 ×2):1 m 灌丛 0.53 s 到峰、过冲 29%、余振周期 1.05 s、1.7 s 停;
  3.8 m 松树 1.02 s 到峰、过冲 38%、余振周期 2.03 s、4.1 s 停(高的慢、矮的快,层次自己就出来了)。
  积分是 `stepSwayOscillator`(纯函数,`backgroundSway.test.ts` 钉着过冲 / 余振周期 / 子步无关 / 不发散),
  子步 1/120 s、一帧最多 8 步,断档(切场景、调试跳帧)按当前风"摆到位"重新起步、不补跑。
- **透视场景**:伪世界横向 1 wu ≡ 1 画面 wu;片的尺寸、离地高度、位移都是真实量 × **脚点透视系数**
  (与实体移动步长 × f 同一根轴)。不乘的话远处的纸既大又飞得快。
- **分割全时段共用主背景那份,底板按时段各补各的**(2026-09-13 起)。结构不随时段变、暗的夜图分割不出来,
  所以 matte / ids / rigid / sway.json 用主背景那一份;但**底板要用这个时段自己的原画补**——夜里植物挪开
  露出来的地方必须是夜景的颜色(之前是把白天的底板字节原样抄进夜景目录,夜里一晃就露出一块白天)。
  补法抽成 `plate_plan`(按植被掩码算一次"去哪取")+ `fill_plate`(照着填任意一张图),同一份计划填所有时段。
  重构前后白天的底板 / matte / ids **逐字节相同**(跑马梁验过)。
  只写进**已有照明载荷**的时段目录——为它单开一个只装 `sway.*` 的目录,打包按载荷入口展开时进不了包。

  `background_sha1`**,不再需要烘完手补。
- **打光场景的漏出处补图按"这个时段烘没烘几何场"出**(`sway_field._slot_lit`),与运行时同一条判据;
  2026-09-14 前按"场景 JSON 有没有 lighting 块"判,运行时改成没写块也打光之后,没写块的场景
  (跑马梁 / 崖墓前段 / 牛头凼)要重跑一遍 `sway_field` 才补得出 `sway_plate_normal/albedo/depth`,
  否则进游戏报"打光场景缺补图,草木不接"。
- **🔴 渲染走一张位移图(UV 图),打光 / 不打光同一条路**(制作人 2026-09-13 定的做法)。每株的网格不出颜色,
  渲进一张离屏 `rgba16float` 位移图:RG = (源 uv − 本像素 uv) × 覆盖度、A = 覆盖度,按预乘混合叠(远的先画)。
  读的一方一律先用本像素 uv 读它,再按 `源 uv = 本像素 uv + RG / A` 去原图取:
  - 不打光:合成面 `mix(底板, 原画(源 uv), 覆盖度)`;
  - 打光(`LitBackground`):植物像素取**主光照缓存**的源 uv(光跟着植物走,不会在树上滑),露出来的地方取
    **"扣掉植物"那份光照缓存**——同一套灯与参数,输入换成补过的原画 / 法线 / albedo / 深度(`sway_plate_normal`
    / `_albedo` / `_depth.png`,烘焙按场景有无 `lighting` 自动出,`sway.json.litPlate` 记着)。两份缓存同脏同算,
    **植物动的时候一格光照都不重算**;雾用的深度同样按位移图取。
  - 存差值不存绝对 uv:位移几十像素,半浮点在这个量级精度足够;覆盖度 0 天然就是"不动"。
  - 位移图每帧在 `Game` 帧尾、光照缓存之前渲(`SwayBackground.renderUv`),**不能放进场景树里渲离屏目标**(串台)。
  - 🔴 打光的背景读着位移图与露出处缓存,**卸载 / 原地重装前必须先 `SceneLightingSystem.detachSway()`**
    (绑回占位)再销毁——顺序反了 BindGroup 自毁、下一帧整局卡死(pixi-v8-traps);`LitBackground.sway.test.ts` 钉着。
  - 打光场景原先**根本没重设风**(只有不打光那条路重设):粒子会接着吃上一个场景的风。现在装光照时一并重设。
  - 取证:页面里同步逐帧调 `update` + `renderUv`,再 `gl.readPixels(FLOAT)` 读位移图对账(跑马梁松树:网格梢部
    平均位移 −18.6 px ↔ 位移图"源 − 本" +15.6 px,方向与量级对上);打光场景把 `litBg.mesh` 渲进离屏图、
    有风无风各一张比像素(崖墓入口 1.8 倍风:32.5% 像素变化、全部在植物附近、零纯黑)。
- **不许回到整张原画 UV 扭曲**(v1,2026-09-12 制作人否掉:"树干应该整体摇晃,石头应该不动")。单层扭曲
  结构上做不到——被植物盖住的背景没有像素,植物一动只能拖邻居,石头、树干跟着变形。v2 两层:
  - **底板**:只把植被轮廓往里 `margin`(48 原生像素)一条带补成背景(镜像外侧纹理,Telea 兜底;
    `plate.authored` 可手修);石头 / 崖壁 / 路面都在底板上,**永远不动**。石头像素在分割时就从植被里扣掉。
  - **植被层**:一株一个实例,网格贴回原画自己的像素,片元按 `sway_ids` 只画本株。`plant`(树,或木质像素
    > 2%)整株绕根**刚体转**(轴 = 上 × 风向,株当过根朝相机的直立面);`field`(灌丛 / 竹丛 / 草)根部钉住、
    按自由度平滑弯;叶片颤动只乘在叶像素上(`matte.G`,木质 ≈ 0)。
  - **逐像素刚体度**(`sway_rigid.png`,作者在草木工作台画):位移在"整株转"与"弯曲"之间按它插值,
    所以**同一株里可以竿是刚体、叶子照弯**(竹子、带主干的灌丛)。转角用该株根部那一个,整根竿一起摆;
    刚体度是连续值,竿与叶的交界不会撕开。⚠ 它**不**改变 `kind` —— 涂层并进 `woody` 会让整丛变刚体,
    那正好毁掉"竿刚叶弯"(2026-09-13 踩过)。
  - **🔴 刚体交界与锚点分界处网格细分**(制作人 2026-09-14:"我把一个地方涂抹成了刚体,怎么运行起来发现还有扭曲呢"
    "不然大部分时候刚体没用")。格内位移是顶点线性插值:原先一格 24 wu、刚体度只在格点上取一次,比格子细的竿
    一个顶点都压不中就整根照弯,半格竿半格叶的格插出来半软半硬(跑马梁实测涂层:7% 的刚体像素实际刚体度 < 0.5、31% < 0.9)。
    现在 `SwayBackground` 建网格时:
    - **只细分交界格**(24 → 4×4 个 6,`GRID_REFINE`):场里一格外扩一个细格的窗口内刚体度有高有低(`RIGID_MIX_TOL`),
      或刚体部分(`plant` 整株 / 场里有刚体的格)跨了两个锚点的管辖区(`swayPivotSplits`:半平面 × 凸矩形,查四角就是精确的)。
      整格全刚(刚体转动对位置是线性的)或全弯时线性插值本来就准,不加密;跑马梁这份涂层场类格从 1962 到约 2870。
    - **顶点刚体度取一个细格内的最大值**(`rigidCoverage`),不取那一点:竿上每个像素所在细格的四角都看得见它,
      竿上插出来就是满的;代价 = 竿两侧一个细格(≈ 6 wu)的叶子跟着硬——过渡带。刚体图 CPU 副本改成**原画全分辨率单通道**
      (半分辨率加平滑会把两三像素宽的竿抹成半灰)。
    - **邻格细分了的格铺成扇形**(格心连到边上每个点),否则挂点处 T 形接缝一动就裂、露出底板。
    - 纸钱的 `offsetAt` 按**三角形**插值取画出来的位移(与光栅化同一个插值;原先按粗格双线性)。
    - `backgroundSwayRigidMesh.test.ts`(真 `SwayBackground`)钉:2 像素宽的竿落在格子里任何位置,竿上画出来的位移
      == 刚体转动公式;同一粗格里分界两侧各绕各的锚点;只细分竿经过的那一列格子;没刚体没多锚点一格不细分;
      没有 T 形接缝、三角形面积恰好铺满;每个顶点上纸钱取的位移 == 顶点画出来的位移。变异验过:退回点采样 / 不细分 / 不铺扇形各自会红。
  - **位移软封顶 = 0.8 × margin × min(4, max(1, gain.sway))**:增益 1 是**安全档**(位移压在补带里,
    不可能露馅);增益再往上是**作者自己掌握的越界档**(制作人 2026-09-12:"调大了会走样,但我自己
    可以看着控制强度"),摆幅按倍数放开,代价是植物挪开处会露出底板补带外没补过的植物本体。
    上限倍数 `SWAY_GAIN_CAP_MAX` 与 F2「草木增益」滑条的上限是同一个数,改一处要改两处。
    **想"摆得大又不露馅"的正路仍然是加宽补带重烘**(`PLATE_MARGIN`)。
    补带宽度要兜得住**风里一直斜着的那一份**(原画没有风,见下),不只是晃动的起伏:2026-09-13 从 12 加到 48,
    自由度外延 `FREEDOM_EXTEND_PX` 按"≥ 网格一格 24 + 补带宽"跟着从 48 加到 72(`test_layers_and_serve` 钉着)。
    跑马梁松树(株高 332)实测梢部顺风位移:不封顶 平均 10.2 / 95 分位 21.9 / 最大 29.2 像素;
    补带 12 → 5.9 / 7.7 / 8.2(被压扁);补带 48 → 9.4 / 18.2 / 22.6。补带越宽,树冠中心离轮廓太远的地方
    镜像取不到背景、退到 Telea 糊色——那块一直被树冠盖着,只要位移小于补带就露不出来。
- **分割认不出"这丛看着怪",作者要有手动出口**(制作人 2026-09-12:"需要可以手动设置不扭曲的 mask"):
  `sway_lock.png` 里白的像素当石头处理——不属于任何实例、**也不补底板**,原画那块原样留在底板上
  (所以锁一丛竹子不会在它周围留一圈补过的痕迹:实测跑马梁锁 99020 px,底板只有 92 px 变过)。
  锁"画面上那一丛"最省事:`--lock-ids <上次烘焙的实例 id>` 把它并进掩码再重烘,之后想改形状直接画那张图。
  ⚠ **id 每次重烘都会变**(实例是分割结果按优先级排的),要再锁别的株先看新的 `sway.json`。
  这张图是输入不是产物:留在开发树、不进发行包、不登记 `LIGHTING_PAYLOAD_OPTIONAL`(与 `skyvis.png` 同类)。
- **摆幅透视按视深查表,不按透视轴**:透视轴只在可走区有意义;轴外(远山、崖下)按屏幕位置投上去会查错
  (跑马梁左上远山投到轴近端拿到 1.3,比脚下竹子还大,远山和近处一样晃)。烘焙沿轴采 (视深, 系数) 成表
  `sway.json.depthScale`,运行时用同一张 raw_depth 同一组映射解视深再查表(`depthScaleLookup`)。
- **不从深度推自由度**:深度估计把草叶细枝抹成地面,离地高当自由度会让梢一动不动;自由度来自分割
  (场 = 往下连着的植被像素数 ÷ 株高像素,向轮廓外延 48 px 让外圈网格顶点跟着走)。
- **逐帧 CPU 预算**:网格只铺有本株像素的格子(外扩一格);场的逐顶点风量按和角拆成"只随点"(参数变才重算)
  与"只随 t"两半,逐帧逐点只剩乘加。跑马梁 30 株 / 4.7k 顶点 ≈ 0.14 ms/帧(拆之前 2.2 ms)。
- **纸钱跟草木走**:躺在植被上的纸钱按 `SwayBackground.offsetAt` 取位移——场是按本株网格**双线性插值
  这一帧真实画出来的顶点位移**(状态在顶点上,再算一份公式必然与画面差一拍),刚体株走同一组转动系数。
- **🔴 弯角必须平滑饱和,不许硬截断**(制作人 2026-09-12:"把风速倍率调很大,树木晃得更小,甚至一动不动")。
  看得见的晃动 = 阵风峰值与平时弯角之差,硬截断 `min(θmax, θmax·x)` 一旦让**两者双双顶到天花板**,
  差恒为 0 —— 树被压死在最大弯角上一动不动,风越大越死,而且是精确的 0。
  实测(跑马梁,阵风顶峰 1.8 倍):旧式灌丛在风速 ×2 归零、松树 ×3 归零;换成 θ = θmax·x/(1+x) 后
  灌丛 ×2 还有 4.8°、×8 还有 0.6°,松树 ×2 峰值 5.7°、×8 还有 1.5°。小风下两者一致(x ≪ 1 时 x/(1+x) ≈ x),
  所以常规风力的手感不变;默认风下摆幅本来就顶着底板补带的封顶,画面上看不出差别。
  同一条也适用于叶片颤动的幅度(用 U/(U_b+U),不用 `min(1, U/U_b)`)。
  `swayBendAngle` 是纯函数,`backgroundSway.test.ts` 钉着"强风里摆幅只变小、绝不归零"。
- **🔴 原画没有风**(制作人 2026-09-13,原话:"原画没有风!原画没有风!原画没有风!")。原画里的草木就是
  **无风时的样子**;画面上画的是**此刻的真实弯角**,从原画姿态算起:风往左吹就往左斜,风一直在就一直斜着,
  阵风来了多斜、过去了靠弹性往回弹(弹性回弹最多过直立一点点,跑马梁松树 0.4% 的时间、约 0.9 像素)。
  **不许减掉任何"平均风弯角",不许给原画设"风力"参数。**
  - 来历(别再犯):2026-09-11 第一版为了让位移小、塞进 12 像素的补带,**编了**一句"原画画的是平均风下的姿态"、
    只画「此刻弯角 − 平均风弯角」。原画里没有风,这是拿技术限制伪装成物理假定。它先后造成:风速调大树反而
    一动不动(09-12,峰值与平均一起顶到天花板相减为 0)、纸钱往左飞树往右倒(09-13,风弱于平均的时间占大半,
    树 59%、草 54% 的时间被画在逆风侧)。09-13 第一次修又加了个 `swayRest = 0.7`("原画是几成风吹成的")
    ——还是同一个编造,换了个数,当天被制作人打回并整个删掉。
  - 真正要解决的只有补带宽度(见上一条"位移软封顶")。
  - 跑马梁实测(页面里同步逐帧调真实的 `update`,新烘焙 补带 48):风往左 松树梢平均 −10.5 像素、
    90% 时间在 −19.7 ~ −4.6 之间、往右 0.3% 的时间;风往右完全镜像 +10.5;所有草丛逆风 0%。
  - `backgroundSwayWindDirection.test.ts` 造一个**真的** `SwayBackground`(只把 `Shader` / `Mesh` 两个渲染对象
    换空壳——`Shader.from` 在无 DOM 的测试环境要 `document`)跑 4 分钟 `update`,钉:风往左树梢 95% 以上时间
    在左、风往右在右、左右镜像、几乎无风时位移 < 0.1 像素(原画就是静止的样子)。变异验过:整株、逐顶点两处
    **各自**塞回"减平均弯角"都会红。⚠ 别退回"照着 `stepInstance` 抄一份公式去模拟"——只保护函数、
    不保护调用处(validator 2026-09-13 指出)。
  - ⚠ 取证坑:**浏览器面板隐藏时别用定时器采样量摆动**(见 [[pixi-v8-traps]] 的隐藏标签页那条)——帧被节流,
    振子追不上目标,量出来是假的(这次先报出过一张"平均偏逆风 8.3 px / 87% 时间逆风"的表,就是这么量歪的)。
    要么面板可见用 rAF,要么在页面里同步逐帧调 `SwayBackground.update(w, t)`(不受可见性影响)。
- **🔴 大植物不许被扭成波浪:波浪尺寸 / 整体摆 / 锚点**(制作人 2026-09-13:"有一些植物看着很大,就应该整体一起扭,
  而不是植物都被扭成波浪了""刚体要可以我自己定锚点,不然有的你就是乱在旋转")。
  - **波浪尺寸** `wind.waveSize`(wu,缺省 **20**,F2「波浪尺寸」):同一株上相距小于它的点一起动。按**株内相对位置**
    起作用——每个点先朝本株的根收拢 `20 / waveSize` 倍,再去取湍流相位**和阵风**;株与株之间根不同,风扫过草坡的先后照旧。
    ⚠ 只放大湍流的空间尺度不够:阵风是沿风向扫过去的,一株沿风向铺开 600 wu,阵风到两头差 1.5 s,照样一截先弯一截后弯
    (测试抓到过,相关系数 −0.19)。⚠ 缺省是 20 不是 180:逐点相位三项正弦叠起来斜率约 0.19 rad/wu,相距二十来 wu
    节奏就错开,数字要说真话。崖墓入口最大那片(两点相距 736 wu)实测相关:20 → −0.13、200 → 0.78、2000 → 0.998。
  - **整体摆** `instances[].coherent`(草木工作台点株切换):整株收拢到零,所有点按根的位置取节奏,只按离根远近决定弯多少。
  - **锚点** `instances[].anchors`(场景 wu,草木工作台点):刚体部分(`plant` 整株与场里的刚体像素)绕**离它最近的锚点**
    转,一丛竹子可以每根竿一个;没点就绕自动分割的根。逐顶点支点 `vPivot` 在构造时算好,纸钱 `offsetAt` 同一个支点。
    有锚点的株烘焙时按"像素到最近锚点"的最远距离重算 `reach`(刚体转角封顶按它压)。
  - 作者输入 `sway_overrides.json`(主背景烘焙目录,**存原画像素位置不存实例 id**——id 每次重烘都会变),烘焙时
    `apply_overrides` 按位置落到这一次分割出来的株上;点在轮廓外 24 px 内往外找最近一株,再远就报"没有任何一株"。
    不进发行包(`never_extract`),与涂层一起保存、覆盖前留历史(`overrides-*.json`)。
  - 叶片细抖 `wind.leaf.size`(wu,缺省 22)/ `wind.leaf.speed`(Hz,缺省 3.2),F2「叶抖大小 / 叶抖速度」。
  - `backgroundSwayCoherence.test.ts`(真 `SwayBackground`)钉:缺省下相距 600 wu 两点相关 < 0.9、波浪尺寸 6000 时 > 0.98、
    整体摆 > 0.999、锚点处钉住;变异验过(整体摆失效 / 锚点改回绕根,各自会红)。
- 摆动的两个植物常数(`SWAY_U_BEND`、`SWAY_THETA_MAX`)是**经验参数**:物理含义是"1 m 植株弯到一半
  最大弯角的风速"与"顺风收拢后的**渐近**最大弯角",推导不出来(没有逐株刚度数据),改它们要按这个含义改。
  摆幅在 U ≈ U_b 附近最大,再大就被"顺风收拢"压下去——这是真实的(被压平的草确实不怎么动),
  但**不许压到零**。

## 怎么验证

- **预算:整套风(草木 + 纸钱)≤ 2 ms/帧**(制作人 2026-09-12)。F2「粒子」页直接显示两笔账:
  粒子的「模拟 x.xx ms/帧」与草木的「x.xx ms/帧(n 株 / m 顶点)」——调参数时看得见账单。
  2026-09-12 跑马梁(520 张纸 / 29 株 / 4.4k 顶点)空载实测:摆动 0.35、薄片模拟 0.2、顶点填充 0.48,
  加上实体层与提交 ≈ 1.6 ms;做完下面三条后 ≈ 0.9 ms。**量的时候先看基线**(把粒子与摆动都关掉的那一帧):
  机器上有别的活时整帧会整体涨三四倍,只有基线能把倍率除掉。
  三条口子,按性价比排:
  - **热路径的正弦走查表**(`fastCos` / `fastSin`,2048 格 + 线性插值,误差 < 1e-6)。`sampleSceneWind`
    每帧被逐粒逐子步调上千次,全走 `Math.cos` 时一次 ≈ 1 µs;查表后涡的部分只剩三分之一。
  - **视口剔除**(`VfxRenderer.refreshCull`):常驻效果铺满整张场景图,屏外的粒子不必逐顶点投影。
    跑马梁只省 9%(纸基本都在屏内),但场景越大越值——这是**成本随屏幕、不随场景大小涨**的那条线。
  - **薄片段数按屏幕尺寸定**:纸钱在屏上只有 10–30 px,`plate.segments` 从 4 降到 2(顶点 10 → 6)
    肉眼无差、填充少 20%。**别照着"弯曲要平滑"去加段数**,先看它在屏幕上到底几个像素。
  ⚠ 睡着的片**照样每帧重算顶点**:贴地的纸在风里会颤(`bend` 逐帧变),所以缓存不掉——
  实测 520 张里 473 张属于这种。想省这一笔只能降段数 / 降数量 / 隔帧刷新,不是加缓存。
- 调强度:游戏里 F2「粒子」页有风速倍率 / 粒子增益 / **湍流强度** / 草木增益四根滑条
  (临时覆盖、不落盘,读数抄回场景 JSON 的 `speed` / `gain` / `turbulence.intensity`)。
- 真机:`?mode=dev&devScene=跑马梁`,页内读 `window.__game.sceneWind`(参数 / 钟)、`swayBackground`(有没有换上)、
  `vfxSystem.debugSnapshot()`;薄片状态在实例的 `sim.emitters[i].plate.arr`(sleep / contact / hold)。
- 风力响应(2026-09-12 跑马梁实测,场景 wu,×0.68 ≈ 屏幕像素):**风速**推到 ×2 以后草木基本不再变化
