# 游戏运行时开发规范

> 适用于所有 `src/` 改动。只收跨架构演进仍成立的不变量、过程义务、验收门与红线;
> 架构、清单、字段、步骤序以代码与 `docs/游戏架构设计文档.md` 为权威源,不在此复述。

## 一、不变量(性质约束,违反即 bug,与具体实现无关)

1. **单一所有者**:一份运行时状态只有一个写入者;模态状态(面板可见性、游戏状态、返回栈)
   必须由同一个控制器原子管理,不允许 UI 与系统各改一半。
2. **失败不得伪装成功**:操作失败后,依赖其成功的后续写入(标记、任务进度、成功提示)
   不得发生——要么让失败可观测,要么补偿回滚。关键进度物不得因普通容量或资源限制被静默丢弃。
3. **异步必须封口**:每个 Promise 最终必须 resolve 或 reject,禁止永久悬挂;声明了顺序的
   动作批,处理器必须返回覆盖真实完成时间的 Promise,禁止 fire-and-forget 后立即报完成。
4. **旧时间线不写新状态**:读档、切场景、换会话、销毁之后,旧任务的写入必须被丢弃或隔离
   (手段不限,性质必须成立)。
5. **生命周期对称**:destroy 不留残留(监听、定时器、RAF、资源、在途任务);
   destroy 后再 init,行为与首次启动一致。
6. **拒绝路径也要恢复**:任何 guard 拒绝、取消、异常分支,必须把玩家的可操作性恢复到
   进入该流程之前;只写 happy path 的流程不允许合入。
7. **构建期严于运行时**:数据错误尽量在编辑器与校验器侧 fail-closed;运行时对内容错误
   容错跳过,但 dev 下必须响(可见错误面),prod 下留痕。
8. **统一通道**:游戏行为经统一动作执行器;条件经统一求值器与唯一上下文工厂,禁止任何
   模块手工拼装缩水版上下文;运行时布尔/数值状态以统一存储为唯一真相源。
9. **登记面同步**:一个能力涉及的全部登记面(运行时注册、编辑器清单、校验器、参数往返
   保真登记)必须在同一次改动内改齐;权威清单在代码,以对账测试与校验器为准。
10. **资源有主**:每份资源(贴图、音频、缓存、监听)有明确所有者,所有者销毁时释放;
    清理完成后才结束的在途加载,其产物不得写回缓存。
11. **分层与解耦**:依赖只能自上而下(UI→系统→渲染→核心→数据),唯一例外是组装层;
    同层系统默认只经事件总线 / 状态存储通信,不互持引用(既有受控例外不得再新增);
    依赖经构造函数注入,禁全局单例与跨模块直接 import 其它系统实例;系统实现统一生命周期接口。
12. **数据驱动**:内容(物件名、规矩名、NPC、任务 id、对话文本)一律走数据文件,代码不硬编码。

> **已知违反者(不是新不变量,是一处埋着的坑)**——律 8 的"唯一上下文工厂":
> 条件求值模块**自己导出的那个便捷全量包装**就地拼了一个缩水上下文,用它求值时若干类条件叶
> **静默失效**(取不到的那些一律按缺省/恒假,没有任何红字)。求条件一律走游戏侧的上下文工厂
> 再逐条求值。这是"违反者就在权威文件里"的活例:看见它被导出别当它是正路。
>
> 同一族里最难查的是**依赖注入式的叶子**(姿态、时段、位面这类靠上下文喂 getter 的):
> 没注入时它们**退化成恒假/恒缺省,且连一句告警都没有**——不像未知动作、未知运算符至少
> 在开发运行时会响。症状是"条件莫名不满足",查的人会先去怀疑数据。

> **已知违反者(律 11 分层解耦)**:通用工具层里有一处真的在运行时依赖上层
> (其余跨层引用都只是类型引用、编译期就没了)。**别照着它抄**;判一处跨层引用要不要管,
> 就看它编译后还在不在。

## 二、过程义务(指路牌,不是地图)

1. **改前先读,只读相关**:先读该机制的架构文档章节、权威源代码与本库对应卡片。
2. **扩展走既定流程**:新增能力原语(动作、参数、条件叶子等)走项目既定扩展流程,
   完成后报告改了哪些登记面。
3. **拿不准就停**:无法在不违反不变量的前提下实现时,停下报告,不得绕过机制糊弄。
4. **行为改动真机验证**:验到"看见行为正确"为止,不以"编译过 + 测试绿"为完成标准。
5. **偏差记录义务**:发现现实与本库文档打架或超出时,收尾往 `agent_docs/_meta/inbox/`
   写一条三行偏差记录(零门槛,不需审批)。这是库内实践类知识唯一的保鲜来源。

## 三、验收门(每次运行时合入,机械执行)

- `npx tsc --noEmit` 零错误;
- `npm test` 全绿(仅当前工作区,不含隐藏 worktree);
- `./dev.sh validate-data` 零 error,且警告数不增加;
- 素材引用审计零问题;
- `git diff --check` 干净。

## 四、审批红线(出现任一,拒绝合入)

- 玩家输入或 UI 状态可能永久锁死;
- 恢复后的状态可能被旧时间线覆盖;
- 关键道具、货币或进度可能失败却继续推进;
- 存在可能永久悬挂的 Promise;
- 新增系统缺完整销毁逻辑;
- 登记面(运行时/编辑器/校验器)未同步;
- 新增 validate-data error,或使警告数上升。

## 附:已确认的默认决策(2026-07-11,勿再问)

- **未知动作**:构建期 fail-closed;运行时 dev 响、prod 跳过留痕(不采用 prod fail-closed)。
- **关键给予**:关键进度物绕过普通容量限制(见 [inventory-capacity-critical](mechanisms/inventory-capacity-critical.md))。
- **警告棘轮**:合入不得新增严格校验警告;存量白名单/清偿另立项,落地前不启用 strict 硬门禁。
