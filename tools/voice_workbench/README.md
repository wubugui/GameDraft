# 配音工作台

原始录音 → 切成一句一条 → 降噪 → 响度对齐 → 批量导出产物。

```bash
sh scripts/py.sh -m tools.voice_workbench
```

首次使用先装依赖：

```bash
.tools/venv/Scripts/python.exe -m pip install -r tools/voice_workbench/requirements.txt
```

## 三个地方，别搞混

| | 位置 | 性质 |
|---|---|---|
| **源库** | `resources/audio_sources/` | 原始录音。**不可再生**，只增不改，不进 public，不进 Git |
| **工程** | `tools/voice_workbench/projects/*.json` | 切点与参数。纯描述，不含音频，删了重切即可 |
| **产物** | `public/resources/runtime/audio/voice/` | **唯一进游戏的东西**。可随时重新导出覆盖 |

游戏永远只用产物。源库里的文件不参与游戏、不被工具改写；工具对源库只做两件事：拷进来、读出来。

## 与 `tools/audio_editor` 的分工

- **本工作台是 source-centric**：管"从不可再生的原始录音，做出干净、音量对齐的资产"。它不认识 `audio_config.json` 里的 key。
- **`tools/audio_editor` 是 key-centric**：管"把某个成品挂到已有的 audio key 上"。它不管素材怎么来的。

链路：原始录音 →〔本工作台〕→ 产物 wav →〔audio_editor〕→ 挂到 key。
两边都不越界：本工作台**永不写 `audio_config.json`**，audio_editor 永不碰源库。

## 一次典型的活

1. **导入**：`源库 → 导入音频…`，选手机拷出来的 WAV。原文件原地不动，工作台只拷一份进库。
   同一份文件重复导入不会产生副本（按 sha256 认身份）；同名不同内容会自动改名，**绝不覆盖**。
2. **切**：左边选一条源 → 调「静音门限 / 最短静音」→ `自动切分`。
   自动切分只是**起点建议**：停顿短的两句会连在一起，在波形上拖区间边界补刀，或 `加一段`。
3. **标底噪**（强烈建议）：把录音开头那 10 秒空房间切成一条，选中它按 `设为底噪样本`，
   然后取消它的「出」勾选。降噪有了真样本比让算法自己猜准得多。
4. **命名**：表格里双击改名，或 `批量命名…` 按「前缀_序号」一次改完。产物文件名就是这个名字。
5. **听**：选中一条，`试听原始` / `试听处理后` 对比。右边会显示这条量到多少 LUFS、加了多少增益。
6. **导出**：设好响度目标（默认 -20 LUFS）→ `批量导出`。报告里逐条列出量到多少、加了多少、
   有没有被真峰上限拦住。

## 几个不显然的设计

- **响度按 LUFS 不按峰值**。峰值一样 ≠ 听感一样响——本项目那批说书配音峰值齐刷刷 -4.8 dBFS，
  LUFS 却差 2.87 LU。对齐靠的是 LUFS。
- **单声道按双声道计**。游戏里单声道素材是两只喇叭同时出声，按单声道测会低 3 LU，
  于是单声道产物比立体声产物响 3 dB——一批素材混着两种格式就永远对不齐。
- **只做增益，不做压缩**。一条录得太动态的素材靠拉增益是对不齐的，那是压缩器的活。
  这里宁可让真峰上限把增益压回来并**如实报出差了多少**（那条八成该重录），也不偷偷改表演。
- **默认不覆盖已有产物**。导出目录在 public 下，里面可能有正在用的资产。
- **只吃 WAV/FLAC/AIFF**，不收 m4a/mp3。手机默认录 m4a，请换能录 WAV 的 app——
  把有损文件转成 wav 只是把损失固化。

## 录音端的几条要求

（决定了这个工具能救回多少，按性价比排序）

1. 被子/衣柜围一圈吸掉反射，比换麦克风管用得多
2. 手机**放稳**（别手持，手持的低频轰隆很难救），嘴到麦固定 20cm，偏轴 30° 别正吹
3. **每次开录先录 10 秒空房间底噪** + 一句固定参考句
4. 峰值瞄 -12 ~ -6 dBFS，宁小勿爆（削顶是唯一救不回来的错误）
5. 同一个角色的台词尽量一次录完；换角色只换表演，不换位置和距离

## 测试

```bash
.tools/venv/Scripts/python.exe -m pytest tools/voice_workbench/tests -q
```

响度那几条拿 EBU Tech 3341 的合规信号钉死（1kHz 正弦的读数必须等于它的 dBFS 电平，
容差 ±0.1 LU）——这是整条链唯一有标准答案的部分，它错了后面全错，
而且错得没有任何提示：所有产物一致地偏 X dB，听起来只是"有点小"。
