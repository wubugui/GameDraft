# 角色照明实验室(伪世界 RT / irradiance cache)

单张场景背景图 → 全自动深度 → 免锚点免平面标定 → 补全伪世界几何 → 角色照明。
实现对应推导文档《伪世界角色照明:从精确辐射传输到全部近似》(A1–A9)。
位置:`tools/character_lighting_lab/`(2026-07-21 自实验目录转正;`out/` 数据不入库)。

## 用法

```bash
./dev.sh char-lighting                      # 开**独立窗口**(缺省)
./dev.sh char-lighting -- --serve           # 只起 HTTP 服务,在真浏览器里调页面/开 devtools
./dev.sh char-lighting -- --serve --port 5311 --no-open
```

**它是个本地窗口程序**(2026-08-31),不是网页工具:双击即开、关窗即退、
**端口由系统分配**(不会冲突、也不用你关心)、**禁止双开**(第二次启动把已有窗口
提到前台就退出)。壳在 `tools/desktop_shell.py`,与场景重打光工作台共用一份。

★ **不留残留**:HTTP 服务跑在 daemon 线程里随进程消失;烘焙那个 3 分钟的子进程
(以及自动装 torch 的子进程)走 `tools/child_jobs.py` 的 Windows Job Object ——
**父进程无论怎么死,内核都会杀光整棵进程树**。关窗口不会留下一个还在写产物的
`pipeline.py`(那会导致下次重烘时两个进程并发写同一批产物且都合法)。

**场景清单直接扫工程,不选文件**(2026-07-23 改):顶部下拉列出
`public/assets/scenes/*.json` 里的**全部**游戏场景,每项带状态——
`○未烘焙 / ✓已烘焙 / ✓已导出 / ⚠背景已变 / ⚠缺背景 / ⚠孤儿`,下面一行显示
背景图名与导出情况。**场景身份只认游戏场景 id**,四个落点全由它推出:

```
场景 id ─┬─ 背景图     public/resources/runtime/scenes/<id>/<backgrounds[0].image>
         ├─ 烘焙工作目录 tools/character_lighting_lab/out/<id>/<背景基名>/
         ├─ 导出照明   public/resources/runtime/scenes/<id>/lighting/<背景基名>/
         └─ 导出深度   public/assets/scenes/<id>.json(+ 同场景运行时目录)
```

**烘焙全部在软件内完成**(①重建区,异步任务队列 + 实时日志,可排队可离开页面):

- 下拉选中**没烘过**的场景 → 橙色按钮变「⤓ 首次烘焙此场景(自动取游戏背景)」,
  点它就跑完整管线(深度→标定→mesh→体素→SAM门控→probe→碰撞),完成自动加载;
- 下拉选中**烘过**的 → 「⟳ 应用上面参数:重建几何+重烘光照」;
- **⟳ 重烘全部已烘场景**:按各场景已保存参数逐个排队重烘。
- 重烘/首烘都会**先从工程重取背景**(按字节拷贝),游戏里重画过就自动跟上;
  因此 `manifest.hash == 游戏背景 sha1`,与导出的 `background_sha1` 门天然对齐。
- 导出/几何编辑有闸门:下拉选的场景与画面上加载的不是同一个时拒绝执行
  (防"选了 A 却导出了 B")。

**两个导出按钮分工不同**(别混用):

| 按钮 | 干什么 | 何时用 |
|---|---|---|
| **⇪ 导出照明** | 重新产出 probe 数据(固化 E 图集 L1/L2/BIN)+ 地面场 + 标定 + 哈希门,连当前着色参数一并写 | 烘完要进游戏、或改了 `nee`/`amb`/`miss_mode` |
| **💾 只存着色参数** | 只补 `lighting.json` 的 `shading` 块,**不动 probe 图集**,秒存 | 只调了 β / eChroma / bulge / flatten / mode / RT 那组 |

`nee`/`amb`/`miss_mode` 是 v3 固化 E 的 **compose 输入**(已烤进图集),所以「只存参数」
会拒绝这三个的改动并提示改走「导出照明」——避免写出「json 声称的值 ≠ 图集实际按其
固化的值」的自相矛盾载荷。同理它也拒绝**没导出过**和**旧版 v2** 的场景(后者运行时本就
禁用,补参数救不回来,必须重导出)。

⚠ **已废除「＋新场景入库…」上传按钮**(及 `POST /api/build_new`):它按**上传文件名**
定场景名,真踩过——选了 `teahouse/background.png`,烘出一个叫 `background` 的场景,
照明导进 `runtime/scenes/background/` 这个不存在的场景,teahouse 反而没拿到照明。
背景图还没进游戏的场景,先在主编辑器建场景 + 放背景,再来这里烘。

CLI 仅作脚本化备用:`./dev.sh char-lighting -- --build <图.png> --name 名字 [参数…]`
(CLI 不做 id 校验,自己保证 `--name` = 游戏场景 id)。

## 四个照明模式

| 模式 | 实现 | 对应近似 |
|---|---|---|
| RT  | 逐片元 cosine 半球采样,体素网格内步进,miss→镜像查 J̄ | ref 路径,(8)+(14) |
| L1  | probe 三线性 + 4 系数球谐辐照度 | A9 一阶 |
| L2  | probe 三线性 + 9 系数球谐辐照度 | A9 二阶(≈无损,Ramamoorthi) |
| BIN | probe 三线性 + octahedral 8×8 法线 bin 辐照度(无球谐截断) | A9 纯数据 |

实测四模式收敛:temple 烛边 RT 5.5 / L1 4.6 / L2 5.5 / BIN 5.4(8bit luma)。

## 管线阶段(pipeline.py)

1. **深度**:Depth Anything base(项目 .tools venv),按图内容哈希缓存。
2. **标定(免平面/免锚点)**:视差仿射模型 d=1/(a·raw+b),粗细网格搜索
   最小化地面掩码上的鲁棒 |∇Y|²("地面平均尽量水平",真实起伏保留);
   地面掩码 = 朝上表面 ∩ 洪泛连通画面底边,迭代 2 轮;o 使地面中位高=0。
3. **地面场**:地面高度 Y_g Laplace 延拓全图 → 非平面行走面 d_walk(角色脚吸附)。
4. **补全**:灰度闭运算找凸出物 + 组件厚度充气;背景层深度/颜色扩散 inpaint;
   行走面之后沿射线填实(地下);→ 占据+辐射体素(192×h×64, RGBA16F, a=占据)。
5. **辐射**:HDR 统一模型(零手调:双尺度 log 亮度残差 + 白天闸门 + 发光体置信度)。
6. **J̄ 闭合**:3 个自由点全球面 gather,命中归一化,radiance SH L2;miss 镜像查询。
7. **probe**:18×10×8 网格,实心内 probe 无条件吸附最近自由体素(EDT),
   196 Fibonacci 方向 gather → 同时产 L1 / L2 / bins 三种 cache。
8. **可走/碰撞**:地面掩码 − 膨胀的凸出物脚印,PNG 输出,查看器洪泛取最大连通域出生。

产物在 `out/<场景>/<背景基名>/`:manifest.json、volume.bin、probes_*.bin、
front_depth.bin、walk_depth.bin、walkable.png、audit.png(标定/分层/体素审计图)。

⚠ **背景是烘焙的一等参数**(2026-08-30):同一场景的白天/夜晚两张背景各有一个
工作目录,基名与导出照明目录同一口径(`pipeline._bake_key`)。谁都别再自己拼
`out/<场景>/` —— serve 这侧曾经漏跟这一层,后果是清单里每个场景都显示未烘焙、
点下去画布空白、笔刷编辑存进没人读的目录(2026-09-08 修,契约锁在
`tests/test_lab_server_contract.py`)。`out/<场景>/<背景图名>` 那张平铺的图是
**烘焙输入**(游戏背景的字节副本),不是产物。

## 已知边界

- 角色显示亮度是严格物理(A1:立绘=albedo),暗场景角色就是暗;曝光 β 是设计旋钮。

- 遮挡判定用可见壳深度(front_depth),角色只与第一层皮比较。
- 体素分辨率下薄结构(细栏杆)会变粗;occluder 厚度是启发式。
- 本工具全部文件在实验目录内,未触碰项目本体。

## miss 闭包控制(运行时旋钮,不用 rebake)

probe 烘焙把每份 cache 拆成三件套存储:E_hit(命中贡献)/ E_amb(miss 方向的 J̄ 贡献)
/ cov(余弦加权命中覆盖率)。运行时:

- **miss环境强度** s:E = E_hit + s·E_amb(s=0 即 miss=黑,严格模式);
- **miss不计入**:E = E_hit / cov(hitnorm 归一化);
- RT 模式同两策略逐射线执行。

注意:**折叠开着时 miss 集合≈空,这些旋钮天然无效**(洞已被折叠填上,是特性不是 bug)。
要看闭包差异:重建区取消「烘焙折叠」重烘(~10s),此时朝相机半球全是 miss,
四个模式的旋钮全部生效(实测 temple:s=0→0.4,s=1→2.5,s=2→4.4,归一→1.5,
且 RT≈L2≈BIN)。当前 temple 为无折叠烘焙(旋钮可玩),雾津街头为折叠烘焙(推荐画质)。

## 3D 检视:mesh 与手性

- 世界矩阵 M 第三行取反(det=−1 正交阵):q 空间(x右/y上/z朝里)是左手系,
  纯旋转会把左手性带进世界,GL 右手相机里必然镜像。取反后世界为右手系,
  转置=逆与等距性均保留;方向键映射同步翻转。已数值验证:画面左点→3D 屏幕左。
- 重建导出真三角 mesh(mesh_verts/mesh_idx,~7-9 万三角形):可见壳/补全层/
  地面延拓三层共一套顶点布局(pos3f+rgb+tag),深度跳变 >0.55q 的三角形被丢弃,
  形成的洞=未观测区域的诚实表达。3D 页「网格」勾选切换 mesh/点云,层开关共用。

## probe 布点修复:射线-盒求交(2026-07-23,必须重烘才生效)

**病灶**:probe 盒是**世界轴对齐**的角色带,体素盒(伪世界)却是 **q 轴对齐**的画面盒
(x/y = 画面范围,z = 深度范围)。世界里"地面往上 1.5m"对**远处**地面来说落在
`q.y > qy_max`,也就是**画面上沿以外**——实测 44~83% 的角色站位如此。老写法:
起点在体素盒外的射线一步就出界 → 该 probe 全程 miss → `valid=0` 被判废。后果两条:

- **一半 probe 是废的**(实测 valid 只有 43~59%),竖直方向 6 层里最上面 1~2 层恒为 0;
- 更要命的是**角色采样点整个失效**:8 个角全废时着色器只能退回全局环境 `ambIrr`
  (实测远端角色 h=1.4m 处有效插值权重 **0**),角色从近走到远,上半身会从局部光照
  "啪"一下掉成全局环境。

**修法**(`_ray_box_enter` / GLSL `boxEnter`,烘焙与两个着色器同式):
射线起点允许在盒外,先用 slab 求交推进到**盒入口**再步进。盒外是**未观测的空气**
(closure 本来就用 J̄ 兜 miss),射线理应能从那儿飞进来打到下面的几何——这与"把体素盒
往上垫一层空体素"数学等价,但**不花一分内存**。配套:

- `valid` 恒为 1(载荷格式不变),着色器不再丢角、不再突然掉回全局环境;
- 实心 EDT 吸附只对**盒内** probe 做(盒外原点是合法的,别拿盒面的实心把它拽回来);
- `_visible_to` 的 NEE 阴影 march 同理:盒外采样点不算遮挡(老写法 clip 到盒面会误判);
## probe 盒高度 = 人的活动高度(2026-07-23 第二轮,用户纠正)

第一轮只把带高从 2.6 收到 2.2,**还是烘到天上去了**:实测三个户外场景的重建世界
最高点只有 1.0~1.5,而盒顶在 2.45~3.0——**最上面 2~3 层整个悬在世界之上**,占掉一半
竖直跨度。规则改成:

```
y0 = 最低地面(P2) − 0.15
y1 = 中位地面 + probe_band     ← probe_band 现在的语义 = **角色最大活动高度**(默认 1.6 ≈ 身高1.5+余量)
     (地面起伏大时用 P98+0.3 兜底;再套常识上界"不超过世界最高点 3m")
```

**为什么是"贴着头顶"而不是"顶到世界最高点"**:拿射线真值做过数值实验(bridge,6 层,
比对角色身上 0.1~1.55m):

| 盒顶 | 层距 | 平均误差 | 头部误差 |
|---|---|---|---|
| 1.10(顶到世界最高点) | 0.28 | 13.0% | 17.4%(头顶被钳) |
| **1.35 ~ 1.60(贴头顶)** | 0.33~0.38 | **8.4~8.5%** | 8.5~10.5% |
| 2.05 | 0.47 | 11.0% | 13.4% |
| 2.45(上一轮) | 0.55 | 12.4% | 8.2% |
| 2.85(最初) | 0.63 | 11.1% | 11.6% |

E 在世界最高点之上**并不会变平**(每升 0.5m 还掉 15~25%,因为脚下几何的立体角一直在变),
所以顶到世界最高点会把头顶钳出偏亮;摊到 2.4~2.9 又把那 6 层稀释掉。**盒顶贴着人的
头顶时最准**——这就是"bake 范围要看人的活动最大高度"。

bridge 实测:盒 y[-0.28,2.85]→**[-0.28,1.61]**,层距 0.62→**0.38m**,全场 10650 个角色
采样点(可走区 × 5 个高度)**有效插值权重 100%、零退回全局环境**。

⚠ 角色更高/更矮(或场景世界尺度不同)就拖①区「角色活动高」滑杆,它就是盒顶。

**实测(bridge_underpass 同参对照)**:

| | 老 | 新 |
|---|---|---|
| probe valid | 43% | **100%** |
| 第 4/5 层(y≈2.2/2.85) | 命中率 0%、E=0(全废) | 盒已压到头顶,不再有这两层 |
| 远端角色 h=0.2/0.8/1.4 的有效插值权重 | 0.72 / 0.21 / **0(退回全局环境)** | **1 / 1 / 1** |
| 烘焙耗时 | 2.4s | 2.5s(probe 阶段) |

**验证**:⑥面板的"现场重追命中率 vs cache 存的 cov"八颗 probe 差 ≤1.2pp;RT 与 L2
在远/中/近三处角色位置逐像素平均差 ≤0.1/255(说明着色器 RT 路径与烘焙同步修好了)。

「导出照明」。`CharacterShadingFilter.ts` 的 RT 路径已同步(dev 模式对照用,prod 不跑 RT)。

## probe 全景 + 3D 角色 quad(2026-07-23)

漫游时把 probe 可视化**裹在相机周围**,直接看"我站这儿周围的光照长什么样"。

- **四种全景**(与⑥面板四张图同源同算法):`①E(n) / ②亮度分层 / ③射线命中 / ④命中辐射 L(ω)`。
  每个屏幕像素的视线方向(世界)经 `Mᵀ` 转回 q 再取值,所以**转头看到的方向就是世界方向**。
  全部在 GLSL 里算(不是 CPU),飞的时候实时;③④ 每像素一条射线,比 RT 模式的 64spp 还便宜。
- **`全景↔mesh` 滑杆**:0=全是全景,1=全是重建 mesh,中间按比例混。probe 点/角色 quad/
  射线这些"仪表"**始终画在最上层**,免得调到 0 就什么都定位不到。
- **`插值` 开关**:开=按游戏口径,周围 8 颗 probe 三线性(含 valid 权重 + 四分账合成,
  与 `CHAR_FS::probeE` 同式);关=只读**最近那一颗** probe 的原始数据,③④ 则改从那颗
  probe 的**实际采样点**打射线(看单颗 probe 的真面目,以及插值到底抹平了多少)。
  实现上是 `uProbeOne` 这个 uniform:>=0 时 probeE 跳过三线性直接解那一颗。
- **相机被钳时会标出来**:飞出 probe 盒(和游戏一样钳到边界层)时**屏幕四边描红 + HUD 提示**
  「显示的不是本位置真值」——不标的话你会拿边界层的值当真。
- **3D 里画角色 quad**:立在伪世界的直立四边形(与新的遮挡口径同一个 quad),
  逐像素走**与 2D 完全同一套着色**(albedo×E/π×β)。这样"周围全景"和"角色被照成什么样"
  能对着看,光照对不对一眼就知道。
- 全景**只在「漫游」相机下有效**(正交没有单一视点);点全景按钮会自动切到漫游。
  曝光复用⑥面板那根「可视化亮度」,不另加旋钮。
- ⚠⚠ **全景的 A7 折叠默认关,且与「RT折叠」独立**(2026-07-23 用户抓的:"360 全景里咋可能
  看到完全对称的东西")。折叠是**给 gather 用的闭合假设**——朝相机侧没数据,就镜像回观测
  半球再积分;拿它当"我周围长什么样"就会看到一个左右镜像的假世界。真相是那一侧**就是没
  数据(miss)**。实测(雾津,相机朝相机侧、q.z<0 占 100%):折叠开/关整帧差 77.5/255,
  折叠关时 50.9% 的屏幕是 miss 深蓝、折叠开时 miss 变 0%(全被镜像填满)。
  开关留着是为了看"烘焙到底吃进了什么"。⚠ **①② 去不掉折叠**——它已经烘进 SH/bin 系数,
  是 cache 的既成事实(也就是说角色在那儿收到的光本来就来自一个镜像世界,这是 A7 的设计)。
  ⚠ 排查这类问题**必须把相机转到 q.z<0 那一侧**:朝观测侧看时折叠几乎不触发
  (实测该视角只有 4% 的方向 q.z<0,整帧差 0.1/255),会误判成"没问题"。
- ⚠ 实现细节:②照明模式选 RT(0) 时 cache 没有对应基,全景 ①② 自动退 L2(同⑥面板规则);
  `probeE/gatherRT/ambRad/boxEnter` 那套已抽成 `LIGHT_FNS/LIGHT_UNIFORMS` 公共块,
  被 2D 角色 / 3D 角色 / 全景**三个程序共用**——同一份数学只写一遍,改一处三处同步。

## 3D 漫游相机 / probe 亮度 / ⑥probe 检视(2026-07-23)

- **3D 检视默认第一人称漫游**(④显示「3D 相机」可切回老的正交轨道):
  `WASD` 平移、`Q/E` 升降、`Shift` 加速、左键拖=原地转头、右键或 `Shift`+拖=平移、
  滚轮=沿视线进退、双击=复位机位。漫游用**透视**相机(视场角可调),轨道仍是**正交**
  (与游戏的正交伪世界对齐,看整体几何/比例时用它)。两模式共用 yaw/pitch,
  来回切**视线方向与眼位不跳**(fly.pos ↔ orbit.eye 互推)。位置被限制在世界包围盒
  外扩一圈内,飞不丢。载入场景时按包围盒对角线给漫游速度一个起点。
- **probe 亮度(④显示)**:probe 点云**专属**显示增益,2D 绿点/3D 球同用,用来扫出
  probe 之间的相对明暗。它**不进任何物理量、不重烘、不导出,也不吃全局「预览亮度」**
  (刻意独立,读数才稳定)。点云顶点色改成**线性 E/π**(不再是预 gamma 的 u8+地板30),
  片元里才曝光+tonemap,所以滑一根滑条就能扫全动态范围;透视下点还会近大远小。
  载入场景按 P90 自动给一个能看出明暗的起点。**暗红点 = valid=0 的 probe**
  (格外/越界,不参与插值)——老版本被 u8 地板糊成灰点,现在一眼可见。
- **⑥ probe 检视面板**:勾「probe」后在 3D 里**点圆点**即选中(2D 里晶格投影太密,
  普通点击留给"点哪站哪",选 probe 用 **Alt/Shift+点**;选中的画洋红十字/环);
  拾取在屏幕距离相近的候选里取**离视点最近**的那颗,不会选到被挡住的。
  面板给四张经纬展开图(横轴一圈:中=朝相机 −z,左=−x,右=+x,两端=背向;
  纵轴 上→下):
  ① `irradiance cache E(n)` — 按所选基函数(跟随②模式 / L1 / L2 / BIN)重建,
     解码与四分账合成**逐行照抄 `CHAR_FS::probeE`**(含 NEE / miss 归一 / 环境强度
     三个运行时开关),所以看到的就是角色采到的;显示口径 E/π(白色朗伯的出射亮度)。
  ② `亮度分层` — 曝光后按 1 EV 分带上色 + 层界黑线,洋红=撞顶,用来判动态范围。
  ③④ `射线命中` / `命中辐射 L(ω)` — **现场重追**这颗 probe 的射线(与
     `pipeline._trace` 同参:0.9 体素步长/220 步/烘焙折叠),③ 色=命中距离、蓝=miss、
     交错纹=折叠命中,④ 是射线真看见的辐射(E 的被积函数;miss 处填 J̄ 环境)。
     3D/2D 里另画 96 条稀疏射线(黄=命中 橙=折叠命中 蓝=miss)。
  面板另给读数:格点/吸附距离/valid、DC 的 base|amb|emit|nee 四分账、展开图 EV 跨度、
  命中率/折叠比/最近·平均·最远命中距离。「可视化亮度」只作用于这四张图,与 probe 点云
  亮度、全局预览亮度三者互不干扰。
- ⚠ 折叠(A7)开着时 ③④ 左右两半会沿 ±x 轴对称——朝相机的方向被镜像回观测半球,
  是正确物理不是 bug(面板底部有同样的提示)。①② 不受影响(cache 存的是全法线域的 E)。
- ⚠ 面板/点云的解码只吃**已烘好的 .bin**,改任何几何/probe 参数仍要重烘才更新。

## NEE 直接光(发光体显式采样)

- **分账**:HDR 恢复天然可分 `全量 = base + emit`(emit=发光增量)。base 只走余弦
  半球(画=收敛解,间接光已含);emit 只走 NEE——增益图×深度提取发光 surfel
  (连通域聚类,大组细分,功率截断≤48),逐光源可见性追踪 + 解析投影。
  余弦射线命中发光体素只记 base——零重复计数,完美分割免 MIS。
- **烘焙四分账**:probe atlas 列布局 [base+cov | amb | emitray | nee],
  「NEE直接光」为纯运行时开关(RT 与三种 cache 同步语义,无需 rebake)。
  atlas 合并是因为 18 个独立采样器超 GL 上限 16。
- **发光体为各向同性 surfel**(无发光端余弦):火苗高度场法线朝相机,单面朗伯
  会把侧面贡献掐零;且射线路径的发光体素本就方向无关,两边必须同物理。
- **期望守恒**:开关 NEE 均值几乎不变是分账正确性的体现(无偏分割),NEE 买的是
  低方差与确定性;效果随 1/r² 集中在贴近光源的部位(脚边烛火照亮腿部)。
  要放大观感:重建区 HDR最大EV 拉到 4–5 重烘。
- 「光源」勾选:2D 橙十字(大小=功率)/3D 橙点,直接检视提取结果。

## 排错备忘(真踩过的)

- probes_*.bin 布局 (probe, coeff, rgb),纹理必须 width=coeff、height=probe。
- probes_valid.bin 存 0/255(R8 归一化);shader 阈值 step(0.002, v) 双兼容。
- GLSL ES 点精灵必须显式写 gl_PointSize,否则 ANGLE/Metal 复用陈旧值(全屏巨点)。
- 法线可视化颜色:朝相机 n.z=−1 → 蓝通道≈0(橄榄色),别当成 bug。
- 内嵌浏览器面板后台会节流 rAF——真浏览器前台无此问题(实测前台 34fps)。
