> 判据不是"字段出现没出现"，是**运行时读不读它** + v11 有没有构造承载。
> 表达不了的东西，先判"它是不是状态"；是状态才补语义，不是状态就该外移。
> 断言全部回读源码，行号见证据列。

规模：7 composition / 56 graph / 201 state / 150 transition / 123 signal。

**结论：不等价。三条真缺口（A/B/C），三条小项（D/E/F）。A 和 B 需要补领域分析。**

## 二、GAP-A｜被打断即作废（结构性表达不了）

**运行时**：活计图单激活槽。切走当前活计时按 `run.resumable` 二分——
`true` = 挂起存快照续玩；`false` = **删实例、进度归零、`aborted++`**（`:1154-1167`）。
挂起的活计**完全不参与扫描**（`:678-688`：只有 `activatedArchetype` 那一张进迭代面）。

**v11**：没有激活槽、没有挂起、没有作废。§5 限制 2「机器不能写另一台机器的状态」+ 限制 4「不提供遗忘/撤销/回滚」**主动禁止**了这件事。

**能不能宏展开消去？**
- 冻结（resumable=true）≈ 给 B 的每条转移加守卫 `when not(A 在进行中)` ⇒ 局部展开，**可消去**（代价是 Diffuseness + 漏一条就静默失效）。
- 作废（resumable=false）= 让 B 的进度归零 ⇒ **不可消去**。v11 里没有任何构造能从外部把一台机器打回起点。

**是不是状态？** 是。`activatedArchetype` 进存档；"我现在在干哪一单""上一单半路黄了"都是世界的记忆。

**判定：真缺口，需要补领域分析。** 要回答的问题不是"要不要加个 activate 构造"，而是：

> **一台机器的进度可不可以被外力清零？如果可以，是谁的权限？**
> 领域事实是有的：半路撂挑子，这单就黄了。但 v11 的记忆模型里没有"夭折"这个概念——
> 它只有"走完一轮"（done）和"还在走"。**夭折是第三种轮次结局，v11 漏了。**

现状用量：全项目只有 1 张活计图（`flow_背尸_淹尸活`，repeatable+resumable），`resumable:false` 分支零使用。
⇒ 缺口是**语义上的**，不是内容逼出来的。按方法论这仍然算数。

## 三、GAP-B｜出口只有"边"，没有"面"（种类错误）

三处现实用法，都是外部系统要读叙事状态的**值**（不是布尔）：

| 消费者 | 读什么 | 方式 | 证据 |
|---|---|---|---|
| `PlaneReconciler` | 当前该激活哪个位面 | 状态自带 `activePlane` 标签，**进入点名、离开自动取消**，多图点名取最后进入者 | `PlaneReconciler.ts:457,466,489` |
| 对话图 `ownerState` 节点 | 宿主机器现在停在哪一拍，据此分路 | pull | `GraphDialogueManager.ts:982-1026` |
| `QuestManager` 可重复任务面板 | 活计当前态 + 结算计数 | pull（`runInfoProvider`） | `Game.ts:1330` → `QuestManager.ts:422` |

**v11 §4.3 把 `activePlane` 判为"效果，走订阅"——这是种类错误。**
订阅效果由**边**触发，是一次性的；`activePlane` 是**面**的属性，在这一拍期间持续成立、离开自动失效。
**一次性动作表达不了持续标签。**

同一个洞的另一面：**`state.onExitActions`**（运行时支持，`:2094`；内容 0 使用）。
v11 的 `:` 只读"进入"的边，没有"离开"的边 ⇒ 写不出"离开这一拍时…"。

⇒ 两者合并成一句：**v11 的观察模型只有"进"没有"出"，因而表达不了区间性质（interval property）——"在 S 期间，P 成立"。**
`M.S` 在条件里正是这个区间，但它**只能被叙事自己读**；对外的唯一出口是边触发的一次性效果。

**是不是状态？** `activePlane` 是当前状态向量的纯函数——是**记忆的投影**。
§1 第三条职责白纸黑字写着"暴露状态供读取"，v11 却只提供了布尔谓词（`cond`）这一种读法。

**判定：真缺口，需要补领域分析。** 要回答的问题：

> **§1.1 的封闭性（出 = 只有订阅效果）是不是定窄了？**
> 现实里叙事对外有两种出口：①事件触发的一次性效果 ②状态的持续投影。
> v11 只承认①。②被迫改写成①就会丢掉"离开自动失效"和"跨机聚合"。

§1.1 是 v11 最新、最没验证过的一节，第一次拿去套现实就在这里崩。

## 四、GAP-C｜身份 vs 名字

数据里有 `migrations`（旧图名→新名、旧状态名→新名），说明**改名是真实发生过的事**，而存档里存的是名字。
v11 通篇用名字作地址，没有身份/名字之分 ⇒ 在 DSL 里改个名，玩家存档里的记忆就对不上。

**判定：语言层缺口（不是领域层），但必须解决。** 你早先已经拍过方向——"ID 不是 Int，是封装的类型"——v11 没有落这条。

## 五、小项

**D｜平级裁决未写明。** 运行时是 priority 降序、平级取声明序（`:1813-1818` 信号路径，`:1948-1953` reactive 路径）。
数据里 **`priority` 零使用** ⇒ 现有 150 条转移的确定性**全靠声明序**。v11 有 `priority` 但没写平级规则 ⇒ 形式语义待补。

**E｜`extern … emits [...]` 应默认推断。** 数据里 `meta.emits` 本就是扫描派生的缓存，不是人写的。
让作者在 DSL 里再声明一遍 = 双重维护（Viscosity + 隐藏依赖）。应改成：默认由编译器扫内容推断，`emits` 仅作可选断言用于核对。

**F｜非 run 图的 `exitStates` 有 2 张合成不出来。** 17 张里 15 张 == "无出边的终态"，可合成；
`scenario_码头官差套近乎`（`done` 仍有出边）和 `scenario_码头真相`（`revealed` 仍有出边）是作者显式标的。
影响面**仅 dev warp 边界**（`canRemoteEnterState` 只被 debug setState 与 planRemoteAdvance 调用，`:2277-2281`）。
⇒ 不是叙事语义缺口，是调试设施的标注会丢。
