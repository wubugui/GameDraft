## §1 系统是什么

### 1.0 这门语言的性质：**描述，不是操作**

> **它定义所有叙事图的结构与行为。一段程序就是那套叙事结构本身。**

没有执行顺序、没有"然后"、没有局部变量、没有命令。每一条语句都是一句**陈述**：
有这么一台机器、有这么一拍、从这一拍出发有这么一条边、这个谓词叫这个名字。

**读法要钉死**（`->` 极易被读成操作）：

> `on X -> Y` 读作「**从这一拍出发，有一条标着 X 的边通向 Y**」，
> **不是**「当 X 发生就去 Y」。

**三条推论：**

**① 这是最便宜的判据。**凡是操作性的构造，一眼否掉，不必再过①②。
（回看：`emit` 的否定我绕了"记忆无从宣称"一大圈，其实一句"它是操作"就够——见 4.1。）

**② 凡是叙事现在"去设置"的东西，都要翻成"别人来读"。**

| 现状：叙事去**设置** | 翻过来：别人来**读** |
|---|---|
| `state.activePlane = "背尸"` | `位面 背尸 when 淹尸活.背着`（4.3） |
| `setFlag(真相已揭)` | `flag 真相已揭 = 水鬼真相.已揭开`（4.17） |

4.3 我曾以为是位面的特殊问题，现在看它是本条的**通用推论**。

**③ 这是静态分析成立的前提，而静态分析是这门语言的全部回报。**
只要有一处是操作性的（动作体、变量、顺序），可达性 / 死锁 / 振荡就不再可判定。
**描述性不是风格选择，是"能不能把上万条网状叙事管住"的前提。**

**亲缘**：最近的是 **Statecharts / SCXML，去掉动作体之后的那一半**。
动作体正是 SCXML 里让整份文档不可分析的东西；本语言把它整块推到不透明句柄外面（2.8）。

---

**叙事系统是世界的记忆。**它持有状态、响应事件改变状态、暴露状态供读取。

### 1.1 语言是封闭的，但出口有推有拉

**入**：叙事只通过**信号**感知世界。
**出**：两种，缺一不可——

| 出口 | 是什么 | 触发者 |
|---|---|---|
| **推** | 订阅触发的效果 | 边（`M:S` / 信号） |
| **拉** | 外部读叙事状态 | 外部系统，随时 |

由"入"推出**外部系统的接口义务**：

> 凡是叙事需要知道的世界变化，**必须以信号告知**。
> 不声不响地变，是外部失职——不是叙事该去轮询补救。

### 1.2 机器恒在。没有实例，没有生死

一台机器不会在运行时被创建、销毁、复制。**"还没开始"不是机器不存在，是机器停在起点。**

⇒ 语言里**没有实例数量、没有实例 id、没有挂起、没有生命周期**（4.15）。

> 模板（2.14）不违反这条：模板是**编译期**展开，盖出的每一台都是独立的具体机器，
> 运行时不留任何模板痕迹。C++ 模板的模型，不是运行时对象。

### 1.3 有些叙事单元会发生多次 → 轮次，且轮次有多种结局

⇒ 机器可声明为**可重复**，且一轮要有明确终点。

> `repeatable` **不是**"可以有多份"（1.2 已排除），是"**这台机器的历史按轮记**"。

**一轮的结束不止一种。**半路撂挑子、过了时辰、要救的人死了——**结束了，但不是完成。**
⇒ 一台机器可有**多个**轮次终点，**每个是一种结局**，各自计数。

### 1.4 记忆有三层时间结构

| 层 | 是什么 | 谁写 | 一轮结束时 |
|---|---|---|---|
| **当前态** | 此刻停在哪一拍 | 转移 | 回起点 |
| **到达过** | 进入过的拍的集合（去重、单调只增） | 自动，作者不可写 | **清空** |
| **计数** | **按结局分别计**：某终点被走到过几次 | 自动，作者不可写 | 对应结局 **+1**，跨轮持久 |

三层都可读，**只有第一层可写**——而"写"也只由转移这条**声明出来的边**发生（1.0）。

## §2 领域层推导

### 2.1 状态需要容器 → `machine` / `state` / `initial`
必须有起点 ⇒ `initial` 显式（靠"第一个 state"是隐式依赖）。

### 2.2 一轮的结束必须显式标记，且结局不止一种 → `repeatable` / `done`

> **① 位置不承载轮次语义。**回到 `initial` 只说明当前态是 initial，不说明发生过什么。

| | 触发 | 计数 | 本轮历史 | 当前态 |
|---|---|---|---|---|
| `done` | 走到标了 done 的拍 | **该结局 +1** | **清空** | 回 initial |
| 普通转移 `-> initial` | 一条边 | 不变 | 不变 | 回 initial |

> **② `done` 可以标在多个拍上，每个是一种结局。**

"夭折"不需要新构造——走到另一个 `done` 即可，而且比"从外部抹掉进度"多给了一拍，
放下尸体、扣钱、掉声望有地方挂。

### 2.3 改变有两类成因，互不可归约 → `on` / `when`
**事件**是瞬时的**边**（来自外部）；**谓词**是持续的**面**（关于状态自身）。
可合取（`on X when C`），不可互相化约。

### 2.4 同时可用必须确定裁决 → `priority` + 声明序兜底
**裁决是全序**：`priority` 降序 → 平级取**声明序**。两级都写进语义定义
（现有 150 条转移一条都没用 `priority`，确定性今天完全由声明序承担）。

### 2.5 状态必须可读，**读出来的是值不是布尔**

| 读什么 | 得到 | 谁用 |
|---|---|---|
| 现在停在哪一拍 | **`State<M>`**（一个值） | 按当前拍分路的消费者 |
| 是不是在某一拍 | `Bool` | 守卫、条件 |
| 到达过某一拍没有 | `Bool` | `ever` |
| 某个结局走过几次 | `Int` | `count`（只接受 `Done<M>`，见 3.4） |

**只给布尔，外面要"按当前是哪一拍分路"就只能拼 n 个布尔测试，加一拍就静默漏掉。**
读出 `State<M>`，消费方才能穷尽分路，加一拍时所有分路点编译期报错。

⇒ 语言**不需要 `switch` 构造**：分路发生在内容侧（4.11）。
**语言只负责把读出口的类型给对**，穷尽性检查是消费方的事。

### 2.6 可观察的只有两种，都不需要许可 → `.` 与 `:`

| | 是什么 | 记号 | 用在 |
|---|---|---|---|
| **面** | 此刻正处于这一拍 | `M.S` | 条件（叙事自己读 / 外部拉） |
| **边** | 进入这一拍这件事发生了 | `M:S` | 转移 / 订阅 |

要求"观察前先声明" = 让被观察方因观察者的存在而改变自己，**耦合方向反了**。
⇒ **观察不需要被观察者授权**。

**只有"进"没有"出"是刻意的。**"离开 S 时…"等价于对 S 的每条出边写订阅——局部展开，
判据②不增加表达力。

### 2.7 机器之间只能这样连，而且是**读**不是**抄**
```
on A:某拍   -> ...     // 观察 A 的边
when A.某拍 -> ...     // 观察 A 的面（经 cond）
```
**没有第三种。**⚠ 不要造镜像其它机器状态的机器——冗余状态会不同步。要知道就去读。

### 2.8 效果需要挂载点，但效果不是记忆 → 订阅目标是不透明句柄

不透明**不等于**无类型：它是 `Effects` 类型的值（3.4），只是语言不看里面。
语言拥有的是**订阅关系**（一条陈述），不是效果本身（那是操作，在句柄外面）——这正是 1.0。

**同一条边上的多个订阅，按声明序执行。**

> 现状 `onEnterActions` 是挂在状态上的**有序数组**，顺序由作者写死。
> 翻成订阅后若不定序就是回归。按 2.4 已立的规矩顺下来即可：
> 顺序是**文本的性质、一次写死**，仍然是描述不是操作。

### 2.9 谓词需要具名 → `cond`（任意元数）

### 2.10 基数谓词表达不了 → `atLeast`

### 2.11 状态属于某物，"属于"要求唯一 → `bind (宿主, 维度)`
地址是 `(宿主, 维度)`，基数 ≤ 1；读取必须指名维度。
**维度不是自由字符串**，在宿主类型上声明（3.4）。
宿主 = 能被问"它现在什么状态"的东西；流程与系统不是 ⇒ 不写 bind。

### 2.12 同一种事件、不同主语 → 私有信号
扁平字母表放不下"一种事件、不同主语" ⇒ 需要一种事件，其**主语由发射方决定**。

> ⚠ v9–v13 从这条推出"机器类型不需要参数"——**已证伪，见 2.14**。
> 私有信号只覆盖**有宿主**的同构；**无宿主的同构流程**（多单任务，ownerType=flow）没有宿主可路由。

### 2.13 字母表必须可枚举 → `signal` 显式声明 + `extern`（emits 默认推断）
`extern` 同时是**外部内容的类型声明**（3.4）：`extern dialogue X` 让 `X` 成为 `Dialogue` 类型的值。

### 2.14 同一套流程反复出现，每次换几个具体对象 → 模板（编译期）

**领域事实**：任务、活计、可拾物这类叙事单元大量同构。没有抽象手段 ⇒ 复制粘贴 ⇒ 改一处要改 N 处。

模板是**编译期**的（1.2）：盖章展开成 N 台各自独立的具体机器。

**参数只有三种**：**信号**、**宿主**、**效果句柄**。
文案数值不是参数——它们是内容（4.11），跟着 quest / 对话桩走。

**模板内声明的信号，实例化时各成一份（卫生）。**
（现状靠 `{{taskId}}__accepted` 的前缀铁律维持，那是**手工卫生**；语言该由构造保证。）

### 3.3 `.` 与 `:`
```
cond 已经被赶过 = 听书.被赶出门      // 面：还停在这拍就一直为真
on   听书:被赶出门 -> 闲逛A          // 边：跨进去那一下成立一次
```

### 3.4 【语言层】类型

> **语言里拿到的状态从来不是字符串，就像 id 从来不是 int。**

| 类型 | 值从哪来 | 能做什么 |
|---|---|---|
| `Machine` | `machine` 声明 / 模板实例化 | 取当前态、取计数 |
| `State<M>` | `M` 的 `state` 声明 | `M.S` 判定 · `M:S` 观察边 · 比较 · **被读出来当值** |
| `Done<M> <: State<M>` | 标了 `done` 的 state | 额外可 `count` |
| `Signal`（`Private` 是其属性） | `signal` 声明 / 模板局部 | `on` 监听 · 模板参数 |
| `Effects` | `extern` 内容 / 效果句柄 | 订阅目标 · 模板参数 |
| `Host` | `npc(…)` `hotspot(…)` `zone(…)` … | `bind` 第一坐标 · 模板参数 |
| `Dimension<H>` | 在宿主类型上声明 | `bind` 第二坐标 · 读取时指名 |
| `Cond` | `cond` 声明 | 组合 · 守卫 |

**类型挡掉的四类错，字符串模型全挡不住：**

| 写错 | 字符串模型的后果 | 类型化后 |
|---|---|---|
| `count M.非done拍` | 运行期查表落空返回 0，**静默** | 编译不过 |
| `bind H.拼错的维度` | 凭空造一个永远读不到的维度 | 编译不过 |
| `M.不存在的拍` | 靠校验器事后扫 | 构造时就不成立 |
| 外面按当前拍分路，机器新增一拍 | 落到 default，**静默漏掉** | 消费方穷尽性检查报错 |

### 3.5 【语言层】id 与 label

**作者写的标识符就是 id。系统用的唯一标识也是它。没有第三样东西，没有隐藏映射。**

**唯一性**：机器 id、信号 id 全局唯一；状态 id 机器内唯一（地址是 `M.S`）。
**id 就该写成可读的**——它就是给人看的那个。

**改名 = 全项目级联重构，不是文本编辑。**一次改名必须把所有引用一并改掉
（机器 id、`ownerId`、派生信号前缀、条件与动作引用、`meta.reads/commands/emits`、quest `runArchetype`）。
项目里已实现（`signal_refactor.py`）；实测 `src/` 里零硬编码。
**够不着的引用面必须拒绝重构并报出位置**，不得静默跳过也不得只改内存。

**存档兼容不归本系统**（4.14）。

### 3.6 【语言层】`todo`：待接线（本版新增，来自 T2）

```
state 闲逛B { todo -> 去赌坊 }
```

**是什么**：一条**形状已定、触发未定**的边。编译得过、**恒不触发**、静态分析**单独归一类**
（"待接线 N 处"），不混进悬垂告警。

**为什么是语言层不是领域层**：判据①问"领域语义里有这一项吗"——**没有**。
"还没想好怎么触发"不是世界里的事，是**创作过程**的事。
判据②问"非宏可消去吗"——**可消去**，写个没人发的信号就是它。

⇒ **它要解决的不是表达力，是"说清楚这是故意的"。**
和 §5 那句「明确不提供，**非遗漏**」是同一个形状。

**现状**：项目里用魔法信号名 `__draft__`（运行时拒绝发射）担这个角色，
意图藏在字符串约定里而不在语言里。T2 实测：主线 `闲逛B → 去赌坊 → 背崖墓尸完成`
两条都是 `__draft__`，**主线实际在"闲逛B"之后就断了**——而这与"信号改名后遗留的悬垂发射端"
在静态分析里长得一模一样。

## §4 不在语言里

**4.1 没有 `emit`** —— **最短的理由：它是操作**（1.0）。
（更长的那条仍然成立：信号是事件，知道它发生的是让它发生的那一方；记忆无从宣称。）

**4.2 没有动作/效果内容** —— 记忆的职责是记，不是做；且动作体是操作（1.0）。

**4.3 没有位面点名** —— 方向反了：**规则读记忆**，不是记忆去点名规则。
⇒ `位面 背尸 when 淹尸活.背着 or 零工活.背着`（在位面那边写）。
条件天生是区间性的，不需要 set/unset 配对，也不需要"离开边"。
（附带：位面激活现有三个来源——叙事、过场 override、调试——现状散在两处，倒过来后全在位面系统一处。）
**这条是 1.0 推论②的第一个实例，不是位面的特殊问题。**

**4.4 没有组织标签** · **4.5 没有 `reactiveAll`/`reactiveAny`** · **4.6 没有 `broadcast`**
· **4.8 没有作用域/导入导出** · **4.9 没有外部状态读取** · **4.10 没有外部调用接口**
· **4.11 没有视图/内容**（坐标、画布、台词、美术、时间轴、标题、文案） · **4.13 没有 `posture`**

**4.7 ~~没有参数化机器~~ → 已撤销**（2.14）。

**4.12 没有 `entryState` / 非可重复机器的 `exitStates`** —— 跳级调试接口。
实测 18 处 `entryState` **全部等于 `initialState`**，编译器可合成。

**4.14 没有存档迁移映射（`migrations`）** —— 三条理由：
①正确的改名是级联改掉所有引用（3.5），项目内部改完就没有旧 id 了；
②这张表**只增不减**，永远删不掉——一份长在内容里的无限增长的历史账本；
③存档那边本来就有版本号（`serialize()` 返回 `version: 2`），有版本号的一侧才是放迁移的地方。
⇒ **改名之后老存档怎么办，由存档系统决定。**

**4.15 没有实例、挂起、激活槽、`resumable`、机器级冻结** —— 由 1.2。

"这条线搁置期间会不会偷偷往前走"是**伪问题**：机器要动，得有一条**从它当前那一拍出去的边**被触发。
**「从哪一拍出发」这道门本来就把机器钉死在它该听的那几件事上。**

> ⚠ v12 曾以 `当前活` 机器 + `active when C` 把它们放回来。"拿实现当语义"的**第五次**，
> 最隐蔽的一次：**没抄机制，抄了它要解决的问题。**

**4.16 没有 `label`** —— 显示文案 ⇒ 内容。实测 label≠id 比例虽高（状态 189/191），
但内容是 `board_read → 看板初读` 这种——**label 只是在补 id 不可读**。DSL 里 id 一开始就写对。

**4.17 没有 flag 通道（本版判定）**

叙事**不读** flag，也**不写** flag。

- **不写**：`setFlag` 是**命令式写状态 = 操作**，违背 1.0。这条是决定性的。
- **不读**：实测全项目叙事转移里 flag 条件叶**只出现一次**——
  `state_1 --[reactive, GameConfig_Demo主线剧情==true]--> 开局听书`，
  读的是个**配置开关**，而且**那条转移的 `signal` 字段作者写的正是 `Demo主线开始`**
  （trigger=reactive 时被忽略）。**作者本意就是事件，实现成了轮询。**
  ⇒ 按 1.1 写成 `on Demo主线开始 -> 开局听书`，由配置那边开机发信号。

flag 仍是项目里的真实状态通道（对话与其它系统大量读它），只是**不归这门语言**。
需要它反映叙事状态时，走 1.0 推论②：`flag 真相已揭 = 水鬼真相.已揭开`（在 flag 那边写）。

## §5 限制清单（明确不提供，非遗漏）

1. **计数不可清零** —— 记忆语义里没有遗忘。要重来就是新档。
2. **机器不能写另一台机器的状态**（2.7）。**不构成限制**：被打断写成"本机观察到别人的边、自己走到那一拍"。
3. **`ever` / `count` 作者不可写** —— 1.4。
4. **不提供遗忘、撤销、回滚**。

### 唯一剩下的悬案

**形式语义未写。** 求值策略——每次扫描每图至多选一条转移、状态变化后重扫至不动点、
队列与嵌套排空、订阅的执行时机——目前只存在于实现里。

**建立其上的静态分析清单**（T2 补了第 5 条）：
①悬垂信号 ②不可达状态 ③死锁（无出边且非终点）④振荡（反应式环）
⑤**待接线**（`todo`，与①严格分开）⑥`count` 的目标非 `Done` ⑦维度拼写

**这是实现前的最后一道作业。**
