# 玩法功能需求清单

本文档列出游戏所有需要用代码实现的玩法功能。每一条都是一个具体的、可编码的需求。

---

## A. 基础架构

### A1. 游戏主循环与状态机

- 游戏全局状态机，管理以下状态的切换：主菜单、场景探索、对话模式、遭遇模式、任务面板、背包/规矩本界面、暂停菜单
- 在场景探索状态下，玩家可自由移动和交互
- 进入对话/遭遇/菜单时，冻结场景探索的输入，切换到对应状态的交互逻辑
- 状态之间的切换有明确的入口和出口条件

### A2. 场景管理

- 场景以数据文件（JSON）定义，包含：背景图层列表、交互热区列表、NPC位置列表、场景转换点列表、BGM/环境音配置；场景边界默认与首张背景图同尺寸，可设 backgroundScale，场景尺寸随背景缩放系数变化
- 场景加载器：读取场景数据，生成对应的渲染对象和交互区域
- 场景切换：从一个场景转换到另一个场景，带过渡效果（淡入淡出）
- 场景状态记忆：离开场景后再回来，之前检查过的物品、拾取过的物件、NPC状态应保持
- 场景解锁机制：部分场景（城外区域）初始不可进入，由主线任务进度解锁

### A3. 渲染系统（基础版）

- 基于PixiJS的2D渲染，支持多层背景图叠加显示
- 等轴视角下的精灵排序（Y轴排序，靠下的在靠上的前面）
- 摄像机跟随角色移动，支持场景边界限制
- 高级表现效果（后处理滤镜、粒子、动态光影等）暂不实现，后续按需添加

### A3.5 场景透视缩放（近大远小）（2026-07-18 拍板；2026-07-20 升级为任意方向深度轴）

- 部分场景背景带透视（近大远小），角色/NPC/热点展示图需随脚底位置动态缩放才能贴合背景；**纵深方向可以是斜的**（斜街），缩放沿该方向递减
- 场景级配置 `perspectiveScale` = 一根**深度轴**：near（近端，大）与 far（远端，小）两个世界坐标点各带缩放系数，可选 midStops 中途点（非线性纵深）。实体按**脚底点在 near→far 轴上的归一化投影**分段线性插值出系数；轴外投影钳到端点；等缩放的等值线自动垂直于轴。**缺省不配置 = 完全不缩放**，存量场景零变化
- 竖直轴（near/far 同 x）即最常见的"上下纵深"，是任意方向轴的特例
- 最终缩放 = 实体手动实例 scale（个体差异基准）× 场景透视系数 f；透视系数为纯派生态，不入存档
- 参与者：玩家与 NPC 默认参与；热点默认不参与（多为 WYSIWYG 贴背景绘制），可逐热点开启（如地面道具）
- 移动速度同步补偿：自由移动与 NPC 巡逻/演出位移的步长 × f，防止远处角色相对背景滑步；场景级 `affectsSpeed` 可关
- 编辑器：场景编辑器在画布上以可拖两端的箭头调节深度轴（近端■/远端○ + 垂直等值线），实时预览实体缩放（与运行时同口径，防预览撒谎），保存进场景 JSON

### A4. 输入系统

- 键盘输入：WASD或方向键移动角色
- 鼠标/点击输入：点击场景中的交互物品、NPC
- 交互提示：当角色走近可交互物体时，显示交互提示图标
- 对话和菜单中的键盘/鼠标选择操作
- 快捷键：打开任务面板（如Tab）、打开背包（如I）、打开规矩本（如R）、暂停（Esc）

### A5. 音频系统

- BGM播放器：支持场景切换时BGM淡入淡出过渡
- 环境音层：每个场景可叠加多个环境音源（市井人声、鸟叫、水流、风声等），每个可独立控制音量
- 音效播放：一次性短音效（拾取物品音效、学到规矩音效、遭遇开始音效、UI操作音效）
- 遭遇氛围音频：进入遭遇时刻时环境音渐弱，叠加低频氛围音
- 所有音频资源通过数据文件配置，不硬编码

### A6. 存档/读档系统

- 手动存档：玩家可在安全环境（非遭遇、非对话中）手动保存
- 存档数据包含：当前场景ID、角色位置、主线任务进度、所有支线任务状态、规矩本内容（含碎片）、背包物件列表、铜钱数量、所有场景状态（已检查的物品、已拾取的物件、NPC状态）、全局剧情标记（flag）、游戏内时间（第几天）
- 支持多个存档槽位
- 读档后完整恢复游戏状态

## B. 角色与场景交互

### B1. 角色移动

- 关二狗剪影角色在2D场景中八方向移动
- 移动速度恒定，可定义走路和跑步两种速度（按住Shift跑步）
- 碰撞检测：角色不能穿过场景中的障碍物（墙壁、家具、岩石等），碰撞区域在场景数据中定义

### B1.5 角色动画系统

- 帧动画播放器：读取序列帧图集（spritesheet），按配置的帧率播放
- 关二狗的基础动画状态：待机、行走、跑步。每个状态至少支持左/右朝向（剪影可做翻转）
- 动画切换：根据角色当前行为（静止/移动/交互）自动切换动画状态（行为分支实现，非图状态机——播放控制走播放头参数，见下）
- 播放头参数（复用动画素材）：一次播放可携带速度倍率（调速）、倒放（开门当关门用）、定格到指定帧（任意帧当 pose）、播完自动切换状态（一次性动作播完自动回待机）；通过 playNpcAnimation 数据配置触发，全部缺省时与旧行为一致
- 场景实体初始播放参数：NPC/氛围实体可在场景数据里配置初始状态的调速/倒放/定格/起播帧（initialAnimPlayback），仅进场起播一次性生效——用于同素材多拷贝错相去同步、跨场景变速复用、静态摆 pose；之后动作/巡逻切动画恢复默认参数
- 步速匹配：移动类动画状态可配置基准速度（referenceSpeed，世界单位/秒）；配置后角色实际移动速度自动缩放步频（夹取 0.5~2 倍防变形），消除滑步；未配置的状态恒原速（现状行为）
- NPC动画：每个NPC可配置自己的待机动画（简单的循环帧动画，如微动、呼吸感）
- 特殊动画：部分场景或遭遇中角色需要播放一次性动作动画（如：蹲下查看、捡东西、被推倒），通过数据配置触发
- 动画数据由外部配置文件定义：每个角色/NPC的图集路径、各动画状态的帧范围、帧率、是否循环、可选步速匹配基准

### B2. 场景交互热区

- 每个场景包含多个交互热区，在场景数据中定义，每个热区包含：位置/范围、交互类型（检查/拾取/NPC/场景转换）、触发条件（可选，如需要特定任务进度或物件）、交互内容ID
- 当角色进入热区检测范围时，显示交互提示图标
- 玩家按交互键或点击后，根据类型执行对应逻辑：
  - **检查**：弹出底部文字框，显示1-3句描述文字，可能附带规矩碎片获取或物件发现
  - **拾取**：物品加入背包，播放拾取音效，热区标记为已拾取
  - **NPC**：进入对话系统
  - **场景转换**：加载目标场景，将角色放置到目标场景的指定位置
- 热区可设置为一次性（检查/拾取后消失或变化）或持久（如NPC、场景转换点）
- 热区可关联任务：某些热区只在特定任务阶段可交互

### B3. NPC管理

- 每个NPC有数据定义：ID、名称、所在场景、位置、外观（剪影类型）、当前可触发的对话ID、状态
- NPC状态随主线/支线任务进度变化：不同任务阶段，NPC可能在不同位置、有不同对话、或完全不出现
- NPC对话可用性标记：当NPC有新对话（玩家未触发过的）时，显示视觉提示

### B4. 多角色与同伴系统（2026-08-06 拍板）

- **角色不分主角与配角**：所有角色同一套身份定义（名字/动画包/立绘）。区别只在于**是否可被玩家接管** —— 可接管的角色额外拥有一套"化身配置"（移动三态 + 身体动词映射 + 待机节目单）
- **一次只控一个**：任何时刻只有一个角色处于受控状态；玩家可在队伍成员间切换（按键直选/轮换）
- **切换即整体转向**：切人后，其余队伍成员立刻改为跟随**新的**受控者（不是原地站着，也不是继续跟老受控者）
- **身体动词对配角同样开放**：蹲/蹲行/驻足注视/踢/跳/躺是**机制**不是主角特权。某角色的动画包里没有对应片段时，该动词在该角色下自动禁用——不需要为配角补齐全部片段才能让它上场
- **两种跟随**：
  - **剧情段跟随**：对场景里已摆放的 NPC 开启跟随，随该段剧情结束而止（不入队）
  - **长期同伴**：入队后跨场景一直跟着走，玩家切场景时自动带过去；入队/离队由剧情驱动
- **数值与资源属于队伍，不属于个人**：血量、气味读数、背包是**整个队伍一套**，切人不改变任何数值。气味仍是"队伍闻到的"——象理术的读数来源不因切人而变（位置变了读数自然变）
- **过场只演关二狗**：一旦进入任何演出（cutscene），立即切回关二狗、其余角色立即隐藏；演出结束后还原为进入前的受控者与同伴显隐，同伴吸附到受控者身边。**关二狗恒在队伍中，不可离队**
- **对话不受此限**：图对话期间同伴照常在场、照常显示；只有演出触发上述规则
- **存读档**：当前受控者、队伍成员、跟随关系、同伴当前落位完整入档恢复
- 技术承载与分期见 `artifact/Design/多角色-可控配角与同伴跟随-技术设计-2026-08-06.md`
- 与 A6（存档）、B1（角色移动）、B1.5（角色动画）、H5（演出系统）均为 additive 扩展，无冲突

## C. 对话系统

### C1. 对话引擎

- 基于 **图对话 JSON**（`GraphDialogueManager`）驱动对话流程：节点、边、选项与条件均在数据文件中描述
- 节点与选项可挂 **条件**：检查玩家是否拥有某规矩、某物件、某铜钱数量、某任务状态、某全局标记（与 FlagStore / 数据约定一致）
- 对话过程中通过节点上的 **`actions`**（统一走 **ActionExecutor**）触发游戏行为：给予/扣除物件、给予/扣除铜钱、学到规矩/规矩碎片、更新任务状态、设置全局标记、触发遭遇等

### C2. 对话UI

- 画面底部对话框：显示说话者名称和对话内容
- 文字逐字显示（打字机效果），点击可跳过直接显示全文
  - 覆盖全部台词面：对话框、遭遇框、**过场对白框与过场字幕**；速度倍率与总开关在设置页，玩家关掉即全部整句上屏
  - 过场里可**逐拍**指定：对白框默认逐字、字幕默认整句上屏，编辑器上逐拍改得动
- 点击推进到下一句
- **台词配音（可选，逐句）**：任何一句台词都可挂一条配音；默认配音与这一句同生死（换句即停）
  - 一条较长的配音可以**盖住后面几句短台词**：起头那句声明"播完不停"，由后面某句声明"跟随配音结束"来收尾
  - 一句也可以声明**固定时长后自动推进**；两种自动推进下玩家点击仍可提前跳
  - 配音缺失/加载失败一律退化为"等玩家点击"，绝不闪切
- 当当前图节点提供选项时，在对话框上方弹出选项列表（2-4个）
- 选项可附带条件标记：
  - 需要铜钱的选项显示"[花X文]"前缀
  - 需要物件的选项显示物件图标
  - 条件不满足时选项灰色不可选，附带提示（如"铜钱不足"）
- 对话结束后自动返回场景探索状态

### C3. 追问机制

- 在图对话中，追问选项通过 **分支节点与选项** 实现
- 选择追问时，由对应节点上的 **`actions`**（如 `removeCurrency` / `removeItem`）扣除铜钱/物件
- 追问成功后，由后续节点或同一节点内的 **`actions`** 执行规矩获取（如 `giveRule` / `giveFragment`）
- 追问失败（资源不足等）通过 **选项条件** 或独立分支节点处理，给出 NPC 的拒绝回应

### C4. 叙事状态机绑定与场景 owner

- 叙事状态机（`NarrativeStateManager`）的 wrapper 图按 `ownerType:ownerId` 绑定实体（NPC、热区、区域、任务、**场景**…）。图对话经 `ownerState`（读"当前对话 owner"的 wrapper 状态）/ `contextState`（读指定 graphId 的状态）两类节点引用状态机
- **场景是一等叙事 owner**：场景可在叙事图里绑定 `ownerType:'scene'`、`ownerId:<场景id>` 的 wrapper，用来表达"这个场景当前处于哪个叙事阶段"
- **onEnter 自动继承场景 owner**：场景 `onEnter` 里用 `startDialogueGraph` 播的对话图，未显式指定 owner 时自动以"当前场景"为 owner——其 `ownerState` 节点解析为本场景 wrapper，无需作者手填。NPC/热区交互播的对话仍以各自实体为 owner
- **相对引用 token**：条件叶子与图对话 `switch`、`ownerState.wrapperGraphId` 支持 `@owner`（当前对话/场景 owner 的主 wrapper）与 `@scene`（当前场景 wrapper），免去写死 graphId，使依赖状态的 onEnter 分支逻辑可达
- **绑定可见与校验**：对话图的 owner 绑定由"谁引用它"（NPC / 热区 / 场景 onEnter）静态推导，在编辑器可见；owner 绑定图被无 owner 的调用点引用时给 **warning**（不阻断保存），运行时缺 owner 时优雅回退

## D. 任务系统

### D1. 任务数据结构

- 每个任务有数据定义：ID、类型（主线/支线/活计）、支线子类型（跑腿/打听/探查/委托）、标题（一句话）、描述（一两句话说清目标）、前置条件（需要完成哪些任务/拥有哪些标记才能触发）、完成条件（到达某地/与某NPC对话/拾取某物/完成某遭遇等）、奖励（铜钱/物件/规矩）、完成后触发的下一个任务ID（主线用）
- 任务状态：未触发、已接受（进行中）、已完成
- 追加（2026-08-08）：**目标清单**（见 D7）、**引导配置**（见 D8）、**接取提示档位**与**自动设为当前**开关（见 D9）。全部可选，不配即维持既有行为

### D2. 任务管理器

- 跟踪所有任务的状态
- **进行中的任务可以有很多条**（主线也不例外：主线链推进与条件自动接取会让多条主线任务同时进行中），面板必须全部列出
- 任务完成检测：每当玩家状态变化（到达新场景、完成对话、拾取物品、完成遭遇）时，检查当前活跃任务的完成条件是否满足
- 任务完成时：发放奖励、播放任务完成提示、更新任务状态、触发后续任务
- **展示层一律查询状态，不靠事件累积**：任务状态发生任何迁移（接取/完成/当前任务改变/目标勾掉）只广播一条「任务态变了」的信号，面板/HUD/引导收到后回头查当前状态重建。事件只说"变了"，不携带真相——这样自动接取与主动接取、首次进入与读档恢复走的是同一条显示路径

> 「同时只有一条主线活跃」的旧条款作废（2026-08-08）：现网主线链 + 条件自动接取本来就会并行多条，
> 而"同一时间只有一个"的正确落点是下面 D6 的**当前任务槽**，不是接取本身。

### D3. 任务触发

- 主线任务由前一个主线任务完成自动触发
- 支线任务的触发方式：与特定NPC对话时NPC给出委托、进入特定场景时自动触发、满足特定条件（如铜钱为0触发"找活干"）
- 触发时显示"新任务"提示（提示形态与是否提示见 D9，逐任务可配）
- **两种接取路径（条件自动接取 / 动作主动接取）在展示上必须完全一致**：状态翻转的同一时刻就广播任务态变化，不等接取动作批（可能内含一整段对话）跑完

### D4. 任务面板UI

- 按快捷键打开任务面板（覆盖在游戏画面上，暂停游戏）
- 页签分组：**进行中**（主线 + 支线，全部列出，不限条数）/ **活计** / **已完成**
- 每条列出：类型徽章 + 标题 + 一行简述；**当前任务**那条额外带「当前」标记
- 右栏详情：标题 + 描述 + **目标清单**（复选框逐条勾选，见 D7）+「设为当前任务」入口
- 关闭面板返回游戏

### D5. 可重复活计（多接单 · 单激活 · 可重复刷新）（2026-07-17 拍板）

- 「活计」= 可重复接取的委托型任务（背尸单、零工单等），与一次性主线/支线任务共存于任务面板
- **多接单**：玩家可同时接下多张活计（来源：NPC 派单 / 告示 / 场景触发）；每接一张，任务面板生成一条**独立的新条目**（同型活计再次接取=再生成新条目，不复用/不复活旧条目）
- **单激活**：同一时间全局至多一张活计处于「激活」状态；激活即当前追踪（HUD 显示其目标）；接单时若当前无激活单则自动激活；玩家可在任务面板切换激活对象。**2026-08-08 起该槽即 D6 的全局当前任务槽**（活计与主线/支线共用一条，不再是活计专属）
- **蛰伏语义**：非激活活计的世界内容默认蛰伏（其专属场景交互/指引不亮），切换激活后亮起；已接未激活的单不会推进也不会失败
- **完成与刷新**：活计完成后其条目标记完成并归档（可回顾）；同型活计可立即或按派单节奏再次接取
- **累计计数入剧情**：同型活计的累计完成次数是持久化的一等条件（首次接单走特殊演出、做满 N 单解锁暗线/涨价/新委托人等）
- **存读档**：在途活计各自的进度、激活槽指向、累计计数完整入档恢复
- 技术承载：叙事图运行实例化（原型/实例分离），设计稿见 `artifact/Design/叙事运行实例化-技术设计-2026-07-17.md`
- 落地状态（2026-07-17）：引擎（S1）+ 第一张活计图·淹尸活（S2批1）+ 任务面板 repeatable 条目/追踪切换/归档汇总（S2批2，`type:'repeatable'`+`runArchetype` 硬绑定）已上线并真机验收；面板归档为按出口汇总行（逐单历史列表未做）；派单节奏属内容编排（对话/告示按条件派单已跑通，按天投放用现有条件表达，不进引擎）；可重复叙事的玩法数据绑定模型（活计图如何声明/引用它驱动的实体/点位/报酬等；原型级静态绑定已由盖章模板覆盖，待设计的是 run 级绑定面；"单间差异"是绑定可参数化的派生结果）等内容拉动再定形（S3）

### D6. 当前任务（全局单一追踪槽）（2026-08-08 拍板）

- **全局至多一条「当前任务」**，跨主线/支线/活计共用同一个槽（不是每类一条）。它决定 HUD 显示哪条任务、引导指向哪里
- 玩家可在任务面板里把任意一条进行中的任务设为当前任务；也可由策划用动作 `setFocusedQuest` 指定
- 自动落焦：接取新任务时，若当前槽为空则自动占位；逐任务可配「接取即抢占」（见 D9）
- 自动改选：当前任务完成或失效时，自动落到另一条进行中的任务（主线 > 支线 > 活计，同级取最近接取）；没有则清空
- **与活计激活槽的桥接是单向的**（故意的）：
  - 把一条活计设为当前任务 = 激活它的活计图（就是 D5 一直以来的「切换激活对象」手势）；活计被激活/切走时当前任务槽同步跟随
  - 把一条**主线/支线**设为当前任务时**不动**活计激活槽——反向清槽会让不可恢复的在途活计被直接作废（切走非 resumable 的活计 = 丢实例 + 计一次 aborted），而玩家只是想追踪主线而已。手上的活继续在跑，只是 HUD/引导跟着主线走
  - 自动改选同理：**绝不为了补位去激活一张挂起的活计**（那等于凭空推进叙事）
- 当前任务槽进存档；读档恢复，恢复目标已不在进行中则按自动改选规则重挑

### D7. 任务目标（objectives）

- 一条任务可以配**若干条目标**，每条目标 = 一句话 + 完成条件（与任务完成条件同一套条件表达式）+ 可选的专属引导
- 目标勾选状态是**从条件派生的**，不单独入档（与"任务清单是叙事状态的镜像"这条一致）
- 「当前目标」= 第一条未完成的必做目标；可标记某条为可选目标（不参与"当前目标"选取，也不阻塞后续）
- 面板右栏按顺序列出目标，已完成打勾；HUD 在任务名下显示当前目标一行
- 不配目标的任务维持现状（面板只显示描述）

### D8. 任务引导（多通道并行，策划自由配置）

- 引导挂在**目标**上（目标没配则回落到任务级配置），只对**当前任务**生效
- 通道**互不排斥**，可同时开任意条数：
  - **地图标记**：在地图界面对应地点上打标（地点 = 场景）
  - **场景内浮标**：目标在当前场景时，在实体或坐标上方显示浮标；目标不在视野内时贴屏幕边缘显示指向箭头（可配是否显示距离）
  - **场景提示**：进入指定场景时在 HUD 出一行提示文字
- 新增通道 = 加一个渲染实现，数据结构与配置面不动
- 引导目标引用实体时用「场景 + 实体种类 + 实体 id」的限定写法，进重构引擎的引用登记面，实体改名/迁场景可跟随；校验器对指不到的引导目标报 error

### D9. 新任务提示（醒目程度逐任务可配）

- 每条任务可配提示档位：**无提示 / 木条提示（右上角 toast，与拾取物件同一条队列）/ 醒目横幅（屏幕中上木牌，任务名 + 首条目标）**
- 缺省档位：主线 = 醒目横幅，支线/活计 = 木条提示（不配也有合理表现）
- 动作 `setFocusedQuest` 可勾选「同时给醒目提示」，用于策划在剧情节点上主动把玩家的注意力拉到某条任务
- **多条任务同时激活**时（同一批动作 / 同一次条件重评里接取多条）：
  1. 横幅是**单通道串行队列**，一次只显示一条，条与条之间留间隔
  2. 同一批里至多**一条**走横幅（优先级：主线 > 支线 > 活计，同级取数据序），其余全部降级为木条提示
  3. 对话/过场/小游戏进行中不出横幅，等回到探索态再出（与木条提示同一套压制判据）
  4. 同一条任务在队列里只保留一条
  5. 排队过久（跨场景或超时）直接降级为木条提示，不做"很久以后突然弹出"
  6. 读档恢复补发的任务态变化一律不出任何提示

## E. 规矩系统

### E1. 规矩数据结构

- 每条规矩的数据定义：ID、名称（一句话概括）、**未集齐时的占位名**（`incompleteName`，可选）、分类（避邪/禁忌/行当暗语/江湖门道）、**象 / 理 / 术** 三层正文（每层可选；至少一层有内容；未配置的层视为该规矩无该深度）。**验证状态（未验证/验过有效/存疑）属于各层属性**，可在每一层独立标注；规矩级不再有统一的 `verified` 字段。**碎片出处**写在各碎片上，不再在规矩级写「来源类型 / 来源长文」。
- 规矩碎片的数据定义：ID、内容文字、所属完整规矩ID、**归属层**（象 / 理 / 术）、**出处**（必填，如「老道士」）、排序以数据文件内顺序为准（不再使用碎片编号字段）。

### E2. 规矩获取逻辑

- **直接获取**：对话或脚本调用 `giveRule`，等价于一次性解锁该规矩**所有已配置层**；仍写入 `rule_<id>_acquired`，并弹出「规矩本新增」类提示。
- **单层授予**：脚本可调用 `grantRuleLayer`（或等价 Action）只解锁某一层（亲历、演出补全等）；**不**单独为此弹完整「规矩本新增」，除非此时所有层已齐。
- **碎片获取**：获得碎片后，若该碎片所属层下碎片已全部集齐，则该层视为解锁；当**所有已配置层**均解锁时，与 `giveRule` 等效（`rule_<id>_acquired` 为真），并播放合成提示（若由「集齐全部碎片」触发自动合成）。
- **层解锁与存档**：每层解锁可同步 `rule_<id>_<层>_done` 等标记，供遭遇选项、区域「用规矩」等按层判定；完整掌握仍由 `rule_<id>_acquired` 表示，供对话 `requireFlag`、书籍条件等沿用旧数据。
- 任何方式**首次完整掌握**一条规矩时：播放固定音效、显示「规矩本新增」提示（非模态，角落弹出短暂显示后消失）。

### E3. 规矩匹配（供遭遇系统调用）

- 提供查询接口：给定一个遭遇ID，返回玩家已学的、与该遭遇关联的规矩列表
- 提供查询接口：给定一个对话条件ID，返回玩家是否拥有该规矩
- **遭遇选项**可选配置「需要已解锁的层」：未配置时仍要求**完整掌握**（`rule_<id>_acquired`）；配置时只要求所列各层均已解锁（读 FlagStore，不直查 Manager）。

### E4. 规矩本UI

- 按快捷键打开规矩本界面（覆盖在游戏画面上，暂停游戏）
- 左侧分类标签：避邪/禁忌/行当暗语/江湖门道/碎片
- 右侧列表：该分类下的所有已获得规矩，每条显示名称
- 点击某条规矩显示详情：**按象 / 理 / 术** 展示已解锁层正文及该层的验证状态标签；未解锁层显示占位（或策划配置的 `lockedHint`）；碎片出处仍体现在各碎片条目上
- 搜集中条目：可按层展示碎片进度；未合成碎片列表仍标注所属规矩与收集进度
- 新获得的规矩有"新"标记，查看后消失
- 关闭界面返回游戏

## F. 物件系统

### F1. 物件数据结构

- 两类物件：
  - **消耗品**：糯米、香灰、红布、桃木片、黄纸、烧酒、馒头/干粮。有数量，使用后数量减少
  - **关键道具**：铁盒子等剧情道具。不可消耗、不可丢弃，有动态描述（随剧情变化）
- 每种物件的数据定义：ID、名称、类型（消耗品/关键道具）、图标、描述文字（消耗品为固定描述，关键道具为随剧情变化的描述列表+对应条件）、购买价格（如果可购买）、最大叠加数量
- 铜钱作为特殊货币物件，独立显示，不占背包格子
- **物件标签（tags）**：一个物件可归入若干民俗类别（辟邪、食物、引火、信物、沾秽……）。标签是给系统看的分类，不是玩家可见文案；用途是让"用点"按类别接受物件，而不必逐个点名物件 ID

### F1b. 物件用途（主动使用）

- **物件可以有"用途"**：即玩家在背包里对该物件主动执行的一次行为（吃掉、点燃、撕开、揣进怀里）。没有用途的物件（多数关键道具、纯凭证）在背包里就没有使用入口
- 用途的数据定义：按钮文字、可用条件、不可用时的说明、是否消耗一个、执行内容、执行后的一段说明文字
- **"能不能用"必须在玩家点下去之前就算得出来**：条件不满足时按钮置灰并给出理由，不允许点了才发现没反应
- **用途只描述"物件自身的行为"**，不描述"对着场景里某个东西用"。后者仍归物件检视的用物表（持物点热区），两者互不覆盖
- 消耗顺序：先扣除物件，再执行内容；扣除失败（数量不足）则整个使用取消，不执行任何内容、不给任何提示以外的反馈
- 关键道具默认不因使用而消耗

### F2. 背包管理

- 背包有容量上限（格子数），消耗品每种占一格（同种叠加），关键道具每个占一格
- 物件获取：拾取/购买/任务奖励/NPC赠送时，检查背包是否有空间，有则加入，无则提示"包袱满了"
- 物件消耗：遭遇/对话中使用时扣除数量
- 物件丢弃：消耗品可手动丢弃腾出空间，关键道具不可丢弃（除非剧情要求，如把盒子扔进河里由剧情脚本处理）

### F3. 商店/购买

- 特定NPC（如集市摊贩、杂货铺）可触发购买界面
- 购买界面：显示可购买的物件列表，每个显示名称、图标、价格
- 选择物件后扣除铜钱，物件加入背包
- 铜钱不足时物件不可选，显示"铜钱不足"

### F4. 背包UI

- 按快捷键打开背包界面（覆盖在游戏画面上，暂停游戏）
- 顶部显示铜钱数量
- 格子式物件列表，每格显示物件图标+数量（消耗品）或图标（关键道具）
- 点击某物件显示详情：名称、描述文字、"使用"按钮（配了用途的物件）、"丢弃"按钮（消耗品）
- "使用"按钮排在"丢弃"上方（主操作在上、破坏性操作在下）；条件不满足时置灰、键盘方向键跳过它，并在按钮上方就地显示不可用的理由——**置灰的按钮点不动，理由只挂在点击上就是读不到的死信息**
- 关键道具的描述文字根据当前剧情标记动态显示对应版本
- 关闭界面返回游戏

## G. 遭遇系统

### G1. 遭遇数据结构

- 每个遭遇的数据定义：ID、触发条件（进入某热区/到达某场景位置/对话中触发/任务进度触发）、前置叙事（关二狗的内心独白或场景描写，在选项出现前显示）、选项列表
- 每个选项的数据定义：
  - 选项文字（具体行动描述）
  - 选项类型（通用/规矩/特殊）
  - 前置条件：需要的规矩ID（规矩选项用）、需要的物件ID和数量（道具增强用）、需要的全局标记（特殊选项用）
  - 道具是否消耗（选择后是否扣除物件）
  - 结果动作列表：选择后由 **ActionExecutor** 执行的一组 Action（与对话/演出等处同一套类型）
- 每个选项的结果可包含：显示结果文字、给予/扣除物件、给予/扣除铜钱、获得规矩（亲历方式）、更新任务状态、设置全局标记、切换场景、触发后续对话、触发延迟后果

### G2. 遭遇触发与流程

- 遭遇触发器：场景中定义遭遇触发区域，角色进入时激活遭遇
- 触发遭遇后的流程：
  1. 冻结角色移动和场景交互
  2. 播放氛围变化效果（画面色调/音频变化）
  3. 显示前置叙事文字（如有）
  4. 查询规矩系统获取匹配的规矩
  5. 生成选项面板：通用选项 + 规矩选项（有规矩才显示）+ 道具增强标记（有道具可选/无道具灰色）+ 特殊选项（条件全满足才显示）
  6. 玩家选择
  7. 执行选择结果
  8. 恢复场景状态或切换到新状态

### G3. 遭遇选项面板UI

- 在画面底部或中下方弹出
- 每个选项一行：选项文字 + 类型标记（规矩选项有小图标标识） + 道具需求标记（灰色/可用）
- 选项总数控制在4-6个
- 选项有高亮选中态，键盘上下选择或鼠标点选
- 选择后面板收起，执行结果

### G4. 延迟后果系统

- 维护一个"延迟事件队列"：每个条目包含触发时间（第几天）、触发内容（设置标记/修改NPC状态/触发对话/修改场景状态）
- 每当游戏内时间推进到新的一天，检查队列中是否有到期事件并执行
- 延迟事件由遭遇结果或对话结果写入队列

## G.5 死亡系绳 / 系统级血量（核心机制）

- **系统级血量**：主角有一条持久血量（默认满、入存档、同步到 flag `player_health`/`player_max_health` 供条件判定）；HUD 常驻血条。平时不掉，只在**危险段**（压力小游戏 / 坠潭等濒死情境）急掉。
- **死亡系绳（玩家永不真死）**：血量将归零（达死亡阈值）那一刻被**拦截**——不死，血被拽回恢复底，同时触发**阿秀冷信号**（香粉味+小调，来自他贪财捡的旧帕子包/空香粉盒）。
  - **机制即主题**：信号不是温情守护，是阿秀死时那口**盲目的"不撒手"念气**，只认物（帕子包）不认人、无意识、无倾向，只是不让揣着它的人撒手。妖护人——他揣着真旱魃还不自知。（信号设计权威源：阿秀定稿《阿秀支线-完整剧情与主线实施方案》§8b/§9）
  - 拦截时发叙事信号 `death_tether`，供剧情按"第几次被拽/创伤留痕"取变体。
- **系绳失灵 / 外部接管（变体）**：特定剧情拍可让系绳"这一次接不住"。在送货⑨回程出山口（李天狗登场戏）那一拍，濒死时 `death_tether` cue 照常起头——香粉味刚冒头，却被一股更冲、更"正"的气息当头压下、没起来就掐灭；系绳第一次没把人拽回来，他是真往黑里去了。随后改由剧情脚本（李天狗一声断喝、符光散开冷东西、把人从雾里拎出来）**外部接管**血量、把 HP 恢复到底。机制即叙事：是那更强的气息冲散了阿秀那口盲目念气，而非念气主动放手——念气始终只认帕子包、不认人、无意识无倾向（红线同上：非守护、非复仇）。
  - 实现上 HealthSystem 需留"本次 tether 被外部接管"的口子，让剧情脚本接手恢复 HP；此处是该变体唯一触及代码处（L2 级）。
- **三个濒死触发点（首批）**：背尸①坠潭、送货⑨认不准应声、义庄镇尸外乡尸扑脸。各自在"他真要死了"那一拍把血打到底 → 系绳拽回（送货⑨这一拍走上述"失灵→外部接管"变体）。
- **无 Game Over**：恐怖/濒死段失败不结束游戏、不阻塞主线——死亡被系绳兜住，只在叙事上留痕。
- **配套新规矩「路祭不能动」**（违则招煞，配合送货⑨触发点）：路标边供野鬼的酒肉路祭，无论多饿都不能碰；动了即犯忌、招那股伏煞缠身。送货⑨"撑过/认不准"分支里，关二狗饿急了给自己编歪理（"野鬼老爷还差这口？"）把规矩说服掉、坐下大吃路祭——这一犯忌正是把濒死那一拍引到出山口的因。规矩走 §E 规矩系统数据定义（避邪/禁忌类），不在代码硬编码。

## H. 游戏时间与世界状态

### H1. 游戏日推进

- 游戏内有"天"的概念：第1天、第2天...
- 天的推进不是实时的，而是由剧情事件驱动：完成当天的主线任务关键节点后，触发"天结束"
- 天结束时：播放过渡效果（如黑屏+文字"第X天"）、处理延迟事件队列、更新NPC状态/位置/对话、更新场景状态（新增/移除物品和交互点）、更新可用支线任务

### H2. 全局标记系统（Flag）

- 一个全局的键值对存储，键为字符串标记名，值为布尔或数字
- 所有系统可读写标记：对话脚本设置标记、遭遇结果设置标记、任务完成设置标记
- 所有系统可查询标记：对话分支判断标记、遭遇选项判断标记、NPC状态判断标记、任务触发判断标记、场景热区判断标记
- 标记是游戏内一切条件判断的统一机制

### H3. 日夜循环（2026-08-12 拍板）

H1 的"天"往下细化出**时刻**与**时段**：同一个场景有白天和夜晚两副面孔，同一批 NPC 白天夜晚各在各的位置。

- **时刻不自行流逝**（与 H1 同一条原则）：游戏内时刻只由动作推进，没有真实时间累加。玩家在长对话里不会莫名其妙天黑
- 推进时刻的来源：剧情事件、场景交互、对话结束，以及**玩家主动"等待"**（选择等待 → 播一段日夜流转的过渡演出 → 时刻推进到下一个时段）
- **时段**由时刻派生（缺省 拂晓 / 白日 / 黄昏 / 入夜四档，分段点可配）；时段是内容侧的通用条件——热区、NPC、区域、**场景分组**、对话分支、叙事图、文书揭示都能直接判"现在是不是夜里"
- **"这东西什么时段在场"只有一种配法**（2026-08-26 补）：热区 / NPC / 区域 / 场景分组四种载体，都用同一格**时段归属**声明自己在哪几段存在——同一个逐场景开关管到底，时刻一变四者同时重算。条件（conditions）负责的是"剧情/任务/状态说了算"的那部分，**不再兼职表达时间**；仍然写得出`时段`条件叶（对话分支、叙事图要用），但用它来控场上实体的显隐属反模式，编辑器会提示改用时段归属。
- **逐场景开关**：一个场景参不参与日夜循环是可配的，不参与的场景维持现状（旧场景零影响）
- **夜里长什么样不由这套机制规定**：可以是同一张背景图按时刻实时算光（光照曲线／色调滤镜），也可以是另画一张夜景图按时段换上，还可以两者混用。开关只负责"现在是什么时段"，画面表现是美术与渲染各自的选择
- 推进时刻时按**有无画面遮挡**分四种表现，这是"无缝"与"不穿帮"的分界：
  - **无缝**：画面不遮挡，光影连续渐变（日夜循环的主力表现）；此时 NPC 换班必须走 H4 的离场演出
  - **延时**：播一段日夜流转的延时演出（玩家"等待"用）
  - **淡入淡出**：黑场过渡
  - **直切**：无过渡，仅调试与演出内部使用
- 时刻与时段进存档；读档后场景面貌与 NPC 位置都按恢复出的时刻重算

### H4. NPC 日程与自然离场（2026-08-12 拍板）

- 每个角色可配一张**日程表**：几点到几点、在哪个场景、在哪个位置、做什么。日程只声明"该在哪"，不声明"怎么走过去"
- 日程按**角色**挂（不是按每个场景里的 NPC 实例挂），一张表管这个角色在全世界的行踪；日程可带条件，剧情推进后可换整张表
- **NPC 绝不当着玩家的面凭空消失**——这是硬要求：
  - 玩家**不在**那个场景时：NPC 的位置直接按日程算，进场景时就已经是该时段的样子（玩家没看见，不存在穿帮）
  - 玩家**在**那个场景时：到点的 NPC 先说一句离场话（"天不早咯，回去了"），然后**走向场景出口**，走到出口才隐去。入场反过来——从出口走进来，不原地冒出来
- **NPC 的缺省作息就是「只在白日出没」**：这个世界的人白天做事、天一擦黑就归家，街上有人是特例不是常态。不给 NPC 配任何东西时，他天黑就不在了；要他在拂晓/黄昏也在、或昼夜常驻，才需要显式配时段。（热点、区域不吃这条——门和路牌夜里当然还在）
- **就近的那一层说了算**（2026-08-26 补，为「场景分组也有时段归属」定调）：一个实体的时段按**自己写的 → 所属分组写的 → 种类缺省**（NPC 只在白日 / 热点区域全时段）三级取用，取到第一个有值的为止。所以给整队人配一次"夜里出现"，队里每个人就都是夜里出现，**不必再逐个勾一遍**——正因为漏勾一个就是一份永远不出现的死内容。
  - 分组自己不写时段 = 不施加限制，现有分组零影响；分组是异构容器（可能同时装着人和门），故它没有 NPC 那条"只在白日"的缺省。
  - 成员**显式**写了时段时，与分组的时段取**交集**（分组是整体限制，与它的"整体显影条件"同一个方向）。交集为空 = 这个实体永远不出现，属于作者写岔了，编辑器校验会当场报出来，不靠上线后靠肉眼发现。
- 场景可配**出口锚点**（街口、门等）；没配的场景自动按场景边界推导，保证任何场景都不会出现原地消失
- **绝不在对话中途走人**：玩家正在与该 NPC 对话、或正在演出/非探索态时，离场挂起，等回到探索态再走
- 日程本身不入档（是"时刻 + 条件"的派生结果）；只有被剧情改写的日程覆盖入档

## H.5 演出系统（Cutscene/Sequence）

### H5.1 什么是演出

演出是游戏中预编排的叙事片段，玩家在此期间失去操控权，由脚本驱动一系列动作按顺序或并行执行。用于：主线剧情的关键情节（如城隍庙发现女尸）、天与天之间的过渡、NPC的重要行为表演、说书人讲故事的特殊演示。

### H5.2 演出引擎

- 演出由一个时间线（Timeline）驱动，时间线由一系列"演出指令"按时间顺序排列组成
- 演出指令类型：
  - **摄像机控制**：移动摄像机到指定位置、缓动方式（线性/缓入缓出）、缩放
  - **角色/NPC移动**：让指定角色沿路径移动到目标位置
  - **角色动画播放**：让指定角色播放指定的一次性动画
  - **对话弹出**：显示对话文字框（无选择，纯叙述），玩家点击推进
  - **字幕**：黑边上/下的整行叙述文字；与对话弹出**同一套配音与推进语义**（见 C2：逐句可挂配音、
    可跨句留声、可跟随配音或定时自动推进）
  - **画面效果**：黑屏淡入淡出、画面闪白、色调变化
  - **音频控制**：播放/停止/渐变BGM、播放音效
  - **等待**：等待指定时长、或等待玩家点击
  - **设置标记**：设置全局标记（用于后续逻辑判断）
  - **场景切换**：切换到另一个场景
  - **显示章节标题**：全屏显示文字（如"第二天"、章节名）
- 支持多条指令并行执行（如摄像机移动的同时角色也在走动）
- 支持指令之间的依赖关系（等前一条执行完再执行下一条）

### H5.3 演出数据格式

- 每段演出以数据文件（JSON）定义，包含时间线指令列表
- 每条指令包含：类型、参数、开始时间或依赖关系、持续时长
- 演出可由以下方式触发：主线任务进度、进入特定场景、遭遇结果、天结束/开始

### H5.4 说书人演出

- 说书人讲故事时的特殊演出模式：画面可能展示故事内容的剪影插画（静态图或简单动画），配合底部文字叙述
- 实现方式：演出时间线中插入一系列"展示插画+对话文字"的指令
- 插画可以是预绘制的静态图，也可以是场景中元素的简单排列和动画

## J. 数据驱动设计

所有游戏内容通过数据文件配置，不硬编码在程序逻辑中。程序只负责读取数据并执行通用逻辑。

### J1. 需要定义的数据格式

- **场景数据**（JSON）：背景图层、碰撞区域、交互热区、NPC位置、转换点、音频配置、遭遇触发区域
- **NPC数据**（JSON）：基本信息、各状态下的位置和对话、状态切换条件（标记）
- **物件数据**（JSON）：所有物件的属性、描述、价格
- **规矩数据**（JSON）：所有规矩和碎片的定义、关联遭遇、关联对话条件
- **任务数据**（JSON）：所有任务定义、前置条件、完成条件、奖励、链式关系
- **遭遇数据**（JSON）：所有遭遇定义、选项、条件、结果
- **图对话数据**（JSON）：所有 NPC 对话与剧情对话分支，含条件、选项与 `actions` 触发的游戏行为
- **动画数据**（JSON）：每个角色/NPC的图集路径、各动画状态的帧范围和帧率、是否循环
- **演出数据**（JSON）：每段演出的时间线指令列表，指令类型/参数/时序/依赖关系
- **人物簿数据**（JSON）：所有NPC的人物簿条目，各阶段信息内容及解锁条件
- **见闻录数据**（JSON）：所有见闻条目的标题/正文/来源/分类/解锁条件
- **文档数据**（JSON）：所有可收集散落文档的名称/原文/批注/发现条件
- **独立书籍数据**（JSON）：每本书的元信息、每页内容、每页解锁条件
- **音频配置**（JSON）：场景-音频映射、音效ID映射

## K. 补充系统

### K1. 失败与死亡处理

#### 设计原则

大部分遭遇中不存在"死亡"。错误的选择导致的是不良后果（丢失物件、受到惊吓、错过线索、NPC态度变差），而非游戏结束。故事始终继续推进，只是走向不同的分支。

#### 少数致命遭遇

极少数关键遭遇中，特别糟糕的选择可能导致关二狗"出事"（如被杀、被鬼缠上无法脱身）。此时：
- 画面渐暗，显示一段结局文字（描述关二狗的下场）
- 弹出选项：[从上次存档继续] / [返回主菜单]
- 不实现自动存档/检查点机制，玩家需要养成手动存档习惯
- 致命遭遇在进入前应有足够的氛围暗示（让玩家有意识地在之前存档）

#### 非致命惩罚类型

遭遇中的"坏结果"不是死亡，而是以下惩罚的组合：
- 丢失随身物件（被抢、弄丢）
- 损失铜钱
- 获得负面标记（影响后续NPC态度或剧情分支）
- 获得"亲历"规矩（吃了亏学到教训，也算收获）
- 被迫离开当前场景（逃跑）
- 触发延迟负面事件（如当晚噩梦、第二天身体不适等叙事后果）

### K2. 场景导航（城市地图）

- 按快捷键（如M）打开城市地图界面
- 地图为简化的手绘风格示意图，显示渝都卫城及周边的所有场景位置
- 已解锁的场景显示为可点击的标记点，未解锁的显示为模糊/未知
- 点击已解锁场景后，画面过渡（淡入淡出），直接切换到目标场景的入口位置
- 当前所在场景高亮标识
- 有新内容/新任务相关的场景可显示提示标记（如小圆点）

### K3. 事件日志（2026-08-17 由「对话记录」升级）

#### 设计定位

日志是**这一局游戏的时间线**：不只是对话，一切"玩家可见的既成事实"都进——接到活计、拿到物件、记下线索、学到规矩、册子进条。

与提示条（toast）的分工是硬边界：

- **toast 负责当下的一瞥，可以丢**。顶中提示条、右上入袋回执、任务横幅全部是一次性的，且面板/过场期间只压出队不丢、出来再依次冒完（**这套节奏是有意保留的**，2026-08-17 拍板：看着回执一条条弹出来本身就是反馈快感，不改成丢弃或折叠）。
- **日志负责事后的复查，不可丢**。玩家错过了任何一条 toast，都能在日志里找回来，并且能**点着跳到那件东西上**。

因此升级前的病灶是：唯一可回溯的面板只收对话，另外三条通道全是易失的——一段过场里发生六件事，提示条放完幻灯片就永远没了。

#### 记录内容

按时间顺序单一时间线，收录通道为**白名单**：

| 通道 | 记什么 | 可点跳到 |
|---|---|---|
| 对话 | 每句台词（说话人 + 正文）、玩家选择、每段对话的开始抬头 | — |
| 任务 | 接取、完成、当前任务变更 | 任务面板并选中该任务 |
| 物品 | 获得（含数量） | 背包并选中该格 |
| 线索 | 采集（`hidden` 线索不记——它连册子都不进） | 线索簿并定位该词条 |
| 规矩 | 习得、碎片合成 | 规矩本并选中该条 |
| 档案 | 人物簿/见闻录/杂书匣/怪话册/歪歌册进条、得书 | 对应册子并定位该条 |

**去噪四条**（日志不是事件总线的镜子，否则它自己就成了第二次轰炸）：

- 只记玩家可见的既成事实。flag 变更、位面切换、场景装载一律不记。
- 相邻同目标合并计数（`获得了 纸钱 ×3` 是一条，不是三条）。
- 每段对话前写一条抬头（`—— 与 王婆 ——`），否则事件条插在对白中间读起来是乱的。
- 一段对话结束后紧跟的结算（任务＋物品＋线索）在视觉上归一组，靠分隔线表达，不加数据字段。

#### 交互

- 快捷键（L）打开，可滚动浏览；面板与触屏入口统一叫「日志」（不再叫「对话记录」）。
- 每条左列一枚通道图标，**与该事件当时冒的 toast 用同一套木刻剪影**——让玩家把"刚才闪过去那条"和"日志里这条"对上号。对话行左列仍是说话人，玩家选项仍以不同样式标识。
- 带跳转目标的条目整行可点（行尾一个 `›`），点击 = 关掉日志、打开目标面板并选中/滚动到那一条。任务条另给一个"追踪这条"的次级入口（设为当前任务，接上世界浮标与地图标记）。
- 顶部一个过滤开关：**全部**（默认）／**只看事件**（隐去对话行，用于"我刚才到底得了些什么"）。鼠标直接点；键盘/手柄从列表顶端按「上」到达、回车切换（不占快捷键——切档与全站面板切页签同一套焦点导航）。
- HUD 的日志入口显示**未读点**：有新条目未读时亮起，打开日志即清。没有它，玩家不知道要去看日志，前面全白做。

#### 数据与存档

- 日志条目是**结构化**的（通道、类型、说话人、正文、跳转目标、序号、游戏内时刻），不是一串已经拼好的字——跳转依赖条目自带的 id。
- 正文按**原始带标记文本**存（`[c:]`/`[tag:]` 原样入档、显示时即时解析），与全站文本引用铁律一致。
- 容量**分桶配额**：对话与事件各自 FIFO，事件条不被对话洪水冲掉（它恰恰是最需要事后查的那部分）。单条超长仍截断。
- 日志随存档走、不跨存档（读档后即该存档当时的状态）。

#### 红线

- **读档恢复期不得收录**。各系统 deserialize 会补发接取/进册等事件，不挡住的话读一次档日志里就多出一屏假记录。
- 日志的数据来源是**领域事件**（带 id），不是提示条文案——照抄 toast 文本会让跳转无从谈起。
- 日志**只读不写**：点条目只做导航，不产生任何游戏状态副作用（唯一例外是显式的"追踪这条"）。
- 跳转目标只用**领域事件原样带出的 id**，日志不做二次解析、不猜。会随游戏进程漂移的目标（如任务当前目标所在地点）不烘进条目——烘进去必然过时。
- 未收集的条目（怪话册/歪歌册的灰槽）**拒绝被跳到**：指认一个还没到手的东西等于剧透，与线索"未采集不占位"同源。

### K4. 新游戏开场与教学引导

#### 设计原则

不做独立的"教学关"。通过序章（盒子的故事）的前几分钟，用游戏内的自然情境教会玩家所有操作和系统。

#### 引导流程

- **移动和交互**：游戏开始在茶馆门口，角色自然需要走进去。第一个交互点（茶馆门口的告示或小物件）教会检查操作
- **对话**：进入茶馆后自然和小二/说书人发生对话，教会对话推进和选择操作
- **追问和规矩获取**：说书人讲故事时出现第一个追问选项，玩家体验追问机制并学到第一条规矩。此时弹出简短提示说明规矩本
- **物件获取**：瞎子李给关二狗盒子时，玩家获得第一个关键道具。此时弹出简短提示说明背包
- **任务**：与瞎子李对话结束后，第一个主线任务激活。此时弹出简短提示说明任务面板
- **遭遇**：城隍庙场景中遇到第一个遭遇时刻，自然体验遭遇系统的选项面板
- **商店**：序章中某个时刻路过集市摊贩，可以买东西

每个新系统首次出现时显示**一行文字的操作提示**（如"按R打开规矩本"），只出现一次，不做弹窗教程。

### K4.5 转盘小游戏

#### 设计定位

转盘小游戏是可由外部内容随时调用的轻量抽签/抽奖交互。小游戏本身只负责展示转盘、完成一次随机停针，并发出结果通知；是否消耗资源、是否限制次数、抽中后如何发奖励，都由外部剧情、热区、任务或后续配置负责。

#### 运行规则

- 通过 Action `startSugarWheelMinigame` 打开指定转盘实例
- 进入后切换到 Minigame 状态，阻断玩家场景移动与普通交互
- 玩家点击"开始"后，指针旋转并缓动停止到随机格子
- 扇区 `weight` 不是精确中奖率，而是物理跑道高度倾向：不填或 `1` 表示基准平地，数值越大该格越低、更容易停留，数值越小该格越高、更难停留；`0` 只表示极高坡，不能保证绝对不命中
- 停止后显示本次抽中的格子，并发出 `minigame:sugarWheelResult` 事件通知
- Esc 可关闭小游戏；关闭后恢复进入前的游戏状态
- 转盘素材由运行时直接加载预处理后的轮盘图与指针图，不在代码中裁切原始合图

#### 旋转氛围脚本

转盘旋转过程中可自动播放围观者/参与者的气泡台词，增强现场感与真实感。

- 策划可配置 N 组**氛围脚本**（`atmosphereGroups`），每次抽奖随机选一组（可加权重），整次旋转沿用
- 每组包含四个**阶段脚本**：`start`（开始转）、`spinning`（旋转中）、`slowing`（慢下来）、`stop`（停止）
- 每组可定义**变量表 `vars`**：命名文案池（字符串数组），供步骤内引用，控制整组基调统一又单阶段多变
- 每个阶段是一个**有序步骤列表**（command list），按序执行
- 步骤使用少量固定 opcode（`say`、`pick`、`wait`、`chance`、`when_near_sector` 等），不支持任意脚本
- DSL 解释器与转盘解耦，其他小游戏可复用壳并只注册自己的 opcode
- 不走 ActionRegistry，只在转盘子系统内部调用 `showSpeech` 等接口
- 编辑器糖画转盘页面内提供完整的组列表、变量表、阶段编辑、步骤编辑 UI，禁止策划直接写 JSON

### K4.6 物件检视（Examine）

#### 设计定位

物件检视是**专注态的物件观察/摆弄会话**，不是带胜负的小游戏。玩家把一件物「拿到眼前」查看异常、点热区、按需做上下文操作；可随时退出，无通关/失败结算。

用途覆盖任意可检视主体：盒子、石头、宝物、纸页、古书、鸡、尸体、僵尸等——主体类型由内容数据决定，系统不硬编码物件种类。

#### 运行规则

- 通过 Action `startObjectExamine` 打开指定检视实例（一会话一物）
- 进入后切到专注态（复用 Minigame 状态壳），阻断场景移动与普通交互；Esc / 关闭浮字可随时退出并恢复进入前状态（若囊屉开着，Esc 先关囊屉）
- **呈现（一期）**：单张静帧 + 叠热区。可选 `presentation.upright` 竖放。托底：`backgroundImage`（自定义）> `backgroundPreset`（mud/straw/wood/stone/softGlow）> 默认 softGlow——是搁置面不是 45° 场景虚化。可选 `backgroundBrightness`（亮度乘数，缺省 1；<1 压暗 >1 提亮）、`backgroundScale`（铺开倍率，缺省 1；越大托底纹理越近）。物件与托底之间的接触 AO 走单管线 mask 流程：caster 轮廓烘进降采样 mask，高斯模糊后作为可见度乘回接收面（竖放随最终层变换自动同步）。**AO 的尺寸量一律用真实长度，不用贴图像素**：实例必须声明 `presentation.physicalWidthCm`（静帧横向跨越的真实宽度，厘米）作为物理标尺，`contactAoRadiusCm` 是真实半径（厘米，缺省 2，上限 8），`contactAoIntensity` 是无量纲浓淡（0～3 缺省 1）；爬虫接触影同理走 `crawlers.contactShadow.radiusCm`（缺省 0.3cm）。换一张更高分辨率的静帧观感不变。旧的像素倍率字段 `contactAoScale` / `contactShadow.size` 已废弃，校验器报 error。探入到最近档时托底 BlurFilter 景深糊化，物件与 AO 保持锐利
- **检视氛围（仅本系统，非公共层）**：实例可选 `ambience`。**单位制铁律：物件空间里的长度写厘米（`*Cm`）、速度写厘米每秒（`*CmPerSec`），一律经 `physicalWidthCm` 标尺换算；只有真正无量纲的量（density/intensity/strength/count/秒数/归一化落点）才保留裸数值；镜头微晃与呼吸是观察者的头、不在物件空间，仍是无量纲倍率。** 内容：烛光/月光强弱缓变、云影（`speedCmPerSec`）、尘埃（`dust`：`true`/`false` 或 `{ density, intensity, radiusCm }`）、**苍蝇飞舞**（`flyingFlies`：可配 `count` / `speedCmPerSec` / `roamRadiusCm` / `lengthCm` / `returnSec`）、**爬虫**（`crawlers`：蛆/蜈蚣/甲虫精灵；虫体 `lengthCm`、簇 `radiusCm`、蜈蚣 `speedCmPerSec` 全走真实单位；进场烘焙物件 alpha 导航场，从贴地轮廓爬上身体，对任意静帧剪影通用）。**体表地形**（`crawlers.terrain`）：剪影只说明边在哪、不说明形体，虫子会把物件当平面爬。烘焙时另出一张高度场——宏观取 `dIn` 开方成穹顶（与明暗无关，不被反照率骗），微观取亮度**高通**（细模糊−粗模糊）还原衣褶沟壑。虫子据此上坡减速、顺沟壑走、随坡面侧倾、高处略大。可配 `reliefCm`（体表落差，厘米）/ `grooveFollow`（顺沟倾向 0~1）/ `climbSlowdown`（爬坡阻力 0~2）；`terrain: false` 退回当平面爬。**注意：这是 2.5D 行为层，不含跨面遮挡**——虫子仍整只在物件前或后，「翻过手臂时被近侧挡半个身子」属未做的 L3、镜头微晃（`headSway`）、呼吸感（`breathing`）。全部可配可关；**缺省仅镜头微晃开（amplitude=1），其余关**。F2「检视氛围」Tab 可会话内热调（不写盘）
- **气味**：实例可选 `smell`（接现有 SmellSystem / HUD 气味烟）。配了则进会话 `setSmell`、退会话 `clearSmell`；不配则不碰气味层
- **音效**：实例可选 `audio`（`ambient` 循环音床、`hoverSfx`、`clickSfx`）；缺省全静音；退出必停 ambient
- **沿口探看（观察者模型）**：初始在**沿外最远**（整物入框，视线锁中心，不可扫视）。**滚轮**改探入距离（缓动，往光标兴趣点略偏）。探入后**左键拖动拨视线**（受限幅度 + 阻尼，不是拖画布）。物件与热区固定在物体空间，只动观察者
- **点击与拖动分离**：左键按下后若移动超过阈值，整段手势只算扫视、不触发热区；未超过阈值抬起才算点击命中；沿外拖动超阈值同样吞点击但不产生扫视
- **异常发现 = 纯点击命中**真热区（矩形；可选多边形，命中以多边形为准）。`decoy: true` 的假热区可点、可跑旁白/actions，**不计入**发现进度、不留朱砂、不进异常影子列表
- **异常影子与朱砂**：真热区以无框墨影浮字提示「还有几处蹊跷」；未发现用 `anomalyShade`，发现后改 `anomalyRevealed`（缺省回落 label）。浮字位置由热区 `shadeUiX`/`shadeUiY`（屏幕归一化 0～1）配置，各条原地独立漂浮，不叠成一列。特写退出后在热区上落朱砂点。UI 无边框面板，文案走游戏口吻，不写操作说明书
- **特写旁白**：激活热区/操作后镜头推近该热区（缓动 zoom + 平移，热区撑到视野短边约一半）；热区/操作可配 `narration` 文案（可含 [tag:…]），以无框旁白浮字叠在特写下方（操作配了则覆盖热区的）。动作批播完后露出继续提示，点击任意处拉回特写前的距离与视线；特写中滚轮与拖视锁定。不额外画四周压暗/圈层
- 每个热区可配置**上下文操作**列表（数据驱动）：
  - 未配置或列表为空：默认只有「观察」；激活后直接执行该热区的 `actions`
  - 已配置：先弹出无框念头菜单，再执行所选操作的 `actions`
  - 操作可选 `requiresItem`：背包无此物则该条不出现
- **摸囊用物**：检视内「摸摸囊」打开无框囊屉（不套全局物品栏面板）。选出物品进入持物态，再点热区：命中该热区 `itemUses`（按 `itemId`）则跑对应 narration/actions；未命中则短旁白「用不上」，不记发现
- 无胜负、不强制找完；会话内记录已触发过的**真**热区
- **当全部真热区都已找过至少一次时**，给出一次提示（文案可配），并跑实例 `onAllFound` Action 列表；提示不是结算，玩家仍可继续操作或退出
- **进度与结果一律 Action**：热区/操作的 `actions` 即时生效；真热区首次计入发现时追加跑 `onFound`；检视系统本身不写任务/规矩/叙事进度，也不靠会话 result 事件驱动档案

#### 与小游戏的边界

- 借用小游戏会话骨架（状态压栈、Esc、动作批播放锁、资源 scope），但语义是检视会话，不产出胜负 `level` / 分数
- 背尸等任务态玩法若只需换位面，仍走位面系统，不塞进检视

### K5. 档案系统（六本书）

#### 设计定位

档案系统是**附属收藏机制，不是核心玩法**。所有影响游戏进程的关键信息（任务目标、规矩效果、当前该做什么）都已在任务面板和遭遇选项中直接呈现，玩家不看档案也能正常游玩通关。

档案的价值在于：为愿意深入了解这个世界的玩家提供丰富的、有趣的、有氛围感的扩展内容。翻看这些书本身就是一种体验——像真的在翻一本旧书。

档案分为三类：
- **系统书册**（规矩本、人物簿）：随游戏进程自动填充，玩家可翻阅回顾
- **世界书籍**（见闻录、杂书匣，以及游戏中获得的独立书籍如"僵尸纲要"等）：玩家在世界中发现/获得的实体读物，一页一页翻看，有图有文，内容有趣且可能包含隐藏提示
- **搜集册**（怪话册、歪歌册）：游戏 meta 层的成就式搜集册，有总数、有进度、有空槽、集齐给评语。**不是叙事层的物件**——关二狗是文盲，这两本册子不由他书写，是系统在替他记账

规矩本已在E章节单独定义，以下补充其余内容。

#### 书一：规矩本（已有，见E章节）

收录所有已学规矩和碎片。分类浏览、详情查看、来源和验证状态追踪。

#### 书二：人物簿

记录关二狗接触过的所有人物。

- 首次与某NPC发生对话后，该NPC自动加入人物簿
- 每个人物条目包含：
  - **名字**（或绰号，如"老辫子"、"瞎子李"）
  - **身份简介**（一句话，如"脚帮头领，挖过坟掘过墓"）
  - **关二狗的印象**（关二狗视角的主观评价，随交往深入更新。如初次见面是"看着像个老油条"，后来变成"靠得住的老江湖"）
  - **已知信息**（随对话和事件积累。如"他说过他以前在神仙顶附近挖坟"、"他认识癫子周"）
  - **相关任务**（该NPC参与的已完成/进行中任务列表）
- 人物条目不是一次性写好的，而是**随剧情推进逐步丰富**。新增信息时显示"人物簿更新"提示
- 人物分组：可按"城内"/"脚帮"/"其他"等简单分类浏览

#### 书三：见闻录

记录渝都卫的世界知识：传说、地理、民俗、历史。

- 条目来源：说书人讲述的故事、NPC闲聊中提到的传闻、场景中发现的碑文/告示内容、完成任务后解锁的背景知识
- 每个条目包含：
  - **标题**（如"神仙顶传说"、"阎王岭由来"、"渝都卫白塔"、"赶尸匠的规矩"）
  - **正文**（一段完整的叙述文字，关二狗或第三方视角）
  - **来源**（"张叨叨说书所述"、"码头渔夫提及"、"城隍庙石碑记载"）
- 条目按主题分类：传说/地理/民俗/人事
- 新增条目时显示"见闻录更新"提示
- **说书人的故事是见闻录的主要来源**：每次听完张叨叨一段完整的说书，对应的故事自动录入见闻录。这给了"听说书"一个明确的收集回报

#### 书四：杂书匣

收录游戏中发现的散落文档。

- 来源：场景中拾取的信件、纸条、残页、告示；NPC交给关二狗的书信、凭证；任务过程中获得的文书
- 每个文档包含：
  - **名称**（如"城隍庙墙上的告示"、"不知名的半截信"、"庄老太爷的请帖"）
  - **原文内容**（玩家可以完整阅读文档原文）
  - **关二狗的批注**（可选，关二狗对这份文件的理解或吐槽）
  - **发现地点**
- 文档按发现时间排列
- 新增文档时显示提示
- 部分文档之间有隐藏关联，供愿意深入的玩家自己发现

#### 书五：怪话册（成就式搜集册）

关二狗大字不识一个，正经学问一样没有，可市井上那些骂人的浑话、江湖上的黑话、他自吹的"道行"，倒是一句不落全记着。这本册子就是**系统一本正经替这个文盲记的"学问"，记下来的全是些啼笑皆非的东西**。

**笑点引擎（设计的第一原则）**：**系统越一本正经，内容越不成器**。词条正文一律用考据体（对标见闻录/《风物志》的口吻：语源、用法、地域分野），末尾一句备注把它砸掉。所有设计取舍都往这个反差上使劲——正文越像正经辞书越好笑。

**收什么**（四类，均为分类浏览）：
- **骂法**：锤子／哈儿／宝器／龟儿／戳锅漏／背时等市井骂詈
- **隐语**：袍哥、脚帮、码头的江湖黑话（关二狗多半只学了个半吊子）
- **道行**：他自称的本事、把李天狗的告诫反读成"向我请教"那一类自吹
- **典故**：从说书人那儿听来又记岔了的正经典故

**每条包含**：
- **词条**（那句话本身，如"说聊斋"）
- **正文**（考据体释义：语源、市井用法、成渝分野）
- **例句**（关二狗声口的实际用法，取自重庆话语料库的活范本）
- **来源**（跟谁学的——"码头脚帮"／"被官差撵的时候听来的"／"李天狗骂他的原话"。最后这类是笑点富矿：人家骂他，他当学问收藏了）

**进度与成就**：
- 册子顶部常驻**总进度 `已记 N / 共 M`**
- 未收集的条目**显示为灰槽**（写"还没听人说过"），不隐藏——空槽是驱动力
- **单个分类集齐 → 一句嘲讽评语**（如骂法集齐："嘴上功夫已臻化境，可惜没一句能当饭吃。"）
- **全册集齐 → 最重的一句评语**，留到终幕

**为什么这本可以露空槽（与规矩本的分野）**：规矩本红线是"未掌握层零像素、不列未知条目"，那条红线保护的是**案件知识不许剧透**。怪话是纯 flavor、有限集合、零剧透风险，所以成就册那套（总数／空槽／集齐提示）在这本里全部成立，两本册子不同构是**有意的**。

**红线：只能读，不能用。**
- 不做"集齐 N 条解锁某能力"、不做"学会某句才能选某对话选项"、不做任何以词条为前置的检定
- 集齐的奖励**只能是文案**（系统损他那句话）+ 格子填满本身
- 违反此条即等于把已被否决的"骂人技能系统"（话术本／气条／情境克制表）从后门放回来，见 L 章"决定不做的东西"

**获取方式**：走档案通用的声明式解锁条件（听到某段对话、经过某个场景、完成某任务），也可由 `addArchiveEntry` 动作显式解锁。

#### 书六：歪歌册（2026-08-17 拍板；成就式搜集册）

关二狗打小在院坝头、码头边听来的那些**歪童谣、荤口顺口溜**——大人逗娃儿念的、娃儿跳皮筋唱的、越念越不对劲的连锁调。和怪话册一样，这本也是**系统替文盲记账**：他一个字不识，倒被系统替他存了一册没人肯写进书里的活口传。

**收什么**：民间连锁调式的歪歌——拍手歌的失传变体、荤口逗娃谣、念到后头就滑进诡异领域的顺口溜。**暂不分类**（flat 列表；数据结构预留分类键位，条数多了再切）。

**每条包含**：
- **标题**（如"张打铁"）
- **全文**（顺口溜完整原文，多行）
- **来源**（在哪听来的，采风口径——"院坝头娃儿跳皮筋唱的"一类）
- **备注**（可选，关二狗声口的吐槽注）

**进度与成就**：与书五同构——总进度 `已记 N / 共 M`、未收集灰槽不隐藏、全册集齐给一句评语。暂无分类故无分类评语。露空槽的理由同书五：纯 flavor、有限集合、零剧透风险。

**内容口径（硬约束）**：
- **宁冷勿俗**：只收搜索引擎搜不到的冷门口传货，不收曝光度高的"金曲"名段——被认出来的一瞬间就出戏。允许"人人会唱的开头 + 各处失传的尾巴"这类活变体，落差本身即歪歌体验
- **注释绝不提张献忠／谶谣／屠蜀**：雷区不在素材在注释姿态，童谣本身无立场，考据注不把历史人物请进文本就没有靶子。适用于本册所有条目的正文／来源／备注
- 该类内容**永不童声配音**；本地化走译者注式意译不逐字直译；Steam 商店内容问卷如实勾"频繁粗俗语言"

**红线：与书五完全一致——只能读，不能用。** 不做以歪歌为前置的任何检定／解锁／能力，违者即"骂人技能系统"还魂，见 L 章。

**获取方式**：走档案通用的声明式解锁条件，也可由 `addArchiveEntry` 动作（bookType `rhyme`）显式解锁。不经 cutscene 发放（过场禁改存档）。

#### 书七：独立书籍（世界中获得的实体书）

游戏世界中关二狗可以获得一些完整的"书"，每本书是一个独立的可翻页阅读物。

- 示例：
  - **《僵尸纲要》**：记录各种僵尸的类型、特征、民间应对法。一页一个种类，有简笔插画和文字描述
  - **《渝都卫县志残本》**：破损不全的地方志，记载了渝都卫的地理、历史、大事件，部分页面缺失或被撕去
  - **《赶尸匠手札》**：某个赶尸匠的工作笔记，记录了他走过的路线和遇到的怪事
  - **《张叨叨话本集》**：说书人张叨叨讲过的故事合集，听过的故事自动收录
- 获取方式：任务奖励、NPC赠送、场景中发现、商店购买
- 每本书的呈现方式：
  - **翻页式阅读**：左右翻页，每页有内容（文字为主，可配简单插画）
  - 未解锁的页面显示为空白或"此页缺失"（随剧情推进、完成特定任务后解锁新页面）
  - 书的总页数和已解锁页数显示在封面上，给收集感
- 独立书籍获得后加入书架，和固定书册并列
- **书中的内容可能隐含实用提示**（如僵尸纲要里提到"白毛僵尸怕火"），但不是必须阅读的——同样的信息会通过NPC对话或遭遇选项提供给玩家

#### 书架UI框架

- 按快捷键打开"书架"界面，显示所有书的封面/书脊

- 点击某本书进入该书的浏览界面：
  - 规矩本/人物簿/见闻录/杂书匣：条目列表式浏览（见各自UI描述）
  - 怪话册：分类分组列表 + 顶部总进度 + 未解锁灰槽（见"书五"）
  - 歪歌册：单列表 + 顶部总进度 + 未解锁灰槽（见"书六"）
  - 独立书籍：**翻页式阅读**（左右翻页，模拟实体书手感）
- 书架界面暂停游戏
- 所有书的数据存入存档

#### 翻页阅读器（独立书籍专用）

- 左右翻页操作（键盘左右键 / 鼠标点击页面左右侧 / 滑动）
- 每页显示内容：标题区 + 正文区 + 插画区（可选）
- 未解锁的页面显示为空白/破损/缺失
- 页码显示（当前页/总页数）
- 翻页有简单的翻页动画

#### 数据格式

- **人物数据**（JSON）：所有NPC的人物簿条目定义，各阶段的信息内容和解锁条件（标记）

### K7. 线索标记与采集（2026-08-17 UI 深审落地）

#### 设计定位

玩家在**读文本**（档案册、成书、告示、日后扩展到对话）时，看到被标记的词条可以**点一下记下来**——"我注意到这个了"。采集到的线索进**线索簿**（书架第七本），并以全局 flag 的形式喂给现有条件系统：对话分支、档案解锁、任务触发都能拿"玩家注意过某线索"当前置。

与档案系统（K5）的边界：档案是**给的**（系统替关二狗记账），线索是**玩家主动摘的**——它是阅读行为的最小互动化，不是推理台（推理系统仍在 L 表的永久禁令语境之外单议）。线索**只作条件面**，不给任何数值能力（与怪话册同一条"搜集不给能力"红线）。

#### 数据与标记

- 线索注册表 `public/assets/data/clues.json`：`{ id, title, desc, category, collectActions?, hidden? }`；id 全局唯一，校验器把关。
- **采集 = 内容事件，不是"往册子里加一行字"**（2026-08-17 拍板）：`collectActions` 是首次采集时经统一动作执行器执行的动作批——解锁文书、推 flag/信号、起对话、给任务，任何机制通道效果都行。落 flag / 回执 / 入线索簿只是**系统默认呈现**；`hidden: true` 的纯机制线索连册子都不进（采了只走动作，不留字面）。幂等由 flag 检查保证，动作批只发一次。
- 文本内以第三层标记 `[clue:<id>]…[/clue]` 圈词（与 `[tag:…]` 引用层、`[c:…]` 样式层并列；实现共用同一分词器）。
- 采集状态 = 全局 flag `clue_<id>`（H2 的统一标记系统，**不另设存档桶**——统一存储唯一真相源）。
- 内容侧也可经动作（collectClue）直接授予（如对话里"关二狗记住了"），与点击采集同一通道、幂等。

#### 交互（方案A，静态册面先行）

- 未采集：词条呈线索苔绿（`[c:clue]` 色板），悬停亮起 + 下划琥珀短线；点击 = 采集——词条闪金一下、右侧冒「已录线索」回执（notification `clue` 类型），词条转暗金常驻。
- 已采集：暗金色、仍可点（无副作用，幂等）。
- 落点顺序：**先落静态文本面**（档案册右栏 / 成书内页——无打字机、无点击推进冲突），再落对话框。
- **对话框（二阶段，2026-08-17 落地）**：渲染一个字都不动（正文仍是单 `Text` + 打字机），只在其上盖一层透明命中框；命中框的位置**问回 Pixi 自己的折行结果**推算，不另写一套排版。三条交互纪律：
  - **整句显示完才可点**——"点一下记下来"是对一句已经读完的话做的动作，给还在往外蹦字的半句挂词条只会让人误点；
  - **点词条不翻页**——那一下被标记为已消费，对话框的推进监听据此让路（否则就是"记下了同时把这句话翻过去了"）；
  - 已采集在对话框里**用常驻暗金下划线**表示，不是像册页那样转字色——单 `Text` 改不了其中一段的颜色，下划线是这块 UI 能给出的同义表达。
- 线索簿（书架第七本）：按 category 分组列出**已采集**的线索（未采集不占位、不给总数——线索的存在本身可能剧透，与怪话册的灰槽刻意不同构）；条目正文 = desc + 采集出处不追溯（保持轻量）。

#### 红线

- 线索不给能力、不做数值；条件面消费一律走既有 ConditionExpr（flag 叶）。
- `[clue:]` 引用不存在的 id：校验器 error（引用完整性与 [tag:] 同级）。
- 剥标记的默认路径（存档/日志/比较）必须把 `[clue:]` 一并剥净——玩家永远不该看见裸标记。
