## 新电脑继续的步骤

已有仓库先确保没有会被覆盖的本机改动，然后：

```sh
git fetch origin
git switch codex/living-open-world
```

没有本地分支时：`git switch --track origin/codex/living-open-world`。第一次搭建按项目 `README.md` 的 bootstrap 流程准备解释器与依赖，并通过项目已有方式配置 OSS 凭据。

Windows 项目解释器可用后：

```powershell
.tools/venv/Scripts/python.exe -m tools.dev pull --editor
npm run dev
```

macOS/Linux：

```sh
./dev.sh pull --editor
npm run dev
```

不要裸 `dvc pull`；项目同步器负责 OSS 大文件传输。需要配音原始源时另加 `--audio`；普通游戏和本次编辑续做不必因此下载配音原始库。

续做先读：本文件 → `CLAUDE.md` → `docs/玩法功能需求清单.md` B3.2/E2 → `IMPLEMENTATION.md`/`NETWORK.md`，再按要改的文件运行知识库 audit。

调试入口：`http://127.0.0.1:5173/?mode=dev&ndbg=0&narrativeWarp=开放雾津`。它是章节夹具，不能用于宣称普通新游戏通关。正式流程验证仍须正常开局。

## 给下一位代理的操作注意

- `artifact/OpenWorld/build_*.py` 是离线作者记录，游戏只读原生 JSON。**不要批量重跑旧脚本**：同一 NPC 菜单、作息和事件后来被其他批次扩展过，重跑会覆盖更新。当前磁盘数据优先。
- `browser_driver.py` 旧辅助脚本写死本机 Playwright Chromium 可执行文件路径，换机先选本机实际浏览器路径；不要照抄 `C:/Users/...`。使用项目命令通道和固定帧驱动，保持真实碰撞和真实输入。
- 判断切场/换时段完成须等 `currentSceneData.id`、`!isSwitching`、`!phaseSwapInFlight`、`!pendingPhaseSwap`，`player_driver.js` 的 `settleScene()` 已加该检查。NPC 显隐读 `npc.container.visible`，不要读不存在的 `npc.visible`。
- rAF/异步操作超时不会自动取消页面操作；先查询原句柄与当前状态，不能因观察超时重复扣物动作。每段重要结果立即落盘，服务可能在宿主消息边界结束。
- 本轮目标仍未完成。用户当前要求换机保存，提交消息与后续汇报都应标为 checkpoint/WIP，不能标为完整开放世界交付。
