# 实体局部状态机（绑定即实例化的私有机器）— 技术设计 v1（2026-08-08）

> 前置：`agent_docs/runtime/mechanisms/narrative-signal-spine.md`（5 层脊椎）、
> `artifact/Design/叙事运行实例化-技术设计-2026-07-17.md`（活计图 v2 契约，本文沿用其 instanceId 缝）。
> **制作人拍板要点（2026-08-08 对话）**：
> ① 状态机是独立可复用资产，实体绑定即实例化——不是 100 个实例写 100 张图；
> ② 实例状态**完全私有**，外部不可见、不可寻址，只经信号交流；
> ③ 局部变量要有——底层是全局存储，local 是上层作用域封装（"汇编层没有天然 local"）；
> ④ 局部层用**命令式直接转移**，不用信号——信号存在的理由是大规模解耦，实例内没有距离要跨；
> ⑤ 必须改现有状态机、与其自洽，**不造第二套系统**。

## 0. 一句话

叙事状态机新增第三类图——**局部机原型**：作为可复用资产定义一次，任意实体在自己的 def 上
绑定它，绑定即在该实体上实例化一台私有机器。实例有自己的当前态与变量表，内部走命令式转移，
对外只经全局信号进出。

## 1. 概念模型

### 1.1 图三类（原有两类语义分毫不变）

| 类 | 声明 | 实例数 | 身份 | 可被外部按 id 寻址 |
|---|---|---|---|---|
| 常驻图 | 无 `run` / 无 `local` | 恒 1 | graphId | 是（`narrative` 叶） |
| 活计图 | `run: {...}` | 至多 1（全局单激活槽） | graphId | 是 |
| **局部机原型** | `local: {...}` | **0..N（每绑定点一台）** | `<machineId>@<host>` | **否** |

### 1.2 三条硬边界（局部机之所以"局部"）

1. **不进 owner 索引**——`@owner` / `@scene` 解析不到它，`getPrimaryGraphByOwner` 看不见它。
2. **不发 `state:<id>:<态>` 派生广播**——`broadcastOnEnter` 在局部机上是**校验 error**。
   要对外说话，走 §4 的显式导出信号。
3. **`narrative` / `narrativeCount` 条件叶不接受局部机 id**——校验 error。外部永远问不到
   "那个箱子什么状态"，这是刻意代价，换掉整个寻址与命名膨胀问题。

**但"私有"不等于"连自己都读不到"**（v1 初稿的设计错误，验收 B3 打回）：宿主实体读自己
绑的那台机器是**必须**的能力，否则实体显隐只能靠 `onEnterActions` 写全局 flag 表达，
本功能要消灭的 `箱子状态_<id>` 命名膨胀原样回来。故补第四条：

4. **宿主自读**：`selfState` / `selfVar` 两条叶子只在**实体自己的 `def.conditions`** 里合法，
   解析为"我绑的那台机器"。不接受任何实例键、不接受指定别的实体——正如 OOP 里对象读
   自己的私有字段：外人不行，`this` 天经地义。私有性（外部不可按 id 寻址）完好。

### 1.3 实例身份

实例 id 由系统机械生成，**作者从不书写**：

```
<machineId>@<sceneId>/<entityKind>:<entityId>
```

`@` 已是图 id 的保留禁用字符（活计图设计 §5.6 定的，现网 0 处），可安全用作实例分隔符。

**已知代价（v1 初稿写反了，验收 H2 纠正）**：键由绑定关系推导，**数据文件侧**改名走实体重构
引擎能机械跟随；但**存档侧不跟随**——重构引擎只改数据不改档，scenes 无 migrations 机制
（见 `entity-refactor-engine` 卡）。反倒是作者手写的 flag 键**有** `flag_registry.migrations`
兜底。所以"比 flag 键更抗重构"这句是错的：改名/删实体会让老档里该实例的状态失联。
要么后续给 locals 补一层实例键 migrations，要么接受这条代价（同 sceneMemory 的现状）。

## 2. 数据契约

### 2.1 原型声明（narrative_graphs.json，新 element kind `localMachine`）

```jsonc
{
  "id": "lm_可拾取物",
  "ownerType": "system",            // 局部机不绑 owner，恒 system
  "local": {
    "vars": [                        // 实例变量表声明（类型+默认值，实例只存当前值）
      { "key": "peeked", "type": "bool",  "default": false },
      { "key": "kicks",  "type": "float", "default": 0 }
    ],
    "listens": ["第三章开始"],        // 显式声明监听的全局信号（索引用，校验用）
    "emits":   ["箱子_已取"]          // 显式声明导出的全局信号
  },
  "initialState": "inactive",
  "states": { "inactive": {...}, "active": {...}, "done": {...} },
  "transitions": [ /* 见 §3 */ ]
}
```

### 2.2 绑定（实体 def：NpcDef / HotspotDef / ZoneDef）

```jsonc
{
  "id": "hs_铁箱",
  "machine": "lm_可拾取物"        // 绑定 = 实例化。一实体至多一台（见 §7 开放项）
}
```

### 2.3 存档

局部机实例挂在 **`narrative.locals`** 一张表下（不进 `activeStates`）。分表的真实理由
（v1 初稿引错了 API，验收 M1 纠正——`getActiveInstanceStates()` 全项目零调用方）：
**`getGraphs()` + `getActiveState()` 才是要设防的遍历点**，PlaneReconciler 正是走这条路
全量派生位面；实例混进 activeStates 会被它当全局图消费。

```jsonc
"locals": {
  "lm_可拾取物@雾津街头/hotspot:hs_铁箱": { "active": "done", "vars": { "peeked": true } }
}
```

- **只存偏离默认的**：`active === initialState && vars 全默认` 的实例**不落盘**（1000 个没碰过
  的箱子 = 存档 0 条目）。这条是数据面膨胀的正解——底层全局，但只为真实发生过的事付费。
- 读档时按当前绑定关系重建：存档里有、现网已无绑定的条目丢弃并记 issue（同 `save.runs.*` 口径）。
- `migrations` 增 `machines` 一层（原型改名），实例键由绑定重推，不需要单独迁移。

### 2.4 破档级字段（硬约束）

原型的 `initialState` 与各 var 的 `default` 是**破档级字段**：因为出厂态不落盘，改了默认值
会让老档里所有未落盘的实例**静默改判**（1000 个箱子的 `peeked` 可能从 false 翻成 true），
且 `migrations.machines` 只管原型改名、救不了这个。改这两类字段前必须评估存量档。

## 3. 局部层 = 命令式（不是信号）

局部机的 transitions 只有两种触发方式：

| trigger | 语义 | 作用域 |
|---|---|---|
| `local`（新增） | 由 `localGoto` 动作**直接点名目标态**触发 | 实例内，确定性同步 |
| `signal` | 监听全局信号（`local.listens` 声明过的） | 全局总线，一对多广播 |

**`local` 型不进队列、不做匹配、不排空**——`localGoto` 直接改本实例的态并跑 onExit/onEnter。
因此局部层没有时序不确定性：现有那套"同一信号到多图先后无稳定序""动作内发射插队"的坑，
在局部层结构性不存在。

`reactive*` 在局部机上是**校验 error**：reactive 的存在理由是"条件何时满足不可预知"，
局部层作者对着整台机器写，要什么直接 goto。

**递归守卫**（实现已落地，v1 文档漏写）：命令式层没有队列兜底，`MAX_LOCAL_GOTO_DEPTH = 16`
拦住 `A.onEnter→goto B、B.onEnter→goto A` 这类互相 goto；超限 fail-loud（error issue + warn）。
`localGoto` 目标态 === 当前态时幂等短路，不重跑生命周期动作。

### 3.1 动作三条（全走相对 self 解析，作者不写实例 id）

| 动作 | 参数 | 语义 |
|---|---|---|
| `localGoto` | `state` | 把**当前 owner 实体**的机器转到 state |
| `setLocalVar` | `key`, `value` / `delta` | 写本实例变量 |
| `emitNarrativeSignal` | 既有 + `bindSource?: bool` | 导出信号，可选附带宿主身份 |

self 解析复用现成管线：`ActionExecutor.executeBatchFromOwner` 已经在线程化 ownerType/ownerId
（`actionOrigin.ts` 是唯一判定源），局部动作按该 owner 找到宿主实体、再找到它绑的实例。
拿不到 owner = 记 issue 跳过（fail-loud，不猜）。

### 3.2 局部变量的条件叶

```jsonc
{ "localVar": "kicks", "op": ">=", "value": 3 }
```

**只在局部机自己的 transition 条件里合法**（其它容器出现 = 校验 error）。求值时
`ConditionEvalContext` 注入 `localVars`（当前实例的变量读取器）——沿用
`currentOwner` / `@owner` 那条「相对 token 靠上下文解析」的现成范式，不新造机制。

### 3.3 宿主自读叶（读侧，验收 B3 补）

```jsonc
{ "selfState": "active" }                          // 我绑的机器是否处于该态
{ "selfVar": "peeked", "op": "==", "value": true }  // 我绑的机器的实例变量
```

**只在实体自己的 `def.conditions` 里合法**。求值时由 InteractionSystem 逐实体注入
`selfHost`（谁的条件正在被判）+ `selfLocal`（读取后端）；两者缺一恒假（fail-closed）。
这是实体显隐能继续走「每帧按 conditions 派生」模型的前提——没有它，箱子的显隐只能靠
`onEnterActions` 写全局 flag，命名膨胀原样回来。

## 4. 对外接口 = 信号（唯一出入口）

- **进**：全局信号广播到所有监听它的机器实例，各自在自己机器里匹配转移。
  "第三章开始 → 1000 个箱子全激活"命名成本 = 1。
- **出**：`emitNarrativeSignal` 进现有全局总线，语义一字不改。
  `bindSource: true` 时填 `sourceType: 'entity'`, `sourceId: '<sceneId>/<entityId>'`；
  否则匿名发。**身份 ≠ 状态**——外面知道谁发的，仍看不见它的态与变量，封装不破。

### 4.1 信号扫描的性能门

现有 `processTrigger` 每信号遍历全部图。1000 个实例不能这么扫。新增
`signalKey → Set<machineId>` 索引（`registerGraphs` 时建、失效同 `listenedSignalKeysCache`）：
一条信号只访问**声明监听它的原型**的实例集，其余零成本。常驻/活计图路径完全不变。

## 5. 生命周期

- **实例化时机**：场景装载时按实体 def 的 `machine` 建实例（默认态+默认变量），
  已有存档条目则覆盖为存档值。
- **卸载**：实例**留在表里**，只把 `loaded` 标为 false（v1 初稿写的"出表"是错的，验收 B1 打回：
  出表会让不在场实例永久漏投批量激活，而局部机禁 reactive、没有补评通道自愈）。
  语义定为：**状态迁移永远发生，生命周期动作只在在场时跑**——玩家走到时看到的是已经
  激活好的箱子，而那一刻本就不该放的演出也确实没放。装载时 `reconcileLocalInstances(sceneId)`
  认领本场景实例（存档回灌的实例默认 `loaded:false`，等认领）。
- **destroy / 代际**：局部实例表随 `invalidateInFlightTimeline` 一并处理；`registerGraphs`
  清空重建。norms 不变量 4/5 逐条对齐。
- **实体被删/改名**：走实体重构引擎，实例键机械跟随（§1.3）。

## 6. 三面校验（TS 权威 → Python 子集 → validator.py）

1. `local` 声明形状；`vars` key 唯一、type ∈ bool/float/string、default 与 type 相符。
2. 局部机上 `broadcastOnEnter` / `reactive*` / `activePlane` / `ownerId` = **error**。
3. `narrative` / `narrativeCount` 叶指向局部机 id = **error**。
4. `localVar` 叶出现在局部机之外 = **error**；key 未在 `vars` 声明 = **error**。
5. `localGoto.state` 必须存在于**绑定到该调用点的**机器（跨绑定点静态可解时校验，不可解时 warning）。
6. 实体 `machine` 指向不存在/非局部机原型 = **error**。
7. `local.listens` 与实际 transition 监听键不一致 = **warning**（声明漂移）。
7b. `selfState` / `selfVar` 叶出现在**实体 def 之外**（叙事图 / 对话图 / 任务条件）= **error**；
    `selfVar` 的 key 未在该实体所绑原型的 `vars` 声明 = **error**（绑定静态可解时）。
7c. 实体声明了 `selfState`/`selfVar` 条件却**没绑任何机器** = **error**（写了永远为假的条件）。
8. 局部机导出信号无人监听 = 沿用现有 `signal.unlistened` 口径。

## 7. 明确的开放项（需制作人拍板，不猜）

1. **一实体能否绑多台机器**？本文按「至多一台」设计（最简、够用）。要多台则实例键需再加
   槽位、且 §3.1 的 self 解析要带槽名消歧。
2. **动态生成实体**（非场景摆放）的实例键与回收策略——本文不覆盖，届时另立。
3. **局部机能否嵌套**（机器里的状态再绑一台机器）——本文明确不支持，校验拦。
