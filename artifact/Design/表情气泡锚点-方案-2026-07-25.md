## 1. 现象

对话播放时会在说话实体头顶挂一个 `……` 气泡指示"谁在说话"。有的角色气泡位置**完全不对**——飘在头顶很高的地方，尤其在播了某些动画之后。

## 2. 根因（已定位，不是"位置没调好"）

气泡锚点走 `getWorldSize()` → `quadTopLocalYAroundFoot()`：

- `Npc.getEmoteBubbleAnchorLocalY()` — `src/entities/Npc.ts:329`
- `Player.getEmoteBubbleAnchorLocalY()` — `src/entities/Player.ts:128`
- 消费方 `EmoteBubbleManager` — `src/systems/EmoteBubbleManager.ts:107,128,226`

而 `SpriteEntity.getWorldSize()`（`src/rendering/SpriteEntity.ts:395`）返回的是 **anim.json 的 `worldWidth/worldHeight` 常量**——这是**整张图集的格子尺寸**映射，per-atlas 恒定，**与当前播的是哪一帧无关**。

图集打包时（`tools/video_to_atlas/atlas_core.py:290` `pack_frames_native_equal_cells`）：

- `cell_h = 全图集最高帧内容高 + 2*pad`
- 每帧**底边对齐、水平居中**贴进格子（`py = cell_h - pad - h`，`px = (cell_w - w)//2`）

所以矮帧上方全是透明留白，而 quad 顶边照样在格子顶。

### 实测数据（`player_anim`，cellH=204 / worldH=150 / pad≈7.5）

| 状态 | 当前帧内容高 | 气泡比头顶高出 |
|---|---|---|
| idle / stand | 182 | ~11 世界 px |
| slow_walk / walk | 173–182 | ~11–18 px |
| run | 150–166 | ~28–34 px |
| crouch | 112–182 | 最多 ~62 px |
| **lie_down / hero_sleep** | **36–179** | **最多 ~118 px** |

全部 38 个角色图集同规律：最矮帧只占格高 16%~25%。躺尸/睡觉状态角色只剩 ~26 世界 px 高，气泡还挂在 118 px 上——就是"完全不对"的来源（背尸/路倒/hero_sleep 这些戏正好都用这些状态）。

### 关键事实：修复所需数据**已经存在**

`anim.json` 的 `atlasFrames[i].contentWidth/contentHeight` 就是每帧 alpha 裁切后的真实内容尺寸（类型见 `src/data/types.ts:994` `AtlasFrameBoxDef`）。不需要重烘图集。

`pad` 未入 JSON，但可在加载时反推：`bottomPad = (cellH - max(所有帧 contentHeight)) / 2`。

## 4. 拍板的语义

### 4.1 X 与 Y 分开对待

- **X**：基准恒为"实体中心"，全局值本来就是 0 → `anchorOffsetX` 保持 delta 语义**不动**。
- **Y**：基准是"当前生效头顶锚"，是随角色/状态变的活值 → 换**绝对锚**语义。

### 4.2 新增 `bubbleAnchorY`，不迁移旧键

新增键 `bubbleAnchorY`（世界 px，脚点为 0，向上为负），**保留 `anchorOffsetY` 不动**：

- 两键并存时：绝对锚 `bubbleAnchorY` 定基准，`anchorOffsetY` 叠加其上。
- 旧数据零迁移，那唯一一个 `-20.0` 继续有效。

### 4.3 统一锚点解析链（所有 UI 的地基）

一个纯函数，运行时 TS + 编辑器 Python 各一份，用 parity 测试锁死（照 `expandExtends` 位面槽的既有套路）：

```
resolveBubbleAnchorY(实体, state, frameSlot) =
  ① 调用点覆盖  bubbleAnchorY（本行 / 本 action step）
  ② 图集授权锚  anim.json states[s].bubbleAnchor      ← P4
  ③ 内容框自动  atlasFrames[slot].contentHeight        ← P1
  ④ 格子 quad   worldHeight                            ← 兜底（8 个 fx_* 图集无 atlasFrames）
```

上层永远拿到"绝对锚点 Y"，所以 UI 里"展开就是当前生效值"天然成立。

### 4.4 控件行为（三处 UI 统一）—— 用户明确要求

| 状态 | 显示 | 写盘 |
|---|---|---|
| 默认（未覆盖） | 灰色只读，显示**当前生效绝对值** + 来源芯片（`自动(内容框) −186` / `图集锚点 −172`） | **不写键** |
| 勾"覆盖本行/本步" | 变可编辑，**初值 = 刚才那个生效值**，直接微调 | 写 `bubbleAnchorY` |

**红线：绝不允许初始化成 0 让用户从零调。** 这是位面编辑器"显式配置此槽"闸门的既有范式（`agent_docs/editor-tools/mechanisms/plane-editor-slot-inheritance.md`）。

## 5. 分期施工计划

### P1 — 运行时锚到"当前帧可见内容顶边"（纯运行时，改完躺尸立刻正常）

1. `SpriteEntity` 加 `getContentTopLocalY()`，紧挨已有的 `getCurrentFramePixelSize()`（`src/rendering/SpriteEntity.ts:487`），槽位查法完全复用（`slot = currentFrameDef.frames[frameIndex]`）：
   - `loadFromDef` 时算一次缓存 `bottomPad = max(0, (cellH - max(所有 contentHeight)) / 2)`
   - `contentTopLocalY = sprite.y - (bottomPad + contentH) * (worldHeight * depthScaleFactor / frameH)`
   - `sprite.y` 那项把**跳跃弧线视觉抬升**算进去（现在 `jumpTo` 期间气泡不跟着起跳，同一 bug 的另一面）
   - 无 `atlasFrames` / 数据非法 → 返回 null，调用方回落旧 quad 口径
2. `src/utils/entityTransform.ts` 加 `contentTopLocalYAroundFoot(effContentW, effContentH, effBottomOffset, rotationRad)`：内容框是"离脚点抬起 bottomPad 的内缩矩形"，旋转实体按四角变换取 min y。
3. `Npc` / `Player` 的 `getEmoteBubbleAnchorLocalY()` 改调它，`× entityScaleOf(def)` 的口径**照抄 `getWorldSize()`**。
4. **不动 `getWorldSize()` 本身** —— 阴影 / 深度排序 / 像素密度匹配 / AO 都吃它，动了影响半径失控。只加新方法。
5. `EmoteBubbleManager.update()` 的 `follow` 分支加一档 lerp（挂载时 snap，之后每帧向目标插值 ~20%），压掉逐帧 contentHeight 抖动。注意 lie_down 的"跟着尸体落地"是**正确行为，必须保留**，别做成常量。

## 9. 落地注记（2026-07-25 施工完成）

### 最终解析链（运行时与编辑器双侧同口径，parity 测试锁定）

```
① 调用点覆盖   EmoteBubbleOffsetOpts.anchorY（图对话行/节点 bubbleAnchorY、action bubbleAnchorY）
② 图集授权锚   anim.json states[*].bubbleAnchor（格高归一化比例，per-state 常量）
③ 内容框自动   atlasFrames[slot].contentHeight → 当前帧可见内容顶边（默认档）
④ 格子 quad    worldHeight（图集无 atlasFrames 时的兜底，8 个 fx_* 包走这里）
```
`anchorOffsetX/Y` 语义**不变**，仍是叠在上述结果之上的相对微调。

### 气泡大小（同日追加）

与锚点**共用同一套阶梯**，但基准不同——大小的"全局值"是真有一个配置项：

```
① 单处覆盖  action 的 bubbleScale / 对话行·节点的 bubbleScale
② 全局缺省  game_config.emoteBubbleScale（缺省 1，夹取 0.3~4）
```

- **按新字号重排，不是拉大 20px 的字**：`fontSize/padX/padY/圆角/描边` 一起 × k，
  Pixi 的 `Text` 是纹理，`container.scale` 放大必糊。
- 全局值改动**只影响此后新建的气泡**，不重排已挂出的（会让正在显示的气泡跳一下，且没人需要）。
- 大小和位置在编辑器里是**同一个控件**（`bubbleScale` 与 `bubbleAnchorY` 共用一个
  `BubbleAnchorPickField` 实例，登记两个参数名）——因为左边那块预览必须同时反映两者，
  拆成两行两控件就又看不见了。
- 气泡底边恒贴锚点：放大只往上长，不会把锚点顶歪（实测偏移恒 0）。
- **基准量 2026-07-25 整体减半**（fontSize 20→10 / padX 8→4 / padY 4→2 / 圆角 6→3 / 描边 1→0.5）：
  原尺寸在 1024×768 视口下压掉大半个角色。这是**基准**不是参数——`emoteBubbleScale`
  与单处 `bubbleScale` 仍以新基准为 1 倍往上乘。运行时 `BUBBLE_*` 与编辑器预览
  `_BUBBLE_*` 是手工镜像，**改一处必须改两处**，否则预览撒谎。

### 不要回退的决定

- **控件展开显示的是当前生效的绝对值**，勾「覆盖」从该值起步；未覆盖不写键。
  取不到预览对象时用参考角色身高兜底，**任何路径都不许初始化成 0**（用户点名的红线）。
- **X 保持 delta 语义**：它的基准恒为实体中心，0 就是全局值，不需要绝对化。
- **躺倒时气泡跟着尸体降下来是正确行为**，别为"稳定"改成 per-state 常量——
  state-max 会取到躺倒前的站立帧，等于没修。平滑只加在锚点项、**不加在实体位置项**
  （否则气泡会拖在走路的角色身后）。
- **`getWorldSize()` 一行没动**：阴影/深度排序/像素密度匹配/AO 全吃它。
- 重导出并回人工字段的登记面是 `atlas_core.PRESERVED_STATE_FIELDS`，新增此类字段要同步补。
- **`bubbleScale` 必须登记进 `_param_widgets`**（哪怕它不单独建控件）：action 编辑器的收集
  循环以 `_param_widgets.get(pname)` 有无为准，缺登记会在 `if w is None: continue` 处被整个
  跳过、值静默丢掉——这坑本轮踩过一次。
