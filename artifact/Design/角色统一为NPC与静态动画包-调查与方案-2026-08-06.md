# 角色统一为 NPC + 静态动画包（单图占位包）— 调查与方案

日期：2026-08-06 ｜ 状态：**待拍板**（本文只出方案，未动任何代码/数据）

需求原话：*「动画管线也能够直接导出只有一个静态图片的动画包，作为一个单独的动画 state，
主要用于占位和优化。把所有的角色全部统一为 npc。先占位用于编排剧情，然后可以统一出资源。」*

---

## 一、结论摘要

1. **运行时已经天然支持单帧动画包**，不需要改渲染层。`SpriteEntity.update()` 在
   `currentFrames.length <= 1` 时直接短路（`src/rendering/SpriteEntity.ts:462`），
   1×1 图集、1 帧 state 是合法且最省的形态。**当前仓库 46 个动画包里一个都没有**，
   所以是新形态、要真机验一次，但不是新机制。
2. **缺口只在产线出口**：工作台的静态支线 `A→B→C→H_STATIC` 只吐**裸 PNG**
   （`workbench_stages.py:1047 write_h_static_stage`，逐字节复制到
   `public/resources/runtime/images/`），没有"出成动画包"这条出口。补一个
   `H_STATIC_BUNDLE` 适配器即可，**核心打包函数 `pack_common_cell_states` 可直接复用**。
3. **"统一为 NPC"的范式已经入库、不是新发明**：装饰 NPC = `animFile` +
   `interactionRange:0` + `castShadow:false` + 无 `dialogueGraphId`
   （`agent_docs/asset-pipeline/recipes/ambient-fx-production.md` 第 5 步）。
   现在缺的只是"每个角色都有一个包可给"。
4. **两个真实缺口，必须一起解决**（不解决则迁移会掉表现）：
   - **`NpcDef` 没有 `spriteSort`**：22 个展示图热点里 8 个用了 `front`/`back` 排序带，
     其中一半是人。转成 NPC 后只能按 Y 排序，前后关系会错。
   - **占位包与正式包的"身高标定"必须同一口径**，否则将来换正式包时角色会突然变大变小。
5. 建议**分三期**：先出静态包出口（能自测），再补 NPC 侧两个字段+编辑器一键路径，
   最后才是批量占位 + 场景迁移。**不要一次性全铺**。

## 二、现状调查（事实与出处）

### 2.1 动画包契约与单帧可行性

- 产物形状唯一：`public/resources/runtime/animation/<id>/` 下 `atlas.png` + `anim.json`
  （+ `<图集名>.normal.png` + 可选 `atlas.meta.json`）。契约见
  `agent_docs/asset-pipeline/mechanisms/sprite-atlas-anim-contract.md`。
- 关键运行时事实（都对单帧有利）：
  - 帧号 **0 基**，`col=idx%cols, row=idx//cols`；1 帧 → `cols=1,rows=1,frames:[0]`。
  - 锚点恒为 `anchor(0.5,1)` 底中＝脚；与热点 `displayImage` **完全同锚**
    （`src/entities/Hotspot.ts:216`），所以热点→NPC 的坐标是 1:1 平移，不用重新摆位。
  - `playAnimation()` 遇到不存在的 state **静默 return**（`SpriteEntity.ts:419-421`），
    `playNpcAnimation` 是 fire-and-forget（`src/core/ActionRegistry.ts:962`），
    **占位包只有 idle 也不会把剧情卡死**，最多是"没换动作"。
  - `Npc.loadSprite` 的初始态解析优先 `idle`，否则取第一个 state（`src/entities/Npc.ts:233`）；
    `CutsceneRenderer.ts:843` 同口径。**占位包的唯一 state 必须叫 `idle`。**
  - 过采样会被自动低通（`EntityPixelDensityMatch`），**占位图做得比出货密度更高是纯浪费**。

### 2.2 静态支线现状：只出裸 PNG，不出包

`tools/anim_preview/workspaceStore.mjs:13` 定义 `H_STATIC`（deps: C），
`workspaceStore.mjs:123` 强制 `staticTargetPath` 必须落在
`public/resources/runtime/images/` 下且是 `.png`；
`workbench_stages.py:1047` 的适配器**只做逐字节复制 + 校验**，不改像素、不产 anim.json。

也就是说：**今天一张静态角色图只能当热点展示图用，当不了 NPC。** 这正是需求的痛点。

## 三、方案 A：静态动画包（单图 → 一个 state）

### A1 产物形状（硬定义）

```
public/resources/runtime/animation/<bundleId>/
  atlas.png            # 1 格；内容紧裁；RGBA
  anim.json            # cols=1 rows=1；states={"idle":{frames:[0],frameRate:8,loop:true}}
  atlas.meta.json      # packMode="static_single_frame"，含占位/标定溯源
  atlas.normal.png     # 走 ./dev.sh bake-normals，与其它包一视同仁
```

- **state 名钦定 `idle`**（理由见 2.1；改名会让初始态解析退化成"取第一个 key"）。
- `frameRate` 写 8 只为 schema 合法，运行时不消费（单帧短路）。

### A2 落点（代码）

| 文件 | 改动 |
|---|---|
| `tools/animation_pipeline/workbench_stages.py` | 新增 `pack_static_single_frame()` + `write_h_static_bundle_stage()` + CLI 子命令 `h-static-bundle`；复用 `pack_common_cell_states` 的网格/世界尺寸校验，**不改 H 的任何不变量** |
| `tools/anim_preview/workspaceStore.mjs` | 新增节点 `H_STATIC_BUNDLE`（deps: `C`，owner: agent），沿用 `bundleId` 作导出目标；发布回执要求 `atlas.png`+`anim.json`+`atlas.meta.json` 三件 |
| `tools/anim_preview/workbench.ts` | 版本图多一个节点的展示/审核入口（跟 `H_STATIC` 同构） |
| `tools/animation_pipeline/tests/` | 新增单元测试：1×1 网格、0 基帧、锚点、`worldSize` 宽高比校验、拒绝写 runtime |

**⚠ 一个真实约束**：`pack_common_cell_states` 里有
「R frames must be referenced exactly once across H states」不变量
（`workbench_stages.py:769`），所以**多个 state 指同一帧（别名）过不了 H 的打包器**。
静态包若要 `walk/stand` 别名，必须走**独立的静态打包函数**，不要去松 H 的不变量
（出货包 `npc_popo_anim` 本身就有 `stand`→idle 帧的别名，说明运行时合法，
这条不变量是 H 阶段特有的工艺约束）。

### A3 标定规则（这是最容易埋雷的地方）

1. **身高口径**：占位包紧裁 → 内容填满格子 → `worldHeight` **就等于该角色的世界身高**。
   参考出货值：成年人 `worldHeight` 135~160（玩家 150）。
   **但正式动画包的格子含跳跃/挥臂留白**（如 `npc_popo_anim` 格 208×204 / 世界 140×135），
   同样填 150 的正式包，角色本体反而比占位矮。
   → **钦定**：占位包把"角色本体世界身高"写进 `atlas.meta.json.authoredBodyHeight`；
   将来做正式包时，R 阶段的 `worldSize` 必须让**本体身高对齐这个数**，而不是照抄
   `worldHeight`。不这么做，换正式包那天全场角色会集体变尺寸。
2. **分辨率**：格高按出货密度定标 ≈ `worldHeight × 1.36`（人 → 约 204px），
   硬上限每边 2048。这就是需求里的"优化"：39 个占位包按此定标约几 MB，
   照搬 1348px 源图则十几倍体积，且多出的像素会被密度匹配滤镜糊掉、白花。
3. **朝向**：源图按工作台 B 阶段约定"正侧面朝右"；朝左的摆放用 `NpcDef.initialFacing:'left'`
   镜像，**不要出两个包**。

### A4 占位可查询（"以后要换掉"的账不能只靠人记）

- `atlas.meta.json` 写 `"placeholder": true` + `"placeholderSource": "workbench:A|C"` +
  `authoredBodyHeight`。
- **刻意不往 `anim.json` 加顶层键**：加了就要同步登记导出器黑名单，否则重导出时旧值盖新值
  （`sprite-atlas-anim-contract.md` 硬契约）。信息放 `atlas.meta.json` 零契约成本。
- 配一条盘点命令（可挂 `./dev.sh`）：扫所有包，列出 `placeholder:true` 的、以及被哪些场景
  的哪些 NPC 引用 —— 这就是"统一出资源"时的工单。

### A5 抠图不跳（2026-08-06 明确）

占位包的图**必须走完工作台 `A→B→C` 的抠图与人工验收**，与正式静态角色同一条路，
**没有"占位所以可以糊弄"的快车道**。本方案唯一的新东西是 C 之后的**出口**：
今天 C 只能被复制成一张裸 PNG（只能当热点展示图），新增出口把它打成
`atlas.png + anim.json`（能当 NPC 用）。前置阶段一律照旧。

### A6 需求里那句"作为一个单独的动画 state"的两种读法

- **读法 1（本方案默认）**：一张图 = 一个独立的**包**，包里就一个 state。
- 读法 2：把一张静态图作为**追加的 state 塞进已有包**。这条技术上要重打整张图集
  （所有 state 共享均匀网格，格尺寸会变），成本远高于新开一个包，且破坏"一角色一图集"。
  → **建议不做**；真要"这个角色多一个静态姿势"，走新包 + `setEntityField(animFile)` 换装
  （运行时已支持，见 `Npc.ts:306` 注释）。

## 四、方案 B：角色统一为 NPC

### B1 口径（先划线，再动手）

**"角色"= 有身份、可能说话/被剧情点名/需要动的人或精怪。**
**已拍板：尸体与物件不转**（2026-08-06 制作人定）。尸体是"被检视的物件"，带 inspect 载荷
与背尸流程强绑定，转 NPC 只会把 5 条已经跑通的流程重新推一遍风险。

### B2 三条迁移路径

| 路径 | 对象 | 做什么 |
|---|---|---|
| P1 **纯欠账** | 码头白天的埃德加、克拉拉 | 已有动画包，删展示图热点、建 NPC（`characterId` 引用注册表），零新资源 |
| P2 **静态转包** | 老衙役、搬运工、洋人女性、挑水人、货郎、许糖匠、人群图… | 拿**游戏当前在用的那张 PNG**（源一致性红线）过 A2 的静态打包 → 建 NPC |
| P3 **占位新建** | 39 个只有设定稿的角色 | `setup.png` → 抠图 → 静态包 → 需要出场的场景建 NPC；剧情可以立刻开编 |

P3 是需求主线（"先占位用于编排剧情"）。**已拍板：39 个全做**（2026-08-06 制作人定）。
批量跑仍受"抠图不得跳过目视复核"红线约束，见 §五 P3 的验收判据。

### B3 运行时缺口（必须补，否则迁移掉表现）

1. **`NpcDef.spriteSort`**：`Renderer.sortEntityLayer` 认的是容器上的 `entitySortBand`，
   与实体类型无关（`Renderer.ts:188-210`），Hotspot 侧已经在打这个标（`Hotspot.ts:157-180`）。
   给 `NpcDef` 加同名可选字段、在 `Npc` 里同样打标即可 —— **additive、不改任何现有行为**，
   但**不补就不能转** 码头人群(back)/搬运工(front)/围观人群(back) 等 8 个。
   需按四件套登记（运行时 + `actionParamManifest` 不涉 / 编辑器字段 / validator）。
2. **不可交互口径**：装饰 NPC 用 `interactionRange:0`（已入库范式）。
   注意与热点不同：空 inspect 热点是**结构上就不提供交互**
   （`hotspotOffersPlayerInteraction` 返回 false），NPC 是"半径为 0 所以够不着"。
   语义够用，但**要写进卡里**，别让人以为 NPC 有"不可交互"开关。
3. `renderRaw`：贴图取自已烤光照背景的（人群图/围观人群）转 NPC 时必须
   `renderRaw:true`，否则色调不符 + 露方框接缝（已入库铁律，别忘）。

### B4 编辑器缺口（决定这事能不能持续做下去）

今天要把一张图变成 NPC，人要手工跑：抠图 → 打包 → 拷进 runtime → 建 NPC → 填 animFile →
量 worldSize。**六步里五步是工具活。**建议在**主编辑器场景页**加一条一键路径：

> 选中一个展示图热点 → 右键「转为 NPC（生成静态动画包）」→ 弹窗确认 bundleId / 身高 /
> spriteSort / 交互半径 → 生成包 + 建 NPC + 删热点 + 报告引用改写

- 复用：`IdRefSelector`（animFile 选择器已在 `scene_editor.py:7252`）、
  `entity_refactor` 的引用扫描与撤销栈。
- **`entity_refactor` 目前没有"改实体种类"这个 op**（只有 move/rename/delete/duplicate），
  热点 id 被叙事/动作点名时需要机械改写 —— 这是本条最实的工作量，也是最该走引擎
  而不是手改 JSON 的地方（`content/mechanisms/entity-refactor-engine.md`）。
- 编辑器改动须服从：唯一写盘出口 `save_all`、两阶段写、数值往返保真、
  `undefined-name` 静态门（`agent_docs/editor-tools/`）。

### B5 角色注册表：只给"有身份的角色"收口，不全收

先纠正一个上一稿的错判：**"占位包换正式包"本身根本不需要注册表**——只要 bundleId 不变，
换掉 `animation/<id>/` 目录里的文件即全场生效，零处数据要改。注册表管的是另一码事：
角色改名 / 换立绘 / 换包名时的一致性。

更要紧的是现状不支持"一包一角色"的假设。实测 36 个包里 25 个跨场景复用，**且不是同一角色
出现在多处，是拿现成包当"路人皮肤"凑背景人**：

```
npc_coolie_a_anim   → 前街扛米脚夫 / 她儿子 / 挑担的脚夫 / 歇脚的脚夫 / 赌坊看场
npc_li_tiangou_anim → 李天狗 / 前街看货的洋行女客
npc_popo_anim       → 卖香烛的婆婆 / 洗衣婆 / 婆子 / 找上门的婆子
```

给"歇脚的脚夫"发角色身份证纯属添乱。故**口径改为部分收口**：

- **登记注册表**：有名字、会说话、被剧情点名的角色——含本次 39 个占位角色
  （它们本来就一人一包一身份，顺手）。
- **保持就地写 `animFile`**：路人皮肤式摆放，不进注册表。

（此项待制作人最终确认。）

## 七、已知风险

- **换包尺寸跳变**：占位与正式包身高口径不一致 → 全场角色变大变小。对策见 A3.1，
  必须写进机制卡，不能只靠这次记住。
- **静态包被当成"做完了"**：没有 placeholder 标记与盘点命令，半年后没人知道哪些还欠资源。
  对策见 A4。
- **迁移丢排序**：不补 `spriteSort` 就转，前后关系错且不会报错（只是看着别扭）。
- **源一致性**：P2 转包必须拿**游戏当前在用的那张 PNG**，不能去 `tmp/` 里找"看着像"的源
  （`asset-pipeline/norms.md` 红线，`2026-07-10` 决策已有前车之鉴）。
- **抠图不目视就批量入库**是明确红线；39 个占位若批跑，必须逐个贴棋盘格复核。
