# 主角身体动词五件套 · 技术设计（蹲 / 踢 / 驻足注视 / 跳 / 躺）

**日期** 2026-08-03 ｜ **状态** 已施工（P0–P3 全落地，kick 待美术）｜ **范围** 运行时 + 编辑器 + 数据契约

---

## §0 一页结论

**动词分两类，不能用一套机制做：**

| 类 | 动词 | 特征 |
|---|---|---|
| **姿态**（持续态，有进/出） | 蹲、躺、驻足注视 | 单槽互斥；改变移动、交互、感官；不入存档 |
| **一次性动作**（播一段就完） | 踢、跳 | 播动画 → 到点触发回调 → 回 idle；期间锁移动。**没有命中判定、没有冷却** |

> **本作是冒险解谜，不是 ARPG。** 踢的目标在**按下那一刻**就定了（复用交互系统已经算好的最近目标，和 `E` 同一套），不存在"打没打中"；跳**没有目标**，只有原地跳（表达）和跨点跳（位移）两种形态。任何前摇/命中窗口/扇区/冷却的机制都没有东西去承接，全部不做。

**回调统一收敛到一张表**：`verb → ActionDef[]`，挂在三个层级（目标 / 区域 / 全局兜底），执行走既有 `ActionExecutor`。这样编辑器复用 `ActionEditor`、校验复用既有动作校验、叙事回调复用 `emitNarrativeSignal`——**零新执行链**。

**按键**：`C` 蹲 · `X` 驻足注视 · `F` 上脚 · `Space` 跳 · 躺 = 在躺点上按 `C`（语境化，不吃新键）。唯一代价是把「用规矩」从 `F` 迁到 `G`。

**唯一硬美术依赖**：踢没有动画。蹲/跳/躺/站的片段全部现成（且 `crouch` 倒放 = 起身，是过场里已验证的手艺）。

**分期**：P0 蹲+注视（零美术）→ P1 跳 → P2 躺 → P3 踢（等动画）。

## §1 现状盘点（施工时当事实用）

### 1.1 键位占用

| 键 | 现用途 | 出处 |
|---|---|---|
| WASD / ↑↓←→ | 移动 | `InputManager.getMovementDirection()` |
| Shift | 跑 | `InputManager.isRunning()` |
| E | 交互（最近目标） | `InteractionSystem.ts:214` |
| Q | 嗅 | `Game.ts:4929` |
| Tab / I / R / L / B / M / F | 任务 / 背包 / 规矩册 / 对话记录 / 书架 / 地图 / **用规矩** | `Game.ts:3080-3088` |
| Space / Enter | 推对话、遭遇、压力条 | 均在**非 Exploring** 状态 |
| Esc / F2 | 关面板 / 调试坞 | `GameStateController` |

**探索态空闲**：`C` `X` `V` `Z` `G` `T` `Space`、鼠标左右键（`playerNavTarget` 只被 dev 命令写，鼠标未占）。

### 1.2 玩家动画资产（`player_anim/anim.json`）

`idle` `walk` `run` `slow_walk` `stand` `crouch` `lie_down` `jump` + hero_* 若干。**全部 16 帧、全部 `loop:true`**。

- 一次性播放靠 `playback.loop:false` 覆盖（`SpriteEntity.playAnimation` 支持，`effectiveLoop = playback.loop ?? frameDef.loop`）。
- **`crouch` 是「下蹲过程」**：正播到末帧 = 蹲住；`reverse:true` + `thenState` = 起身。这是过场 K5 已验证的手艺，直接继承。`lie_down` 同理。
- **没有 `kick`，也没有 `crouch_walk`。**

### 1.3 已有可复用引擎能力

- `Player.jumpTo(x,y,durationMs,arcHeight,jumpAnimState,landAnimState,faceTowardMovement)` —— 抛物线抬升 + 按进度插帧 + 落地切态，**跳跃演出已经写好了**，玩家跳只是接输入 + 落点校验。
- `Player.setMovementModifier()` —— 位面注入的 `speedScale` / `allowRun` 通道，姿态调速直接复用同一个口。
- `Player.getEmoteBubbleAnchorLocalY()` —— 按**当前帧可见内容**顶部锚气泡，蹲/躺矮帧自动降下来，**不需要为姿态改气泡**。
- `PlayerAvatarConfig.stateMap` —— 逻辑名→图集状态名的映射层，是姿态扩展的天然挂载点。
- `PlaneInteractionConfig` —— 位面已有 `canPickup/canInteractHotspots/canTalkNpcs` 三闸的先例。

## §2 动词模型

### 2.1 姿态机（单槽互斥）

```
stand ──C按下──▶ crouch ──C松开──▶ stand
  │                 │
  │                 └─(在 act_spot 且允许 lie)──▶ lie ──任意移动/E──▶ stand
  └──X按住──▶ gaze ──X松开──▶ stand
```

硬约束：
- 单槽：同时只有一个姿态；进新姿态先走旧姿态的 `exit`。
- 只在 `GameState.Exploring` 受理输入；进 Dialogue/Cutscene/Minigame/UIOverlay **强制复位 stand**（不播起身动画，直接切 idle，避免抢演出）。
- **不入存档**（§10）。

### 2.2 一次性动作

```
按下 ──▶ 目标/形态在此刻定死 ──▶ 播动画（期间锁移动）──▶ 到 callbackFrame 触发回调 ──▶ 回 idle
```

- **目标不是"判定"出来的**：按下瞬间取 `InteractionSystem` 当前的最近目标（同一套目标集、同一个 `interactionRange`、同一个位面闸），只是筛选条件从"可交互"换成"配了 `acts.<verb>`"。没有独立半径、没有朝向扇区。
- **没有冷却**：动画播完前该动词的键被忽略（这是播放互斥，不是冷却机制）。可选 `cooldownMs` 保留但缺省 0。
- **回调时机 = 动画的一帧**（`callbackFrame`，缺省片段中点）。这是表演对齐，不是"命中窗口"——它不影响成败，只影响脚落地的那一下和世界反应对不对得上。
- 锁移动是为了让动画播完整；跳的位移由 `Player.jumpTo` 独占接管（既有实现如此）。

## §3 按键分配

### 3.1 推荐方案（A）

| 动词 | 键盘 | 触屏 | 交互形式 | 理由 |
|---|---|---|---|---|
| **蹲** | `C` | 「蹲」按钮（触屏用 toggle） | **按住**蹲，松开起身 | C=crouch 直觉；按住式不会忘记自己蹲着 |
| **驻足注视** | `X` | 「看」按钮（按住） | **按住** | 与 `Q` 嗅并列成「感官对」，两个都是按住式的被动感官 |
| **上脚 / 踢** | `F` | 「手」按钮 | 点按 | F 是通用近身 use/melee 键位；**需把「用规矩」迁到 `G`** |
| **跳** | `Space` | 「跳」按钮 | 点按 | 探索态 Space 完全空闲；其它状态的 Space 语义（推进）不冲突，因为 GameState 不同 |
| **躺** | 躺点上按 `C` | 同「蹲」按钮 | 语境化 | 不吃新键；躺的地点必须由策划控制（满街乱躺美术上必翻车） |

### 3.2 待拍板：F 键迁移

方案 A 要把 `registerPanel('ruleUse', …, 'KeyF')` 改成 `'KeyG'`。

**备选 B（不动任何现有键位）**：踢用 `V`。代价是 V 键手感陌生、和 `C`/`X` 不在同一手位区。

**建议 A**，理由：`F` 在动作游戏里就是「上手做事」，而「用规矩」是个面板（面板键该和 Tab/I/R/L/B/M 一族在一起，`G` 更合群）。迁移成本 = 一行注册 + 触屏按钮标签 + 快捷键说明文案。

### 3.3 触屏 HUD 是真成本

现状只有「跑 / 用」两个按钮（`TouchMobileControls.ts:110-155`）。加完是 6 个（跑/用/蹲/看/手/跳），必须重排：建议右下 2×3 网格，`touch-mc-explore-only` 类照旧；蹲/看在触屏上改 **toggle**（触屏没有「按住」的可靠手感）。

## §4 五个动词逐条规格

### 4.1 蹲（crouch）

| 项 | 规格 |
|---|---|
| 进入 | 播 `stateMap.crouch`，`{loop:false}` → 停末帧（约 250ms） |
| 退出 | 播 `stateMap.crouch`，`{loop:false, reverse:true, thenState: stateMap.idle}` |
| 移动 | **允许**，速度 × `speedScale`（缺省 0.45）；动画 P0 用 `stateMap.crouchWalk` ?? `slow_walk`（近似猫腰走）<br>⚠ **TODO 美术**：真正的 `crouch_walk` 未画，P0 是将就 |
| 跑 | 蹲态屏蔽（同 `allowRun:false` 通道） |
| 交互 | 蹲态下 `requiredPosture:'crouch'` 的热点才出提示；普通热点照常 |
| 感官 | 蹲下降低嗅判定高度（可选，接 `SmellSystem`，P2） |
| 生态耦合 | 蹲 = 最小惊扰档；世界经 `player:posture` 事件与 `requiredPosture` 读它 |

**设计意图**：蹲是「翻检 / 看低处 / 凑近闻 / 歇」的统一身体锚。8 个翻检点从「站着按 E 弹字」改成「蹲下才出提示」，翻检层立刻落进世界空间。

### 4.2 驻足注视（gaze）

| 项 | 规格 |
|---|---|
| 进入 | 站定（移动输入被吞），朝向最近目标（`faceEntity` 同口径），播 `stateMap.gaze` ?? `stand` |
| 相机 | 可选微推：`camera.setZoom(baseline × 1.08)`，退出**必须**回 baseline（`scene.camera.zoom` 已有基线记录） |
| 触发 | **进入注视态即触发**目标 `acts.gaze`——按住 X 已经是明确意图，不需要再计时考验玩家。可选 `holdMsToTrigger` 缺省 0（策划想要"盯久了才看出门道"可单独配） |
| 退出 | 松键立即回 idle；触发过的目标本次进区内不重复触发 |
| 生态耦合 | 「他停下来盯着你」是反应层 K2「侧目」的天然触发源 |

**注**：`acts.gaze` 是「看出门道」的世界空间入口——若日后要把「象」的获取从面板挪到世界，这里是接口，但**本设计不改规矩系统模型**。

### 4.3 上脚 / 踢（kick）

| 项 | 规格 |
|---|---|
| 动画 | **缺，需新画**：6~8 帧一次性片段（抬脚→送出→收），`loop:false, thenState:idle` |
| 目标 | 按下瞬间取 `InteractionSystem` 的最近目标——**同一套目标集、同一个 `interactionRange`、同一个位面闸**，只多一条筛选：该目标配了 `acts.kick` |
| 提示 | 有目标时 HUD 出「[F] 踢」，与「[E] 查看」并列。**能不能踢由提示告诉玩家**，不靠玩家试 |
| 朝向 | 取到目标后 `setFacing` 朝它，再播动画 |
| 触发 | 动画播到 `callbackFrame` 时执行 `acts.kick.actions` |
| 空挥 | 无目标时按 F：播同一段动画 + `missActions`（踢空音/扬尘）。**可以什么都不配**，此时按下无反应也是合法设计（提示已经说明了没东西可踢） |
| 锁移动 | 动画播放期间（约 500ms），播完即解 |
| 位面 | 背尸位面禁用（`allowedVerbs` 不含 kick） |

**数据迁移收益**：[寻狗_踢狗.json](public/assets/dialogues/graphs/寻狗_踢狗.json) 现在是「按 E → 弹菜单 → 点『踹它一脚』」。改成 `npc.acts.kick` 后，图里的 `randomBranch` 概率、`tigou_run`/`tigou_bite` 信号、`wrap_踢狗` 迁移**一个字节都不用改**，只是入口从菜单选项换成一脚。踢猫、偷鸡同构。

### 4.4 跳（jump）

**跳没有目标，只有两种形态**——按下时站在哪儿决定是哪种，玩家不需要瞄准任何东西：

| 形态 | 触发 | 行为 |
|---|---|---|
| **原地跳** | 任意地方按 `Space` | 抛物线蹦一下，**不位移**。纯表达（着急、试探、够一下高处），`zone.onPlayerAct.jump` 可以接（鸡受惊、狗叫） |
| **跨点跳** | 站在 `act_spot`（`verbs:['jump']`）范围内，HUD 出「[Space] 跳过去」 | `Player.jumpTo` 到 `data.landing`，无视沿途阻挡。跨阴沟 / 跨门槛 / 上矮台的唯一合法方式 |

- 实现：两种都调既有 `Player.jumpTo`（现成的抛物线 + 按进度插帧 + 落地切态），原地跳就是 `targetX/Y = 当前位置`。
- 参数：`durationMs` 480 / `arcHeight` 46（缺省可配）。跨点跳的时长/弧高可由 `act_spot` 单独覆盖。
- 位面：背尸位面禁用。

**为什么不做"朝当前方向跳一段距离"**：那需要落点碰撞校验，而碰撞走深度反投影——屏幕上是屋顶的位置也可能判「可走」（生态规格 V5 实测）。方向跳等于发一张上房顶的通行证，还要为"落点不可走就退化原地跳"写一段没人看得懂的规则。**跨越必须由策划显式钉点**，落点由 `audit-walkable` 保证，运行时零判定。

### 4.5 躺（lie）

| 项 | 规格 |
|---|---|
| 触发 | 仅在 `act_spot`（`verbs:['lie']`）范围内，按 `C`（提示词由 `data.promptKey` 给，如「躺下歇一气」） |
| 落位 | 先 `moveTo(data.align)` 对齐，朝 `data.facing`，再播 `lie_down {loop:false}` 停末帧 |
| 起身 | 任意移动键 / `E`，播 `lie_down {reverse:true, thenState:idle}`，**约 900ms 不可打断**——这是躺的代价 |
| 期间 | 不可交互、不可击发；`acts` 里可挂时辰推进 / 淡出转场 / 梦境过场 |
| 自由躺 | **默认关闭**。`playerActs.lie.freeAnywhere:true` 可开（不建议：满街躺美术上必翻车） |

## §5 回调设计

### 5.1 三层回调面

```
① 本体反馈（引擎内，策划不配）
   动画 / 音效 / 相机微动 / 气泡锚点自动跟随矮帧
② 世界回调（策划配，走 ActionDef[]）
   目标级  NpcDef.acts / HotspotDef.acts        ← 踢这条狗、看这个人
   区域级  ZoneDef.onPlayerAct                  ← 在这片地方蹲下
   全局级  game_config.playerActs[verb].missActions  ← 空挥兜底
③ 叙事回调（在 ② 的 ActionDef[] 里写）
   emitNarrativeSignal / setFlag / incFlag / startDialogueGraph …
```

**派发优先级**：目标级 → 区域级 → 全局兜底。**匹配到即停**，不层层叠加（否则踢一脚同时放三段反应）。

### 5.2 引擎事件（对齐现有 `zone:enter` 风格）

| 事件 | 载荷 | 谁听 |
|---|---|---|
| `player:posture` | `{ from, to, x, y }` | 音频（起身衣料声）、生态惊扰半径、调试快照 |
| `player:act` | `{ verb, targetKind, targetId, hit, x, y }` | 音频、无头断言、生态层 |

两个都由新 `PlayerActionSystem` 发，`EventBridge` 挂音效。

### 5.3 条件读取姿态

两条路，**优先前者**：

1. **`requiredPosture` 字段**（P0）：`HotspotDef.requiredPosture?: 'crouch'|'lie'`。`InteractionSystem` 选目标时过滤——不满足则不出提示、不可触发。覆盖 90% 需求（蹲下才能翻的柴堆）。
2. **新条件叶 `{ posture: 'crouch' }`**（P2，L2 升级）：供任意 `conditions` 用（蹲下才**看得见**墙根的洞）。成本是 `evaluateGraphCondition` + `ConditionEvalContext` 注入 + 编辑器 `condition_editor` + Python 侧兜底校验，四处同步。**没有明确内容需求前不做。**

⚠ **姿态绝不写 FlagStore**：FlagStore 全量入存档，姿态入档 = 读档后「档里蹲着、精灵站着」的必然错位。

## §6 数据契约（策划怎么配）

### 6.1 `game_config.json` → 新增 `playerActs`

```json
"playerActs": {
  "crouch": { "enabled": true, "speedScale": 0.45, "enterMs": 250, "allowRun": false },
  "gaze":   { "enabled": true, "holdMsToTrigger": 0, "cameraZoom": 1.08 },
  "kick":   { "enabled": true, "callbackFrame": 3,
              "missActions": [ { "type": "playSound", "params": { "id": "kick_miss" } } ] },
  "jump":   { "enabled": true, "durationMs": 480, "arcHeight": 46 },
  "lie":    { "enabled": true, "freeAnywhere": false, "exitMs": 900 }
}
```

缺省全部有值，**整块不写 = 五个动词全按缺省开启**；单个 `enabled:false` 关掉该动词（键按下无反应、触屏按钮隐藏）。

### 6.2 `playerAvatar.stateMap` 扩容

现状固定三行（`idle`/`walk`/`run`）。扩为逻辑名表：

```json
"stateMap": {
  "idle": "idle", "walk": "walk", "run": "run",
  "crouch": "crouch", "crouchWalk": "slow_walk",
  "gaze": "stand", "jump": "jump", "lie": "lie_down",
  "kick": "kick"
}
```

**缺项即禁用**：某装扮（如 `player_carry_corpse_anim`）没有 `kick`/`jump` 状态就不写该键，运行时该动词在此装扮下自动禁用、不出提示。这条规则同时解决了「背尸时能不能跳」——**由动画资产回答，不需要额外开关**。

### 6.3 场景实体：`acts` + `requiredPosture`

`NpcDef` / `HotspotDef` 各加两个可选字段：

```json
"acts": {
  "kick": { "actions": [ … ], "conditions": [ … ], "oncePerScene": false },
  "gaze": { "actions": [ … ] }
},
"requiredPosture": "crouch"
```

- `conditions` 不满足 = 视同未配置（回落区域级/全局兜底），**不是静默失败**。
- `oncePerScene` 走会话覆盖，不入永久档（要永久记忆就在 `actions` 里发信号）。
- 空对象不写键（往返契约）。

### 6.4 `ZoneDef.onPlayerAct`

```json
"onPlayerAct": {
  "crouch": [ { "type": "playNpcAnimation", "params": { "target": "eco_wj_鸡甲", "state": "peck" } } ],
  "kick":   [ … ]
}
```

与 `onEnter/onStay/onExit` 同级、同执行口（`executeBatchInZoneContext`，zone 上下文照旧线程化）。**不受 `onStay` 的 0.25s 节流影响**——它是事件驱动的。

### 6.5 新热点类型 `act_spot`

`HotspotType` 加一个成员：`'inspect' | 'pickup' | 'transition' | 'npc' | 'encounter' | 'act_spot'`。

```json
{
  "id": "hs_yz_板铺", "type": "act_spot", "x": 1820, "y": 2100,
  "interactionRange": 46,
  "data": {
    "verbs": ["lie"],
    "align":  { "x": 1824, "y": 2104 },
    "facing": "left",
    "promptKey": "躺下歇一气",
    "actions":     [ … 躺下时 … ],
    "exitActions": [ … 起身时 … ]
  }
}
```

跨点跳用同一类型：`"verbs":["jump"]` + `"landing":{x,y}`。

⚠ `act_spot` **不出 E 提示**（`hotspotOffersPlayerInteraction` 要认它并返回 false），它出的是动词提示（「[C] 躺下歇一气」）。

### 6.6 位面闸

## §12 分期、成本、明确不做

### 分期（按「有没有美术阻塞」排，不按重要性）

| 期 | 内容 | 美术 | 产出 |
|---|---|---|---|
| **P0** | 蹲 + 驻足注视 + 三层回调骨架 + `acts`/`requiredPosture` 数据面 + 编辑器区 + validator | **零** | 翻检层落地世界空间；反应层拿到两个玩家侧输入 |
| **P1** | 跳（自由跳 + `act_spot` 跨点） | 零（`jump` 现成） | 跨阴沟/门槛；生态惊扰源 |
| **P2** | 躺（`act_spot` 躺点 + 起身代价） | 零（`lie_down` 现成） | 「歇一气」从热点弹图变成身体动作，接时辰推进 |
| **P3** | 踢 | **需 kick 动画 6~8 帧** | 踢狗/踢猫从菜单选项变成一脚，数据零改 |

### 明确不做

- **任何动作游戏机制**：前摇/后摇分段、命中窗口、朝向扇区、独立攻击半径、冷却、连击、蓄力、成功失败判定。本作是冒险解谜，这些没有东西承接
- 朝当前方向跳一段距离（只有原地跳 + `act_spot` 钉点跨）
- 姿态写 FlagStore / 入存档
- 姿态条件叶（P2 待内容拉动才升 L2）
- 蹲态的「被发现值」——**蹲不是潜行系统**，没有检测条、没有失败态，只是世界对步态与高度有反应

### 风险

1. **死键风险**：靠「提示驱动」化解大半——有东西可踢/可跳时 HUD 才出提示，玩家不用瞎试。剩下的风险是「提示出现了、按下去反应寡淡」，所以每个配了 `acts` 的目标都必须给出**世界空间的**回应（动物动一下、有人抬头、有声音），不能只弹一行字。
2. **蹲行动画将就**：P0 用 `slow_walk` 顶 `crouch_walk`，视觉上是「猫腰快走」，能接受但不精确。
3. **触屏 HUD 从 2 键涨到 6 键**，小屏排布需真机验。
4. **F→G 迁移**：老玩家/文档/录像里的键位说明要同步。
5. **gaze 相机 zoom** 与过场 `cameraZoom`、场景基线 zoom 三者的复位顺序要理清，否则退出注视时镜头停在错误缩放上（建议 P0 先不做 zoom，只做站定+朝向）。

## §13 落地注记（2026-08-03 施工完毕后回填）

### 与设计稿的差异（以代码为准）

| 项 | 设计稿写的 | 实际落地 | 为什么 |
|---|---|---|---|
| 姿态进入/退出时长 | `enterMs` / `exitMs` 直接当锁窗 | 片段用 `playback.speed` **变速压进**该时长；speed 被 `[0.1,10]` 钳位时锁窗反过来跟着实际时长走 | 图集姿态片段是 16 帧 @8fps＝2s，直接播完远超手感需要；按 ms 硬切会看见跳帧 |
| `act_spot.align` | 先 `moveTo(align)` 对齐再躺 | **直接落位**（`alignToSpot`） | 距离都在 interactionRange 内，为几十像素引一段异步位移＝"旧时间线写新状态"的破口 |
| `gaze.cameraZoom` | 可选推镜 | **字段删除** | 与过场 `cameraZoom`、场景基线 zoom 的复位顺序纠缠，设计稿 §12 风险 5 已标；不做比做半套好 |
| kick / gaze 目标的动词提示 | HUD 出「[F] 踢」 | **未做**（只有 act_spot 有提示） | kick 无动画片段 → 动词整体禁用 → 今天不存在死键。**kick 动画落地那一版必须同时补上**，否则「能不能踢由提示告诉玩家」没有承接物 |
| 姿态回调 | 只提了翻检/歇脚 | 姿态也走完整三层派发（`dispatchVerb`） | 否则编辑器写得出、校验器放行、游戏里永不触发＝最坏的配置死区 |

### 施工中确立的两条硬约束（后来人必读）

1. **姿态复位分两种力度**。`resetToStand('soft')`（离开探索态）只归还自己占的锁与动画所有权，**不许** `cancelMotion()`、**不许**强切 idle——此刻玩家极可能正被动作批的 `moveEntityTo` 或过场接管，抢它的 `moveTarget` 会让那段位移瞬间"到达"。只有 `'hard'`（切场景/读档/销毁）才连位移带动画一起复位。
2. **复位时要给仍按着的姿态键上闩**（`latchPressedPostureKeys`）。否则「按住 C 蹲下 → 回调起对话 → 对话结束回探索 → C 还按着 → 又蹲又起对话」会无限循环。

### 编辑器侧：重块必须懒建

hotspot / npc / zone 面板各挂 5 个动词区 ≈ 每个 SceneEditor 实例多 15 棵 ActionEditor/ConditionEditor 子树。编辑器测试的耗时对**存活控件数是 O(N²)**（`app.setStyleSheet()` 全应用重刷，实测记录在 `tools/editor/tests/qt_teardown.py` 的 docstring）。因此 `player_acts_editor.py` 用 `_LazyVerbSection`：控件首次展开才造，没展开过的动词 `to_dict()` 原样透传磁盘原值——顺带让"没碰过的动词"往返逐字节不变。**以后往实体面板加重块，先想懒建。**

### 验收门实况

`tsc` 干净 · `npm test` 347 passed · `validate-data` 与施工前逐字相同（85 error / 60 warning，全部既有）· 素材审计 2 issues（既有）· dialogue_graph 76 passed · 编辑器 915 passed。

⚠ 编辑器全套需 `--deselect test_scene_entity_tree_multiselect.py::test_assign_group_write_and_undo`：那条是**既有死挂**（测试 monkeypatch `QInputDialog.getItem`，实现走 `ReferencePickerDialog.exec()`，offscreen 下永不返回），HEAD 上就有，已单独立项。

### 仍未做（按期排）

- **kick 动画**（6~8 帧一次性片段）——落地后需同时：在「玩家化身」页把 `kick` 映射到该片段、给 `playerActs.kick.missActions` 配落空反馈、补 kick/gaze 的目标动词提示。
- **`crouch_walk` 片段**——现在蹲行复用 `slow_walk`，是将就。
- 姿态条件叶 `{posture:…}`（P2，待内容拉动）。

### 验收账（四轮，subagent 只读审查）

| 轮 | 发现 | 结果 |
|---|---|---|
| 1 | 16 条（4 个 P0：gaze 的 `speedScale:0` 被 `>0` 守卫吞掉、姿态期间击发导致姿态与精灵错位、crouch/lie/gaze 三个动词编辑器写得出但运行时永不派发、`promptKey`/`align` 是死字段） | 全修 |
| 2 | 返工新引入 8 条（2 个 P0：soft 复位抢走演出已接管的 Player；复位清闩导致姿态回调无限重触发） | 全修 |

| 4 | — | **合格** |

其中三条值得记住的教训：
- **给姿态接上回调之后，"复位"就不再是纯清理动作**——它会把玩家送回一个还按着键的状态，回调会再触发一次。闩必须在复位时上，不是清。
- **新面板的 `changed` 信号是数据完整性的一部分**，不是可选的 UX 糖：不接 = 编辑不置 pending-dirty = 切条目时 staging 被 auto-discard = 无声丢数据、无提示。这是 scene_editor 既有审查项 P1-1 的原样复发。
- **懒建的收益有边界**：配了内容的动词照样全建，O(N²) 的压力会随内容回来。真要扛住，得从"面板重建"这一层想办法，不能只靠折叠。

## §14 形状改判：实体级响应表退役（2026-08-03 制作人拍板 A 方案）

§6.3 的 `acts` / `requiredPosture` **已删除**。制作人的判断：这五个动作本质是
「**一个角色状态 + 几个触发入口**」，不该在每个实体上开一张响应表。

### 决定性事实

`ActionRegistry` 里**没有条件分支动作**——只有 `chooseAction`（弹菜单问玩家）与
`randomBranch`（掷骰）。而"同一个目标对不同动词有不同反应"本质就是分支，
**只有对话图的 `switch` 能分**。原设计给每个动词开一个格子，是被这个工具限制推出来的
形状，不是问题本身的形状。

### 改后的三段

| 层 | 旧 | 新 |
|---|---|---|
| 姿态查询 | `HotspotDef.requiredPosture` / `NpcDef.requiredPosture` 两个字段 | **`{posture:'crouch'}` 条件叶**，进实体既有 `conditions`（默认只锁交互不隐藏，正是「蹲下才翻得动柴堆」要的语义），图 switch / zone / 叙事图也都能读 |
| 目标级响应 | `acts:{verb:{actions,conditions,oncePerScene}}` | **动词名 = 对话图的 entry**。踢狗 = 开狗**已有的**那张图、entry 走 `kick`；图里没有该 entry ＝ 这个目标不吃这一脚。实体上零新增字段 |
| 区域级响应 | `zone.onPlayerAct` | 不变（这就是"触发入口"，也是生态层既有 idiom——那 43 条街坊反应全是 zone 驱动） |
| 语境点 | `act_spot` | 不变（`align`/`landing` 是几何，化约不掉） |

### 白捡的两件事

1. **affordance 有了承接物**：目标吃不吃某动词 = 它的图有没有同名 entry，加载期扫一遍就知道。
   §13 记的「kick/gaze 提示未做」因此**当场补上了**——`Game.graphHasEntry` 用 AssetManager
   已缓存的图 JSON 同步作答，`scene:ready` 的 `preloadSceneDialogueGraphs` 负责把本场景
   实体引用的图拉进缓存。
2. **编辑器少 10 棵重控件树**：hotspot/npc 两个面板的动作响应区整个删除，只剩 zone 的 5 节。
   `EntityActsEditor` 退役，§13 记的"懒建收益有边界"这条压力大半消失。

### 代价与残留

- 目标级响应现在必须经过一张对话图。**纯表演的一拍**（鸡扑腾、猫弓背）走图偏重
  （会 churn 一次 GameState），这类应当走 `zone.onPlayerAct`——A 方案的分工就是
  「有戏走图、一拍走 zone」，策划需要自己判断这次算哪种。
- `oncePerScene`（会话级只响应一次）随 `acts` 一起没了。要"只发生一次"请在图里用
  叙事状态/flag 判，与其它一次性剧情同一套写法。
