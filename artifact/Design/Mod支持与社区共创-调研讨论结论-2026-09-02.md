# Mod 支持与社区共创 — 调研讨论结论(2026-09-02)

> 性质:制作人与 Claude 六轮讨论的收敛结论,供后续决策引用。
> 状态:**方向共识已达成,未排期**;所有 mod/编辑器工作均为**发售后副产品**,发售前投入为零(除 §6 三件发布时必做的零成本决策)。

---

## 1. 问题与背景

制作人调研:为让玩家社区参与游戏,本游戏是否应支持 mod?需要吗?利弊?同类(非 AAA)先例?改动量与工作量影响?

讨论基于的游戏画像(调研自 agent_docs / docs / 数据目录):

- 《寻狗记》/渝都卫:45° 冒险 RPG 骨架 + 民俗志怪血肉,悲情志怪调性,全员渝都腔对白铁律;
- **半开放志怪世界**:有主线,但世界里有大量灵异事件、鬼怪传闻、恐怖传说可调查,大量秘密与神秘道具可探索,以规矩/禁忌系统为脊椎——这一点是本次讨论结论的决定性前提;
- 技术:TypeScript + Pixi 8 + Tauri,内容 100% 数据驱动(架构铁律:代码中不出现具体内容名),发行打包 = JSON 引用闭包只读抽取;
- 编辑侧:一整套 PyQt 策划工具(零丢失往返契约、引用选择器、校验门、叙事模板系统),且**整条生产线是 AI native 的**(agent_docs 机器可读工作法、json_lang schema 工具链、production-mode agent 产内容、headless 验证与运行时命令通道);
- 美术侧:原画即光照,每张背景一整套离线烘焙产物(深度/probe/行走面/法线),角色需图集+法线+身高标定。

## 2. 核心判断:要不要做?

**不做通用 mod 支持;做一条窄而深的"社区共创"通道,形态为"包"。**

判断依据与演进:

1. mod 生态繁荣度 ∝ 游戏的系统性,∝⁻¹ 作者性。纯线性叙事游戏(极乐迪斯科、烟火、三伏)不做 mod 是品类默认答案,毫无损失。
2. 但本作是**半开放事件选集世界**,这是叙事类里唯一被验证过 mod 能成立的亚型:
   - 内容单元是"一桩灵异事件"——模块化、加性、不碰主线;
   - 世界密度是独立开发者最稀缺的资源,社区供给的恰恰是体量;
   - "传闻"在世界观内部本来就众口相传、版本各异——社区内容的调性参差被文类天然收纳;
   - 规矩/遭遇/气味/日夜/位面提供真机制钩子,社区事件玩起来像内容不像同人文。
3. 规则怪谈本身是中文互联网 UGC 文类,社区产能与本作核心数据类型(规矩+遭遇+对话)直接对口。

## 3. 通道的两条腿(共用同一套包基建 + 同一道结局门)

| 通道 | 内容 | 定位 | 风险特征 |
|---|---|---|---|
| **传述层(香火集)** | 社区给世界添怪谈/传闻/规矩/遭遇/档案 | 加性内容,活在世界内部("茶馆里听来的说法") | 低;调性参差是文类特征 |
| **别传层(意难平出口)** | 社区改写角色命运(如阿秀 if 线) | 平行现实,明确站在正史之外,别传/独立档运行 | 高情感浓度、高传播爆点,策展大考 |

关键设计共识:

- **正史铁律**:意难平出口能成立,前提恰恰是正史永远不松口。官方绝不出 if 线、绝不给玩家版 HE 盖章——正史越冷,mod 空间越有生命力;两者互保而非互斥。冷框架(如阿秀"只认帕子包不认人")在正史里守死,温情版只能以同人身份活在别传层。
- **结局门**:打完对应结局才解锁创作与游戏内消费(查结局 flag 再装载对应 tag 的包)。它同时是三样东西:创作资格的仪式("看完她完整的故事才有资格讲她的故事")、创作者筛选器、新玩家剧透防护。运行时可强制执行;工坊页面剧透只能靠分区命名规范兜,系通病不另设计。
- **供需结构**:意难平玩家(十万级)与有能力创作者(数量级远小)是两群人。目标不是人人能写,而是少数人写得出、多数人一键装得上——一个好别传接住百万人的意难平(先例:DDLC 的 Monika After Story)。
- **AU 承载**:位面系统天生就是"同一场景、不同现实"的容器,别传即位面;别传与主线存档隔离,防玩家版现实污染正史档。

## 4. 边界:美术墙决定 mod 形状

| 社区够得着(纯 JSON 或单图) | 够不着(需整套烘焙管线,不开放) |
|---|---|
| 规矩、遭遇、图对话、传闻/档案/线索、物品与检视、现有场景内摆热区/zone、单帧静态 NPC(一张透明 PNG→可用 NPC 通道)、过场编排、氛围脚本 | 新场景(原画+深度+probe+行走面)、正经动画角色、光照、视差过场 |

结论:**mod = 在官方场景与资产里写自己的故事**(Skyrim 任务 mod 的主流形态亦如此)。编辑器能力边界与此墙完全重合——发编辑器不需要突破美术墙,墙内一切它已全覆盖。

## 5. 资产盘点:编辑器与 AI native 改写成本结构

### 5.1 编辑器外化(第二产品)

- 现有 PyQt 套件是策划级工具,多数独立游戏没有——他们要从零造,我们只需包装。先例:Kenshi 发 FCS、无冬之夜附 Aurora(模组形态与本蓝图同构)。
- 编辑器出去,校验门跟着出去——运行时"静默跳过"对 modder 无报错面的问题被编辑器侧拒存/校验补掉大半。
- **"封装一下"的真实成本重心:mod 工程模式**。现编辑器只认整棵开发树单一真相源;需新增工程形态:基础游戏数据只读引用(选择器照常补全)+ mod 覆盖层可写。其余为常规:Python 打包安装器、版本化发布、文档。
- 叙事模板系统("填 taskId 一键派生")改造为"新建怪谈包/别传"向导,是 modder 上手体验的最大单点杠杆。
- 编辑器是全剧情明文阅览器→编辑器/剧情数据加载同走结局门。
- 决策实质:**愿不愿意把编辑器当第二个产品养**(自有用户、版本线、支援,永久性)。Kenshi/NWN 的答案是"值",但都是发售后游戏立住才接的担子。

### 5.2 AI native:mod SDK 已经存在

- agent_docs(机器可读工作法)+ json_lang(schema 现场重算、LSP 级补全查错)+ 往返契约 + headless 验证/命令通道 = **别的工作室要给 modder 写的教程,我们只需把日常喂给自己 agent 的东西发出去**。mod SDK ≈ 自家开发方法论的外化,且被日常验证。
- 玩家形态从"作者"变"导演":自然语言描述→自带 agent 读 schema/机制卡写内容→编辑器校验→headless 真跑验收→迭代。接口形态 = 编辑器暴露 MCP(仓库已有 narrative-debugger MCP 雏形)。
- "带上你自己的 AI 来写你自己的怪谈"在 2026 年几乎无同行做到(缺契约层底子),本身是差异化卖点。
- 成本冲抵:文档负担(agent_docs 本来就维护)、modder 支援(agent 自助)、schema 兼容税软化(agent 写的 mod 可由 agent 按迁移配方卡自动迁移)。
- **代价守恒,压力换位:AI 拆掉能力门槛,拆不掉品味门槛。** 稀缺资源从"谁写得出"翻转为"什么值得玩",策展从加分项变生死项。渝都腔反而更守得住(语料库+对白契约卡喂 agent,腔调比随机玩家标准);筛不掉的是调性与趣味,只能靠人工策展。

## 6. 成本模型与时序

### 6.1 三档成本

| 档 | 内容 | 代价 |
|---|---|---|
| L0 不做但不封门 | 维持数据驱动纪律,发行包 JSON 可读 | ≈0(现行铁律即是) |
| L1 被动可 mod | mods/ 目录 JSON 覆盖合并+素材重定向,不承诺不给工具 | 代码小;宣布即有隐性支援期望 |
| L2 正式共创通道 | mod 工程模式、打包、结局门、MCP 接口、Workshop、策展规则、版本承诺 | 编辑器+AI native 使其从"造产品"降为"外化内部产品",但仍是数月+持续税 |

**核心结论:mod 支持的真实成本从来不是加载代码,而是随之而来的稳定性承诺、文档、策展与支援——持续税,非一次性。**

### 6.2 时序(共识,六轮未动摇)

1. **发售前:mod 投入为零。** schema 高速演进期(光照三个月三代、scenarios 退役中)对外承诺格式稳定 = 自灌水泥。
2. **发布时三件必做的零成本决策**(事后补不了):
   - 发行包 JSON 保持明文可读,不加壳不加密(文件可读则社区自造加载器,免费生态火种;参照 Stardew/SMAPI——官方没做加载器,社区自建);
   - 用户协议放一段同人/mod 政策(允许非商业二创、mod 不含正版数据本体、正史唯一;参照 DDLC IP 准则);
   - 自己的内容继续用"包"的姿势生产(见 3)。
3. **贯穿发售前的唯一动作:官方内容走 mod 通道生产(dogfood)。** 用 production-mode/agent 做怪谈内容时即是在试跑未来 modder 的完整工作流;固定文件组织、独立信号命名空间、挂进现有场景、过同一条校验门。攒下的摩擦清单 = 未来 mod 工程模式的需求文档(Paradox/RimWorld 的"官方 DLC 本身就是 mod"策略)。**先设计 mod 格式再让社区试,格式必错;先用自己的几十个包磨真,加载器是最后收尾的小头。**
4. **发售后视社区热度开阀**:先香火集试基建(低风险,验证世界能不能长),别传当发布会(高爆点,考策展);策展模式可先"几十个核心玩家投稿逐个策展"(半人工,几乎零基建)再升级"上工坊自由生长"(太吾路径),两档成本差一个数量级。
5. **发售前为 mod 生态做的最大投入 = 把主线做狠。** 结局越不留活路,意难平燃料越足;世界密度越扎实,传述层越有画布。好好写正史,就是在建 mod 生态。

## 7. 案例对标(非 AAA)

- **World of Horror**(单人):规则恐怖选集+事件 mod,题材最近对标;成立前提是 1-bit 低美术门槛——反证本作必须走"复用官方美术"路线。
- **DDLC / Monika After Story**(小团队):意难平驱动 fix-it mod 的教科书;官方 IP 准则给社区安全感。
- **太吾绘卷**(小团队):中文半开放世界开工坊后 mod 成生命线一半;"先策展后工坊"路径参照。
- **Wildermyth**(小团队):社区投稿"事件"插进框架,与怪谈包同构。
- **Sunless Sea**(小团队):结构最像(半开放+港口故事选集+JSON mod),但 mod 圈始终不大——教训:好叙事内容永远稀缺,策展与精选比加载器重要。
- **Kenshi / 无冬之夜**:发自家编辑器/工具集的先例与代价参照。
- **Stardew Valley**:数据开放则社区自建加载器(SMAPI),官方不必抢跑。
- **StoryNexus(Failbetter,反例)**:工具给足社区也写不出量足质优的叙事,平台关停——"给工具社区就会写好故事"假设不成立,窄赛道+策展是唯一活法。
- **鬼谷八荒(反例)**:mod 成游戏价值大头后,与 mod 作者的关系本身需要经营。

## 8. 已识别风险与预留问题(不必现在解决,记档)

- 多个包往同一场景摆热区的冲突规则;
- mod 写进存档的 flag/信号在卸载后的语义;
- 开放加载 vs 策展精选的双轨关系(倾向:技术开放、官方定期精选集立质量标杆);
- AI 量产平庸内容淹没工坊(策展权重提高的直接原因);
- 别传层的内容底线与平台规则(逝者角色相关的越界内容);
- 玩家自带 agent 的成本与接口边界(倾向 bring-your-own-agent,官方不代管推理成本);
- **制作人待想清单**:除阿秀外,主线还打算埋几个意难平级别的点(出口容量在写正史时决定);"不可让渡清单"——哪些点永远不让渡给传述层。

## 9. 一句话总结

**本作不做通用 mod;做"怪谈包"共创通道(传述层+别传层),复用官方美术、共用结局门、正史永不松口。凭数据驱动架构、成套编辑器与 AI native 生产线,L2 成本已从"造产品"降为"外化自家生产方式";一切外化留到发售后,发售前唯一要做的就是用未来 modder 的姿势生产自己的内容,并把主线写狠。**
