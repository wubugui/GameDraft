## 0 · 先说结论

上一轮修的是**缺件**（入口条、确认框、纸页、车道表、线索层），件确实补上了，且大多接得干净。这一轮暴露出来的问题换了性质：**新件与旧场之间的接缝**——车道压面板、罩层压模态、纸页没有天头地脚、入口条先关后开。八条 P0/P1 里有六条是本轮改动引入或放大的，剩下两条是上一轮明示未修的存量。

## ① P0/P1 · 本轮改动引入的接缝问题

### 1. toast 车道 y=160 落进全屏面板的内容区（P0）

`UITheme.topLanes.toast = 160`（UITheme.ts:338）是**屏幕坐标**，与面板无关。全屏面板顶沿在逻辑 y≈70，标题带在 y≈150–190 —— toast 正好压在面板标题/正文首行上。

实拍三处：
- `after/map.png`：「存档到槽位 1」压在地图纸面顶部；
- `after/book_archive.png` / `clue_book.png`：「已录线索」把条目标题「城隍庙后山怪谈」盖掉大半，只剩一线鬼影；
- `after/confirm_dialog.png`：「档案更新」盖住「包袱」标题。

上一轮把车道从 50 推到 160，解决的是探索态压引导条（`after/notification_lane.png` 证明确实修好了），代价是全部推进了面板内容区。**车道表只有一套坐标，没有"面板在场时改走哪"这一维。**

### 2. 面板内操作的回执被"电影化静默"压成脱节播报（P1）

`Game.ts:1120-1123`：`UIOverlay || Cutscene` 一律压队。可是**面板内的操作回执也走同一条 notification 通道**：

- 存档（MenuUI.ts:882/906/912）→ 菜单是 UIOverlay → 压队 → 关掉菜单之后才冒，落在下一个界面上（`map.png` 就是这个现场：地图上飘着上一屏的存档回执）；
- 线索采集（ClueManager.ts:113，无 priority）、档案更新（ArchiveManager.ts:415）→ 在册子里点词条，**当场零 toast**，出册子才冒一句没有上下文的「已录线索」。

同一个机制，一边盖面板、一边脱离上下文，两头都不对。根因是**没有区分"世界回执"与"面板内回执"**：前者该走顶中车道且面板期静默，后者该在面板内就地出（贴面板底沿/角）且不进全局队列。

### 3. 确认框自己被罩层压暗，成了全屏对比度最低的一块（P1）

`UIConfirmDialog.ts:74` scrim = `overlay` + `alpha 0.6` 铺满全屏；`:108` 框体用 `SKINS.dialogue`（`fillAlpha 0.92`，PanelSkin.ts:82）。半透明的框叠在被压暗的画面上，罩层的黑从框底透上来 —— `after/confirm_dialog.png` 里「丢弃物件」标题、正文、两枚按钮全部糊成一片暗色，比它底下的包袱面板还难读。**模态是全屏唯一该最亮的东西。** 给确认框一套 `fillAlpha: 1` 的专用皮肤即可。

### 4. 纸页四边零内边距，正文贴着纸沿（P1）

ArchiveBookView.ts:249 纸页 = `(pageX, 0, bodyWidth-pageX, bodyHeight)`，:263-268 正文 UIScrollView 也从 `y=0` 起、高度整条 bodyHeight，:444 起条目标题画在 `y=0`。

结果：**条目标题压在纸的上沿线上、正文最后一行贴下沿、左边距只有一个 `spacing.md`**（`book_archive.png`/`clue_book.png` 可证）。纸页皮肤上了，但"纸"最起码的天头地脚白边没有 —— 观感上仍是"一块米色矩形"，不是一张纸。

### 5. 纸面色板没做对比度校核，`faint` 档实际不可读（P1）

`UITheme.paperInk`（:156-172）在 `0xd8c9a3` 纸上：

| 档 | 色 | 与纸底对比度 | 判定 |
|---|---|---|---|
| body 0x33281a | 深墨 | ≈ 9:1 | 好 |
| muted 0x59492f | 中墨 | ≈ 4.6:1 | 可 |
| **faint 0x7c6a4d** | 浅褐 | **≈ 2.2:1** | **不可读** |
| title 0x7a4d1a | 赭 | ≈ 4.3:1 | 可 |

`book_archive.png` 里「— 来源: 说书人张叭叭」几乎溶进纸里。上一轮把暗底的 14 档灰收敛成 5 档语义灰是对的，但**纸面这套是新造的，同一道校核没跑**。faint 至少压到 0x6a5636。

### 6. 册子左右两栏材质割裂（P1）

左栏纯黑窗底 + 右栏米白纸页，中间只有一条纸边（ArchiveBookView.ts:247 明确删掉了旧中缝竖线）。`book_archive.png` 里读作"黑洞旁边贴了张纸"，而且左栏 36% 宽在条目少时是一整块死黑。纸页是对的，缺的是**左栏也要有材质**（暗纸/木格背板/装订线），让两栏读成"一本摊开的册子"。

### 7. `switchToPanel` 先关后开，闸门拒绝时把玩家丢回裸画面（P1，导航）

```ts
// GameStateController.ts:142-153
switchToPanel(name) {
  ...
  for (const [n, e] of this.panels) if (e.panel.isOpen && e.overlaysGameState) this.closePanel(n, {silent:true});
  this.togglePanel(name);   // ← 这里才过 canOpen / openGuard
}
```

`togglePanel` 的 `canOpen`（:205）与 `openGuard`（:207）在**旧面板已经关掉之后**才判。于是：开着规矩本 → 点入口条 [G]「用规矩」→ 当前没有可用规矩，openGuard 拒绝 → **规矩本关了、用规矩没开，玩家回到裸画面并收到一句拒绝提示**。注释里写的"打不开的场合仍由 togglePanel 的既有闸门兜住"只兜住了"没开成"，没兜住"旧的白关了"。修法：把闸门判据抽出来先试，通过了再关旧。

### 8. 入口条与面板的层叠没有预留空间（P1，比例）

HUD 容器**没有 zIndex**（HUD.ts 全文无 zIndex 赋值，默认 0），面板 `z.panel = 10`。入口条挂在 HUD 上，所以**面板一旦盖到它就整条消失**。

当前 1024×768 逻辑分辨率下：面板 `MIN_W_PCT 0.84 / MIN_H_PCT 0.62`（UIWindow.ts:53-54），实拍面板底沿 ≈ y665，入口条顶沿 ≈ y675 —— **只剩 10px 余量**。窗口再矮一点、或某个面板内容再高一点，"常驻可见入口"就静默不见了。既然它是 P0 修复的落点，就该反过来：布局先扣掉入口条的地界。

## ② P1 · 上一轮明示/未列，本轮仍在的存量

### 9. 存档页「JSON ↓ / JSON ↑」无 DEV 门控（P1，发行面）

MenuUI.ts:686-690 `addJsonLink` **无条件调用**（devHooks 只门控了标题页那行「[叙事调试]」，:494）。`after/save_slots.png` 实拍：正式存档界面上挂着全站唯一的拉丁词，且是"导入任意 JSON 当存档"的口子。批 0 关掉了 `?mode=dev` 直达，这条同类漏了。

### 10. 商店陈列一字未动（P1）

`after/shop.png`：五行仍是「名 + 价 + [购买]」，无图标、无描述、无持有数、一点即购无确认。上一轮列 P1，修复记录未涉及。包袱里明明已经有每件物品的写实图标和描述文案，商店直接复用即可。

### 11. 地图标记仍不锚定底图像素（P1）

MapUI.ts:470-473 仍是按节点包围盒归一化投影。`after/map.png` 上五个红环散落在山顶、水面、崖壁等**没有任何地点的位置**；当前节点「城门口」的金点倒是落在城门附近。换真画稿或增删节点会整图漂移。

### 12. 对话框：单行台词占满四行框 + 行长通栏（P1）

`BODY_MAX_LINES = 4` → `BOX_HEIGHT` 由它算死（DialogueUI.ts:58-66），`after/dialogue.png` 里一句「你哪个嘛？不给.」占着 25% 屏高的框，下面 3/4 全空。同时 `wordWrapWidth = boxWidth - padding*2 - inset`（:270）是通栏，1024 逻辑宽下一行能排 40+ 字，正文行长完全失控（商业 VN 通常锁 26–34 字）。

顺带两条：该句**无说话人名牌也无立绘**（需实机复核是不是旁白）；文案以半角句点 `.` 结尾。

### 13. 立绘 360 vs 定稿注释 240 仍未对账（P2）

`PORTRAIT_SIZE = 360`（:88）与同文件 :312 注释「构图参数（240px…）是定稿值，勿顺手优化」直接矛盾。inbox 已立项，需要制作人拍一次板。

## ③ P1/P2 · 美术风格一致性

### 14. 入口条 8 枚 22px 剪影辨识度不足（P1）

`ENTRY_ICON = 22`（HUD.ts:81）。实拍：Tab(卷轴) / M(舆图) / G(木简) 在这个尺寸下**都是"一张纸"**，R(戒尺)只是一根白棍。名字只在 hover 名签里（:448），键盘玩家和第一次看的人都读不出。要么把图标加大一档、要么换成**辨识度靠外形轮廓**（书=长方带书脊、图=折角纸、规矩=木牌带绳）的一批。

### 15. 同屏两套图标语言（P1）

入口条 / 书架 / HUD = 白剪影线稿；背包格 = 彩色写实小图（铜钱堆、扫帚、包袱皮、符纸）。`after/inventory.png` 一屏之内两种画法并置。需要拍板：物品走写实、UI 功能走剪影（可接受，但至少要给写实图标一个统一的底/框把它们收进去），还是全部统一。

### 16. 方括号伪按钮与真描边按钮混用（P2）

`[购买]`（shop.png）、`[离开]`、`[返回]`（save_slots.png）用方括号包字模拟按钮，而确认框/丢弃/页签用的是真描边按钮。方括号是程序味，跟做旧木框语言不搭，并且制造"哪个能点"的二义。

### 17. 地图图例卡片压住地图内容且不可关（P2）

`after/map.png` 右下角亮底图例把整座建筑盖掉。同图里当前节点标签是**红字白框**、其它节点是**灰字暗框**——两套样式没有共同语言。

### 18. 底部关闭出口四家四制（P2）

`Tab 关闭`（任务）/ `I 关闭`（包袱）/ `[离开]`（商店）/ `返回书架`（册子）/ `[返回]`（存档）—— 键帽式、方括号式、纯文字按钮式三种形态混用，且有的在面板内、有的浮在纸上。

## ④ P2 · 比例与空间

### 19. 空面板巨大（P2，但最伤第一印象）

`after/quest.png` / `rules.png`：84% 宽 × ≈77% 高的面板，内容只有三个页签 + 两行空态字。`MIN_H_PCT` 已从上一轮降到 0.62，但**实际高度是各面板自己算出来的**，空态没有走"按内容收缩"。空态应该直接落 `sm`/`md` 档。

### 20. 书架网格 5+2 收尾散（P2）

`after/book_shelf.png`：第二排两本靠左，右侧三格空，右下大片黑。7 本改 4+3 或第二排居中即可。另：未读标记是**金点**不是红点，"未读"这层意思偏弱；牌面无进度（"3/12"）。

### 21. 全屏面板背后不压暗 + 面板底半透（P2）

`SKINS.panel.fillAlpha = 0.95`（PanelSkin.ts:83 / alpha.panelBg :176），且全屏面板期没有 scrim。`after/inventory.png` 里详情区能清楚看到两个 NPC 剪影和石板路"走过"面板。**要么背景压暗、要么面板底不透**，现在是两头不靠。

## ⑤ P2 · 功能逻辑与细节

### 22. 首开包袱先显示物品名文字、图标到位后跳变

InventoryUI.ts:441-462 的文字兜底 + :761-777 异步加载。冷开一定看得到"一格格文字 → 突然全变成图"这一跳（`after/confirm_dialog.png` 就抓到了文字态）。给格子一个占位框 + 淡入，或在面板 open 前预热该批图标。

### 23. 线索簿/见闻录分组表头是单字

`clues.json` categories = 人/地/物/话（数据侧刻意的简笔），但当组标题渲染时（ClueBookUI.ts:51）单独一个「地」字读起来像被截断。建议表头用双字（人物/地方/物件/闲话），或给表头加"·"装饰把它读成刻意的简笔。

### 24. 标题页无「退出游戏」

MenuUI.ts:407-413 只有 新游戏 / 继续游戏（有档时）/ 设置。桌面发行必补。

- **HUD 本体**：铜钱芯片 / 三把阳火 / 气味的克制程度是全站最好的（`hud.png`），别再往上加常驻件。
