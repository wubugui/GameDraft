## 1 · P0/P1 · 功能逻辑

### 1.1 面板里的操作**零反馈**，出了面板才播报（P0，功能逻辑）

运行时实测（开着包袱 → 发一条线索回执）：

```
面板内：entries=0  queued=1  state=UIOverlay   ← 屏幕上什么也没有
关面板后 2s：entries=1  queued=0  state=Exploring  ← 冒在游戏画面上
```

`Game.ts:1121-1124` 的静默判据是 `state === 'UIOverlay' || 'Cutscene'`，而**面板内操作的回执走的是同一条
notification 通道**：

- 线索采集（`ClueManager.ts` 的苔绿回执）——玩家在册子里点了那个词，**当场毫无反应**；
- 存档（`MenuUI.ts:882/906/912`）——存完档没有任何确认，关掉菜单才在街上飘一句「存档到槽位 1」；
- 档案更新（`ArchiveManager.ts:415`）同理。

上一轮把这条写成「脱节播报」，这一轮因为静默做严了，它从"位置不对"退化成了**"点了没反应"**。
玩家最直接的判断是"这个词条点不动 / 存档失败了"。

**这是本轮唯一的 P0。** 修法仍是上一轮给的那条：分「世界回执」与「面板内回执」两路，
后者在面板内就地出（贴面板底沿/角），不进全局队列。

### 1.2 `switchToPanel` 先关后开，闸门拒绝时把玩家丢回裸画面（P1，导航）

运行时复现（开着规矩本 → 点入口条 [G]）：

```
before: { rules: true,  state: 'UIOverlay' }
after : { rules: false, ruleUse: false, state: 'Exploring', openPanels: [], stack: [] }
```

`GameStateController.ts:149-152` 仍是「先无条件关掉所有覆盖层面板，再 `togglePanel`」，
而 `canOpen`(:205) 与 `openGuard`(:207) 判在关完之后。于是**规矩本被关掉、用规矩没开、
玩家回到裸画面**。上一轮的原文一字未动（连"仍由既有闸门兜住"那句注释都在）。

修法：把 `canOpen`/`openGuard` 抽成 `canOpenPanel(name)`，先试闸再关旧。

顺带一条同源的：`closeAllPanels()`(:164-171) 逐个调 `panel.close()`，**不弹
`overlayReturnStack`、不恢复 GameState**。现在只被 `destroy()` 与取景台调用，还没伤到玩家，
但它和 `closePanel` 的语义不一致，是下一个"状态滞留 UIOverlay 软锁"的现成入口。

### 1.3 地图：画稿上有 7 个朱砂锚位，代码完全不认（P1，功能逻辑 + 视觉）

`B_map` 实拍：纸面上散着 **7 个醒目的朱砂空心圈**（左上、上中、右上、右中、左中、下中、右下），
分布均匀、大小一致——这看起来就是画稿作者预留的**地点锚位**。

而 `MapUI.ts:447-474` 的 `buildProjection` 仍是「取所有节点 x/y 的包围盒 → 归一化 → 铺进
`MAP_INSET` 矩形」，**完全不认这些锚位**：三处可去的地点（茶馆 / 雾津街头 / 码头）没有一处
落在朱砂圈上，其中「码头」落在船坞的空地上、「茶馆」落在民居屋顶上。

三个后果：
1. 玩家会把那 7 个红圈当成"还没解锁的地点"去点——它们是全图唯一的正红色，**比真正能去的地点显眼得多**；
2. 图例里**根本没有这一项**（图例六项：当前所在 / 可前往 / 尚不可往 / 未知之地 `???` / 任务目标 / 来往路线），
   玩家找不到解释；
3. 换画稿或增删节点，三个真地点会整体漂移。

**视觉优先级完全反了**：能去的地方是暗褐色圆盘（几乎融进画稿），去不了的红圈最跳眼。

修法（按性价比）：给 `map_config.json` 的节点加一对**画稿像素坐标**（`px`/`py`，0~1 归一化到
sheetRect），投影改为「有 px/py 就直接贴，没有才退回包围盒」。7 个朱砂圈正好是现成的坐标表。

### 1.4 空态面板：84%×85% 的黑板 + 一条竖分割线（P1，比例 + 视觉）

三张实拍是同一个病：

- `A_quest`：84%宽 × 77%高的面板，内容只有三个页签 `(0)(0)(0)` + 屏幕正中一行「这一页还空着」；
- `A_book_lore`（见闻录空态）：整块黑面板，左上角一行 `(暂无见闻)`，**中间那条竖分割线仍然画满全高**
  ——把一块空黑板一分为二，读起来像"内容加载失败"；
- `A_book_clues`（线索簿空态）：同上，右栏全空。

`UIWindow.ts:53-54` 的 `MIN_H_PCT 0.62` 是地板，而各面板算出来的高又都比它大（册子恒取 `lg`
850×630），所以空态永远撑满。上一轮把这条列为 P2，实拍下来它是**第一印象最伤的一条**——
新玩家开局按 Tab，看到的就是一块一人高的空黑板。

修法两步：① 空态走 `sm` 档（480×390）；② 空态不画中缝竖线、不铺两栏，直接居中一句引导。

另：两本册子的空态文案风格不统一——`(暂无见闻)` 是程序味的括号占位，`(还没记下什么。看书读告示时，
标了记号的词点一下就能记来。)` 是完整引导句。统一走后者。

### 1.5 铺子：五行全灰 + 无任何解释（P1，功能逻辑）

`A_shop` 实拍（身上 0 铜钱）：五行货品**全部灰态**、右侧五枚 `[不足]`，整块面板读起来像
"这家店坏了"。唯一的因果线索是右上角一行小字「铜钱: 0」。

叠加上一轮未修的 #10：无图标、无描述、无持有数、一点即购无确认——**包袱里明明已经有每件物品的
写实图标和描述文案**（`A_inventory` 可证），商店直接复用即可。

## 2 · P1/P2 · 美术风格一致性

### 2.1 对话框行长没有上限，宽屏必崩（P1）

`DialogueUI.ts:431` `wordWrapWidth = boxWidth - TEXT_PADDING*2`，而 `boxWidth = screenWidth - 40`。
1024 宽下实测 34 字/行（`A_dialogue_long`，正好卡在商业 VN 的 26–34 上限）；1920 宽下就是 **60+ 字/行**，
成段阅读直接失控。

加一条 `BODY_MAX_WRAP_W`（按 34 字反推 ≈ 850px），超出就居中留白，别让框宽直接当行宽。

### 2.2 对话选项：序号与正文脱节、按钮不随内容收窄（P1）

`A_dialogue_choices` 实拍：三条选项都是 620 宽的定宽木条，**正文居中、序号左对齐**。
于是「回头看一眼」这条 5 个字的选项，序号「2.」孤零零钉在最左端，与文字之间隔着 300px 空白，
读起来"这个序号跟这行没关系"。

`DialogueUI.ts:75` `CHOICE_MAX_W = 620` 是**定宽**不是上限。修法二选一：
① 按钮宽度按最长选项收窄（所有行同宽，但不是恒 620）；② 正文改左对齐、跟在序号右边。

### 2.3 设置页是全站最"软件感"的一页（P1）

`A_menu_settings`：三条音量滑条**横跨整个面板宽度**（逻辑 ~650px），填充段是很粗的实心琥珀条——
四条粗金线横穿面板，是这一页最重的视觉元素，比「设置」标题还抢眼。而「逐字显示 [开]」是一枚
72×32 的小按钮，跟旁边的通栏长条完全不是一个重量级，一行看着像漏排。

这一页与"民俗草根·做旧木框"最不搭。修法：滑条收到 ~280px 定宽（右侧百分比列跟着靠），
轨道换成方正的凹槽（与 `createProgressBar` 同口径），开关按钮抬到与滑条同高。

另：面板下 1/3 完全空白（5 行内容 + 大片空 + [返回]），同 §1.4。

### 2.4 方括号伪按钮：同一套约定在三处不一致（P2）

- `UIWindow.plainHint`(:121) **会剥掉**文案里的方括号（「[返回书架]」→ 框 + 「返回书架」）；
- `MenuUI.addBackButton`(:852) 把 `strings.menu.back`（`[返回]`）**原样塞进 UIButton** → 实拍是
  「一个描边框里套着 [返回]」；
- `ShopUI`(:234) 的「[离开]」同病；
- `InventoryUI.detailTags`(:693) 又**手动剥**了一次方括号。

三种处理散在四处。要么统一在 strings 层去掉方括号、由控件表达可点，要么统一由控件剥。

### 2.5 菜单入口用了齿轮图标（P2，题材铁律）

`HUD.ts:103` 入口条第 8 枚 `icon: 'gear'`，实拍里就是一枚标准的**设置齿轮**。
其余七枚全是民俗器物（卷轴/钱袋/戒尺/折扇/书/舆图/符），唯独这一枚是西洋/现代 UI 隐喻，
与「禁西洋/现代物件隐喻」的题材铁律直接冲突。换成灯笼、铜锁、门环一类即可。

### 2.6 包袱右栏 55% 是空的（P2，比例）

`A_inventory`：右栏自上而下是「铜钱」+ 细线 + 一行描述，然后 **约 500px 的空白**，
再是贴底的 `x99` 标签块与「丢弃」按钮。描述短的物品（大多数）都是这个样子。

`InventoryUI.buildDetail` 把标签/丢弃按自下而上占位、描述吃中间的可滚高——逻辑对，但短描述时
中间就是一大块死区。修法：描述块与标签块之间不留弹性空隙，整块内容顶对齐，丢弃钮跟在标签后面。

### 2.7 三把阳火在这个尺寸下读不出任何意思（P2）

`A_hud`：屏幕左上角三枚约 20px 高的暖色小火苗，既无标签也无边框，实拍里更像三粒麦穗。
「离死之距」这层意思——本身就是刻意含蓄的设计——在当前尺寸下等于不存在。
不是要加标签（那会毁掉含蓄），是要么放大一档、要么在数值真的掉下来时给一次一次性的进场提示。

### 2.8 书架 5+2 收尾散（P2）

`A_bookshelf2`：七块木牌排成 5+2，第二行两块靠左、右侧三格是一整片黑。
`BookshelfUI.ts:22` `COLS = 5` 改 4（4+3）或第二行居中即可。

另：每排木牌底下那条"搁板"（`createRule`）在实拍里几乎看不见（`alpha.titleRule` 0.75 × 渐隐），
"书立在架子上"这层意思没传到。

### 3.2 标题页仍无「退出游戏」（P2，发行面）

拉丁词，且是"导入任意 JSON 当存档"的口子。批 0 关掉了 `?mode=dev` 直达，这条同类漏了。

### 3.4 书架木牌的 `pointerdown` 没有 `markPointerConsumed`（P2，契约）

`BookshelfUI.ts:349`：`hit.on('pointerdown', () => this.onBookClick(slot.id))`。

`ui-component-layer` 机制卡明写「所有行内 pointerdown 必须 markPointerConsumed」。
当前书架只在 Exploring 下可开，穿透暂时伤不到人，但这是靠"恰好没有 window 级监听在场"活着的。
