## 2. 终审第一轮判了什么、每条怎么修的

### 阻断级（3 条，全修）

**B1 · 批量盖的图会被叙事页整份回写抹掉**。叙事页 React 文档是加载期快照，下次 flush 整份回写
compositions（signals 有 merge 兜底、作曲没有）；闸门只查"此刻脏不脏"且找不到主窗时 fail-open。
修法：`scene_editor.py` 盖章成功后调 `_notify_narrative_projection_stale()` → 叙事页
`reload_from_model()`（Task apply 同款现成机制）；闸门找不到主窗改为按"有草稿"拦（连带修 H6）。

**B2 · `narrative_templates.json` 黄金字节往返破 + inbox 记录污染判据**。新增模板的键序
（`produces` 在 `params` 后、`from` 在 `note` 前）与 `normalize_templates_file` 规范序相反；
且真回归被 `2026-08-09-windows-write-text-breaks-template-byte-fidelity.md` 那条 inbox 记录
误标成"Windows 已知红"。修法：键序调成规范序（`normalize` 后逐字节相等已验）；inbox 记录加勘误
（教训：把测试归入"已知红"必须逐条点名，不许按文件粒度豁免）。

**B3 · 模板通道吞 `scope`，模板盖出的私有信号是全局信号**。`normalize_template` 重建 signal row
只保留 id/label/notes。修法：保留 `scope:'private'`（`'global'` 归缺省不落键，保字节往返）。

### 高（4 条，全修）

**H1 · owner 四档优先级下 npcId 抢占 origin，发射点无逃生口**。热点动作批写
`startDialogueGraph(npcId=某NPC)`（历史写法量最大）时，图里发的私有信号 owner 是那个 NPC 而非热点。
修法：`emitNarrativeSignal` 加显式 `ownerType`/`ownerId` 参数（优先级最高）；
`actionParamManifest` optional + `action_editor.py` `_PARAM_SCHEMAS` 同步登记。

**H2 · owner 有但没有 wrapper 图 = 完全静默**（机制卡声称是 error，实际只 trace）。
修法：升级为 `signal.private.ownerNoGraph` error + console.warn。

**H4 · Python 兜底比 TS 权威更严（红线）**。TS 判 trigger 用 `t?.trigger && t.trigger !== 'signal'`
（不 trim），Python 用 `.strip()` ⇒ `"signal "` 被 Python 当非信号触发跳过 → unlistened/unbound
误报 → 编辑器拒存 TS 认可的数据。修法：`narrative_state_editor.py` 与 `validator.py` 两处
逐字对齐（不 trim）。

**H5 · 模板声明共享信号时批量第 2 份必撞名，整批作废**。修法：`stamp_template` 加
`existing_signal_rows` 参数做**幂等注册**——内容逐键相同（id/label/notes/scope）= 已登记跳过；
内容不同（如 scope 不一致）仍 error。`narrative_template_batch.py` 传 rows 且批内累加。
端到端验过三份连盖 + scope 不一致报错。

### 瞎护栏（终审变异测试暴露 4 个全绿变异，全部封上）

`NarrativeStateManager.test.ts` 新增四条走**真实链路**的用例：
- **M5 接线**：走真 `loadFromAsset`（fake assetManager）验证 signals 声明喂进 `setSignalDefs`；
- **M9 接线**：走真 `registerActionHandlers` + `executeBatchFromOwner` 验证 owner 从 originContext 取；
- **M11 契约**：同 owner 两张 wrapper 图，私有信号必须两张都收到（投递面=全部，非主 wrapper）；
- **H2 诊断**：owner 无图时 `signal.private.ownerNoGraph` 进 recentIssues + warn 被调。
变异复验：四处实现逐一改坏 → 4 条全红；复原 → 73/73 绿。

### 修复过程中引入又修掉的回归（R1）

我给 `emitNarrativeSignal` 加 `ownerType`/`ownerId` 控件时**没登记 omit 表** ⇒ 打开任何带该动作
的对话节点再保存，凭空注入 `"ownerType": "", "ownerId": ""`（影响 47 个已发布节点）。
外围 agent 抓到。修法：`action_editor.py` 的 `_ACTION_SCOPED_OMIT_WHEN_ABSENT_AND_DEFAULT` 补
`("emitNarrativeSignal","ownerType"/"ownerId")` 两行（**不能进全局表**——那两个参数名同时是
`startDialogueGraph` 的，全局剔除会跟它的保存路径打架）。验证：dge
`test_open_clean_and_save_fidelity` + `test_inspector_roundtrip` 恢复 5 passed。
