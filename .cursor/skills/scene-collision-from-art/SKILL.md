# 修一张图的碰撞(固定流程)

> **深度也要做 / 深度是塌的**(新场景第一次建几何、峭壁栈道这类深度塌成平面的图)→ 用 `scene-depth-collision-from-art`:
> 它先按本技能做碰撞第一轮,再拿圈好的路标定深度,深度体检过了之后用游戏真实深度遮挡做第二轮。本技能只修碰撞、不碰深度。

> **深度也要做 / 深度是塌的**(新场景第一次建几何、峭壁栈道这类深度塌成平面的图)→ 用 `scene-depth-collision-from-art`:
> 它先按本技能做碰撞第一轮,再拿圈好的路标定深度,深度体检过了之后用游戏真实深度遮挡做第二轮。本技能只修碰撞、不碰深度。

> 知识(口径、为什么、已知坑)在 `agent_docs/editor-tools/recipes/collision-from-art.md`——**先读完那张卡再动手**;
> 本技能只管怎么做。工具一律 `sh scripts/py.sh -m tools.terrain_workbench.art_review <命令> <场景>`(下文写 `AR`),
> Windows 下命令前加 `PYTHONIOENCODING=utf-8`。产物默认在 `local/collision_review/<场景>/`,
> `render` / `crop` / `crowd` 都能 `--out` 到自己的目录——修的人和复查的人别互相覆盖。

## 四条硬规矩

1. **只看画、按 3D 判**:画是 3D 世界的投影,物体挡住的地画上没信息,要估。**不依赖深度**(有的图深度整张是错的),
   深度着色、深度图、自动碰撞都不作依据。
2. **物体只占占地**:前沿 = 看得见的接地线(墙脚、桌脚凳脚、台子侧面底边);后沿 = 顶面(檐口、桌面、台面)往下平移物体高 h。
   占地以上、轮廓以内那片是**物体后面被挡住的地**:两边看得见的地明显从后面连过去 → 能走;靠墙 / 另一栋房 / 崖 / 画边 → 封;
   拿不准 → 封,并在回报里点名。
3. **只做局部补丁**:哪块错改哪块(同 id 重写 = 替换);不重烘深度、不整张重画、不动 `collision_auto.png`、不手改 `art_可走以外*`。
   写盘只走 `AR apply / region / remove / move / grid --fit / brush --clear`。
4. **一个场景同一时间只归一个人写**(别的会话 / 子代理在改就等)。

## 七步

每步写着:做什么 → 命令 → 过了才往下的标准。

### 1. 看现状
- `AR check <场景>`、`AR render <场景> [--out 路径]`:现在的红块(= 阻挡)、标记点、世界宽高、时段变体名。
- `check` 的 `offGridPct` 明显大于 0(画面有一截在碰撞网格外,运行时那里当"不挡")→ 先 `AR grid <场景> --fit`。
- 旧碰撞笔刷层(`brushLayer: true`)且这次整场照画重圈 → 落盘后 `AR brush <场景> --clear`。
- 第一次落盘前工具自动存 `before.png`(已存在就不动,多轮修过的场景自己留意它是哪一刻的)。

### 2. 读图
- `AR crop <场景> x0 y0 x1 y1`:大场景按约 1100×750 分块;室内、灌木密处切 300×200 放大(`--no-grid` 去格子看细节)。
- 每个立着的东西(房、墙、桌凳、台、柜、石、树)读**三样**:接地线在哪、顶面在哪、差多高(= h)。
  再看它后面被挡的那片:两边看得见的地连不连过去。
- 构图先分三类:**野外 / 山梁 / 崖路**(可走的是一条带)、**院落 / 室内 / 疏朗街镇**(地连成一片,房子是岛)、
  **房挨房的密集街镇**(街是房子之间的窄条)。
- 图例:出生点绿、出口青圈、NPC 橙方块、交互热点淡蓝圈、跨点站位紫 / 落点黄(跳完切场景的灰黄,不查)、
  触发区青虚框、实体自带碰撞品红(只描边 = 只在某段剧情里在)、作者多边形 walk 绿 / block 红、黄虚线 = 占地往上抬 h。

### 3. 起草
草稿 JSON,场景坐标:`{"id": {"kind": "walk"|"block", "pts": "x,y x,y …", "h": 物体高, "h0": 下面空着多高, "flat": true, "note": "…"}}`
- **walk 只圈能站的地方**,其余工具自动封死。按构图:一条带就圈那条带;连片的圈整片地;密集街镇按街带一条条圈。
- **可走区里每个物体一块 block = 占地 + h**。已经按画面轮廓圈过的块:`AR footprint <场景> --id <块> --h N` 出占地草稿。
  高矮不一的一堆按高矮拆块;坡屋顶 h 量到**檐口**。
- 特殊写法:门楼 / 过街楼底下的路 = walk 带 `h0`(门楣底)+ `h`;死角地、墙后封口 = block 写 `flat: true`(不写 h);
  会挡住人的墙 / 隔墙 / 路边棚石,在墙线上补一条带 h 的细 block(只为摆人图遮挡)。
- 出口、出生点、站位、场内跳跃落点一定在 walk 里;一大片画上是街却连不上主路 → 先找被屋顶挡住一半的巷口、门洞、灯杆边,真没有才封。
- 相邻块互相压进约 10 单位,别共用一条边;贴画边的块往画外多画 20 单位。
- **过关**:`AR crop … --draft 草稿.json` 叠在画上——实线(占地)贴接地线,黄虚线对上屋顶 / 桌面(差半个人以内)。

### 4. 落盘
- `AR apply <场景> 草稿.json`,看逐块实现度。标"⚠ 实现不足"的才要改(有不足时退出码 1,但已经存上了);
  "比网格细,仅参考"的不用管。删一块用 `AR remove <场景> --id <id>`。

### 5. 自检三件(都过才往下)
1. **`AR check <场景>` 退出码 0**。修的顺序:
   - `marksOnBlock` / `reach`(出生点、站位、落点落阻挡 / 走不到出口);
   - `interactUnreachable` / `zoneUnreachable`(交互物、触发区够不着)——先在画上(和对白里)找到它指的那个东西:
     摆在墙上屋顶上 = 旧布局遗留,`AR move <场景> <npc|hotspot|spawn|zone>:<id> x,y` 挪到那东西脚下的地上;
     出生点先查是哪个场景的哪个出口跳过来的,挪到本场景对应出口旁(交互半径外);
     画外坐标、半径离谱的历史热点别挪,列进回报;
   - `islands`(能站但走不到的整块地):该连上就补 walk,封闭死角就封 `flat`;
   - `blocksWithoutH` 过一眼:立着的东西忘写 h 就补。`smallIslands` / `finerThanGrid` / `variantDiff` 只作参考。
2. **叠红块**:分块 `AR crop … --overlay`,红边贴着墙脚、崖边、路沿;每个时段变体再 `--variant <名>` 扫一遍。
   围起来的院子 / 屋子:`AR connected <场景> 墙里一点 墙外一点 --seal <门矩形>` 必须"不连通"(墙不漏);
   上下两层(桥面 / 桥下)同理,堵上正常上下口问一次,必须"不连通"。
3. **摆人**:分块 `AR crowd <场景> --x0 … --y0 … --x1 … --y1 …`(窄条 `--spacing 12`,小块太密用 40~60)。
   **看脚底圆点**:绿 = 走得到、橙 = 能站但走不到;没有点落在水 / 崖外 / 物体占地里;没有明明是路却空着的一片;
   被物体抠掉一截的人,脚下那块地按连续性该有。拿不准的点 `AR probe <场景> x,y`。

有错 → 回第 3 步只改错的那块 → 再过第 5 步。

### 6. 独立复查(必须做)
- 起一个**新的**子代理(不带你的上下文),把下面「复查协议」原样给它,告诉它场景 id 和你开放了哪些"物体后面的地"。
- 它只报不改。按它报的每一条局部补丁,改完让它**只看改过的那一片**再复查,直到它报"无问题"。

### 7. 收尾
- `sh scripts/py.sh -m tools.terrain_workbench --check`(全场景)+ `sh scripts/py.sh -m tools.editor.validate --errors-only`(挪过任何坐标必跑;只看有没有新增 error)。
- 回报制作人:每个场景 `before.png` 与 `AR render` 出的改后图;挪过的标记(原坐标 → 新坐标,凭判断放的单独标);
  **开放了"物体后面的地"的具体位置**——游戏里人走到那儿要靠运行时深度遮挡画到物体后面,深度错的图会画在物体上面,请他进游戏看。

## 哪些是固定的,哪些还靠判断

- **固定**:七步、每步的命令、检查项、过关标准。
- **靠判断**:物体高估多少、被挡的地连不连、暗处是地还是东西、画上没通路时挑哪里当路。同一张图两个人看会有出入——
  所以第 6 步不能省(2026-09-23~24 那一轮,每组复查都抓到过真问题,主代理自己圈的两张也被抓出 12 处)。
- **已知难点**(`check` 查不出,要人看 + `connected` 核):
  - 上下两层重叠(桥面与桥下栈道):共用碰撞格,边一动就可能上下漏通,或把下层压成走不过去的细缝;
  - 立着的物体画面边缘:画面点换算到碰撞格会折叠,薄块在那里的实现度报不出来,逐块 `crop --overlay` 放大核。

## 耗时参考

中等场景修一遍约 1~1.5 小时;大街镇(雾津街头这种)加 2~3 轮复查要好几个小时。一轮复查约 10 分钟到 1 小时。

## 复查协议(原样交给复查子代理)

> 你是碰撞复查员,只看图、只报告、**不改任何文件**。项目根 `E:\GameDev\GameDraft`,命令前加 `PYTHONIOENCODING=utf-8`,
> 工具 `sh scripts/py.sh -m tools.terrain_workbench.art_review`,`render` / `crop` / `crowd` 一律 `--out` 到你自己的临时目录。
> 先 `render <场景>` 看世界宽高与时段变体,把整张图按约 1100×750 场景单位分块(小场景 / 室内再切小块放大),每块跑:
> - `crowd <场景> --x0 X0 --y0 Y0 --x1 X1 --y1 Y1`(在游戏判为可走的每个点上摆了一个玩家,**脚底圆点就是他站的位置**:
>   绿 = 从出生点走得到,橙 = 能站但走不到;站在带高度的物体后面的人会被物体抠掉一截)
> - `crop <场景> X0 Y0 X1 Y1 --overlay`(红 = 阻挡;黄虚线 = 物体占地往上抬它的高)
> - 有时段变体的,`crop` 再加 `--variant <名>` 看一遍
> 再跑一次 `check <场景>`,把非空项一并列出。
>
> 然后用眼睛判(画是 3D 世界的投影,被挡住的地要估;**别看深度**,有的图深度是错的):
> 1. 有没有圆点落在**水面、崖外 / 天空、物体的占地**(房子墙脚线以内、桌脚凳脚之间、桶 / 摊子 / 柱子脚下)上(站错地方);
>    被物体抠掉一截的人:那块被挡的地两边是不是连着看得见的地——连着就对,物体背后靠墙 / 靠另一栋房 / 是崖是画边就报;
>    没被抠、却整个人画在屋顶 / 桌面上的,也报;
> 2. 有没有**明明是路 / 地面 / 门口却没有人**的一片(该走的走不了),尤其出口(青圈)周围、NPC(橙方块)和交互热点(淡蓝圈)跟前、触发区(青虚框)里;
> 3. 有没有橙点(走不到的地)——画上它是不是其实该连着路;
> 4. 红块边缘有没有明显偏出墙脚线 / 路沿(偏半个人以上才算);
> 5. 黄虚线和画上的屋顶 / 桌面差得多(半个人以上)也报;
> 6. 围起来的院子:用 `connected <场景> 院里一点 院外一点 --seal <院门矩形>` 查墙漏不漏(必须"不连通")。
> 拿不准就 `probe <场景> x,y` 问那个点挡不挡。人的身子盖在屋顶上但脚在墙脚线外的地上 = 正确,不要报;
> 小于一个人宽的柱子 / 单个桶漏了不报。
>
> 输出一张表,每行:`场景坐标框 (x0,y0)-(x1,y1)` | `问题`(站错 / 走不了 / 走不到 / 边偏)| `画上那是什么` | `建议`(block 或 walk + 大致多边形顶点)。
> 没有问题就明确写"无问题",并列出你看过的分块。只报真问题,别凑数。

## 批量(多场景)

- 场景之间互不相干,可以分给多个子代理并行;**每个子代理只拿自己那几个场景**,一个场景只归一个人。
- 每组修完另起复查子代理按协议看;修复与复查交替直到复查无问题。
- 在 `agent_docs/_meta/governance-log.md` 记:哪些场景、几轮复查、复查抓到了什么——这是这套方法真能产出正确碰撞的证据。
