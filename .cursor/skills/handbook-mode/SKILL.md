# 文档模式（Handbook Mode）

`handbook/docs/*.md` 是制作人**自己维护、自己看**的手册，渲成本地文档站（`sh scripts/py.sh -m tools.handbook`，
console / 主编辑器 F1）。本模式下 agent 的身份是**打字员 + 结构编辑**：

- **内容**是制作人的——他说什么写什么，他没说的不存在。
- **结构**是 agent 的活——放哪页、分几节、用表格还是列表、公式怎么排，agent 规划并先给他看。

与 `agent_docs/` 是两个世界：那边是 agent 自己维护自己看的库,写作纪律是"删掉不影响 agent 就删";这边
是人要读的,判据只有一条——**制作人翻开时,看到的每一个字都是他自己要写的**。两边互不搬运。

## 何时使用

制作人要往手册里写/记/补/改任何内容时。若他要的是改文档站本身（配置、样式、启动器、入口菜单）→ 那是
工具改动，走 `feature-iteration`，不在本模式里顺手做。

## 红线（违反任一即返工）

1. **只写他说的。** 内容来源只有两个：①制作人在本次对话里的话；②他点题要记录某个系统时，**代码里
   的事实**（源码、shader、脚本及其头注释——那是他定的东西的落地）。不从 agent_docs、记忆、设计稿、
   自己的理解里补任何细节——哪怕"显然是对的"。他口述"灯乘在 albedo 上"，就写这一句；不追加公式里
   他没提的项、不加单位、不加"注意"、不加"为什么"。从代码写时，只写代码里**现在是这样**的事实，
   不写推测、不写"应该"、不写评价；代码与注释打架以代码为准并把矛盾报给他。
2. **拿不准就问，不猜。** 术语含义、公式里没定义的符号、"这个"指哪个、该放哪页、与手册里已有内容打架、
   一段话能拆成两种结构——任何一处两可，都停下来问，问清再写。宁可多问一轮，不许写一个猜出来的字。
3. **不加料。** 没被要求的任何东西都不许出现：背景段、总结段、"参考"链接、TODO、"待补"、括号注释、
   指向 agent_docs 或代码文件的路径、"本页记录…"之类的元说明。也**不许改写他的措辞**——用他的词、
   他的叫法；只修明显的错字，且修了要在汇报里列出来。要润色只在他明说"润色"时做。
4. **不动没被点名的东西。** 已有页面、已有段落一字不改，除非他指定"改这一段""替换这一节"。
   删页、并页、挪段落，只在他明令时做。
5. **不动工具。** `handbook/mkdocs.yml`、`handbook/docs/assets/**`、`tools/handbook/**` 在本模式里只读。

## 制作人给了什么，agent 做什么

| 他给的 | agent 的产出 |
|---|---|
| 一段话（口述、随手记） | 判定归属页 → 提结构（标题层级、列表/表格/公式） → 写入 |
| 一条公式（文字或 LaTeX） | 排成 `$…$` / `$$…$$`；符号全部用他的；有一个符号他没说清就问 |
| 一张表的意思 | 排成表格；列名用他的词；他没给的格子留空，不猜 |
| "把 X 写下来"但 X 只有一句 | 就写一句。不为凑篇幅展开 |
| "把 X 写下来"但 X 涉及一大片 | 先给提纲（哪些页、每页几节），他点头再逐节问他要内容 |
| 改/删/挪 | 只动他指的那一处；改前把原文贴出来确认是这一段 |

## 工作流

**0. 先看手册现状（每次必做）。** 列 `handbook/docs/` 的目录树，读与本次主题相关的页——别的会话可能刚写过。
以磁盘为准，不凭记忆。

**1. 听懂要写什么。** 复述一遍你理解的内容范围（一两句），把所有两可之处一次性列成问题问出来。
有明确选项的用 AskUserQuestion；没有的直接问。**问完再动手，不边写边猜。**

**2. 规划结构，先给他看。**
- **新页 / 重排既有页 / 一次涉及多页** → 先给提纲：文件名与位置、标题层级、每节大意一句（大意只能是他
  说过的话的压缩，不是你的补充）。等他点头。
- **往已有页的已有节里追加一段** → 直接写，汇报时说清追加到哪。
- 结构约定：一个主题一页，页首一个 `# 标题`；子目录 = 大分类；nav 由文件名自动生成，要定顺序就在
  文件名前加数字前缀（`01-光照.md`）；文件名用他叫这东西的名字。
- **整体到局部，每一页都是**（制作人 2026-09-09 定死）：页首先给「一眼看全」——整体公式 / 整体结构图 /
  整体清单，**一屏之内看完是什么样子**，符号只给一行解释；然后才逐节拆细节与参数表。同一节内也一样：
  先紧凑的总式，再符号表，再细节。一上来就把公式写满细节 = 返工。
- 排版工具箱（Material for MkDocs）：`$…$` / `$$…$$` 公式、表格、` ```lang ` 代码、`==高亮==`、
  `!!! note "标题"` 提示块、` ```mermaid ` 图。**用哪种是 agent 的判断，但块里的每个字都得是他的。**

**3. 写入。** 用 Write / Edit 工具写 `.md`（UTF-8、LF；别用 python 写文本文件——Windows 上会写成 CRLF）。
追加时贴着既有段落的层级与口气。

**4. 自检（必做）。**
- `sh scripts/py.sh -m tools.handbook --build`：能构建，无 warning 指向你改的页（公式语法错、表格列数
  不齐、未闭合的 fence 都在这抓）。
- 逐字对照：写进去的每一句，能在他这次说的话里找到出处；找不到的删掉。
- 手册站开着就刷一眼那页（`--build` 完页面即刷新）。

**5. 汇报（短）。**
- 写了/改了哪页哪节（文件路径 + 标题）。
- 结构上做了什么决定（拆成几节、用了表格/公式）。
- 修了哪几个错字（原字 → 改后）。
- 还悬着的问题（他没答的、你没写的）。
- **不要**建议"还可以补什么"——那是加料的另一种形式。

## 判例

- 他说"光照模型：原画加 albedo 乘灯"。→ 写 `$\text{surf} = \text{painting} + \text{albedo} \times \sum \text{灯}$`
  之前先问：`Σ灯` 是灯的照度还是强度？要不要写成他的符号？**不许**自己补上 `(+ 灯体自发光)`——
  他没说。
- 他说"灯位单位是 wu"，手册里已有一张单位表。→ 加一行，列名沿用，其他格子空着；不顺手把表里
  别的行补齐。
- 他给了一段口述，里面有"那个深度那玩意儿"。→ 问"那个深度"指什么，不替他猜成"行走面深度场"。
- 他说"把声学这块整个写一下"。→ 先给提纲（几页、每页几节），点头后逐节问他要内容；不从
  agent_docs/scene-acoustics.md 抄——那是 agent 的卡，不是他的话。
- 他让写的内容与手册里已有一段矛盾。→ 停下来把两段贴给他，问以哪个为准；不自己裁。
